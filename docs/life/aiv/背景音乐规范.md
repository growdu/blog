# Growdu 背景音乐规范

后续系列视频统一用这套背景音乐。本文记录**规则本身**（入库、可评审），
音乐成品留本机（`music/tracks/`，不入库），**授权台账入库**（`music/library.json`）。

> 配套：`pipeline/pyv/bgm.py` 把本文 §4、§7 的判据做成可执行的检查，
> `python -m pyv.cli bgm check --music <文件>` 能直接判一条曲子合不合格。
> 本文与 `bgm.py` 的规则编号必须一一对应，由 `pipeline/tests/test_bgm.py` 盯着。

---

## 一、为什么要有这份规范

问题不是「没有 BGM」，是**没有 BGM 的规矩**，而没有规矩的 BGM 一定出这三类事故：

1. **响度不可移植。** 曲库母带的响度差能到 10 dB 以上（实测存量两条 AI 配乐
   分别是 -8.8 LUFS 与 -13.1 LUFS，差 4.3 dB；曲库同跨度是常态）。
   而流水线现在用的是**固定 dB 增益**（`compose.py` 的 `DEFAULT_BGM_GAIN_DB = -18`），
   固定增益叠在忽高忽低的母版上，换一首曲子就得重新调音量——
   这不是调音问题，是**规则错了**：应该按目标响度归一化，再按固定增益混。
2. **授权没人管。** 免版权不等于没有条件：CC-BY 要署名、Pixabay 有自己的
   Content License。曲子下到本机没人记，半年后根本说不清哪首能发。
   **授权台账必须入库**，这是事实，不是产物。
3. **BGM 抢旁白。** 音乐和旁白挤在同一段频谱里（1~4 kHz 是语音清晰度区），
   不做避让，旁白听着就发闷——这不是音量问题，是频谱问题。

## 二、获取规则

### 2.1 来源与授权白名单

只从**允许商用**的免版权曲库取，授权类型限以下几种（`bgm.ALLOWED_LICENSES`）：

| 授权 | 署名要求 | 说明 |
| --- | --- | --- |
| `CC0-1.0` | 无 | 最省事的一档，优先选 |
| `Public Domain` | 无 | 同上 |
| `CC-BY-4.0` / `CC-BY-3.0` | **必须署名** | 署名串逐字写进台账，出片时带到简介 |
| `Pixabay Content License` | 无 | 站点自有协议，不是 CC |
| `YouTube Audio Library` | 无 | 平台曲库 |

**不在白名单里的授权一律不用**，包括「非商用」「仅个人使用」「CC-BY-NC」「CC-BY-SA」
（SA 的传染性会让成片素材没法再分发）。

### 2.2 下载与入库流程

```
曲库页面 ──▶ 下载原曲 ──▶ 转规格（48k / 立体声 / wav）
                              │
                              ▼
                      响度归一化到 -20 LUFS
                              │
                              ▼
                    登记台账（music/library.json）
                    + 算 sha256 指纹 + 写授权信息
                              │
                              ▼
                    落本机 music/tracks/（不入库）
```

- **音频不入库**，台账入库。跟仓库既有原则一致：入库的是事实，不入库的是产物。
- **每首曲子必须留 sha256 指纹**。指纹对不上说明文件被动过（换源、重新转码），
  授权记录也就不可信了——`bgm.check_library` 会验这一条。
- 台账里的 `local_path` 一律相对 `aiv/` 写，换机器不用改。

台账字段（`music/library.json`）：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | ✓ | 稳定标识，台账内唯一 |
| `title` / `artist` | ✓ | 曲名与作者 |
| `source` / `source_url` | ✓ | 来源站点与原始页面地址 |
| `license` | ✓ | 必须在 §2.1 白名单里 |
| `attribution_required` | ✓ | 是否需要署名 |
| `attribution_text` | 署名时必填 | 逐字的署名串 |
| `series_role` | ✓ | `motif` / `bed` / `sting`（见 §6） |
| `local_path` | ✓ | 相对 `aiv/` 的路径 |
| `sha256` | ✓ | 文件指纹 |
| `duration_s` / `bpm` | | 实测值与手工标注 |
| `downloaded_at` / `notes` | | 下载日期与备注 |

### 2.3 下载脚本

`music/scripts/fetch_music.py` 按台账下载并校验：

```bash
cd docs/life/aiv/music
python3 scripts/fetch_music.py --id <台账里的 id>
python3 scripts/fetch_music.py --all
```

它只做四件事：下载 → 转规格 → 响度归一化 → 校验 sha256 并落盘。
**台账里没有的曲子不会被下载**——授权信息是人工确认过的，脚本不替你判断。

## 三、风格标准：深蓝电影感 ambient + 低频脉冲

「科技感」不是标签，是**可听出来的东西**。这个系列的调子定为：
暗色、有厚度、低频有律动但不轰，中频留给旁白。

### 3.1 人工审核清单（机器判不了的部分）

选曲时逐条过：

| # | 判据 | 怎么听 |
| --- | --- | --- |
| 1 | **纯器乐** | 有人声 / 拟声 / 采样人声的一律不要 |
| 2 | **不要 corporate uplifting** | 那种「励志广告」的钢琴弦乐，跟深藏蓝的视觉打架 |
| 3 | **不要 drop 与爆点** | 代码演示画面的节奏由讲解决定，BGM 再抢一次就乱了 |
| 4 | **低频是律动不是鼓点** | 有持续的低频脉冲，但不能有打点的 kick |
| 5 | **暗色** | 高频不亮、不炫技；亮音乐会像广告而不是像技术内容 |
| 6 | **能连续听 3 分钟不累** | 系列视频不是 3 秒片头，是 30 秒以上的正片 |

### 3.2 风格与视觉的对应

| 视觉 | 音乐 |
| --- | --- |
| 深藏蓝 `#2B4C7E` 主色 | 暗色、低频厚、不刺眼的音色 |
| 琥珀黄 `#F5A623` 强调色 | 偶尔一点亮色（比如一条合成器的泛音） |
| 代码画面的规律推进 | 低频脉冲提供稳定的推进感，不抢画面 |
| 克制的工程师气质 | 不炫技的编排，留白比满编好 |

## 四、技术规格（可机检）

一条曲子进管线前必须满足（`bgm.check_track`）：

| 编号 | 判据 | 阈值 | 为什么 |
| --- | --- | --- | --- |
| `bgm.sample-rate` | 采样率 | **48 kHz** | 管线规格；44.1 kHz 要重采样，白丢一次 |
| `bgm.channels` | 声道 | **立体声** | 单声道上混没有空间感，铺不出宽度 |
| `bgm.duration` | 时长 | **≥ 目标视频时长** | 短了要循环，循环点找不到等于没有 |
| `bgm.true-peak` | 真峰值 | **≤ -3.0 dBTP** | 归一化后留足混音余量 |
| `bgm.voice-band` | 1~4 kHz 能量占比 | **≤ 30%** | 这一段是旁白的清晰度区 |
| `bgm.air-band` | >10 kHz 能量占比 | **≤ 10%** | 刺耳 |
| `bgm.centroid` | 频谱重心 | **≤ 2000 Hz** | 亮音乐会像广告 |

### 4.1 响度归一化：入库时的硬要求

**每首曲子入库时统一归一化到 -20 LUFS**（`bgm.MASTER_LUFS`）。

这是整套规则的地基：母版响度被拉平之后，`compose.py` 里那个**固定增益**
才真正可用。存量两条 AI 配乐的母带响度差 4.3 dB，就是因为它们从来没过归一化。

```bash
ffmpeg -i 原曲.wav -af "loudnorm=I=-20:TP=-3.0:LRA=11" \
       -ar 48000 -ac 2 -c:a pcm_s16le 归一化后.wav
```

### 4.2 阈值是怎么定的

不是拍的，是拿存量素材和合成信号量出来的：

| 实测对象 | 采样率 | LUFS | 真峰值 | 频谱重心 | 1~4 kHz |
| --- | --- | --- | --- | --- | --- |
| 存量 AI 配乐 A（片头） | 44.1 kHz | -8.8 | **+1.5 dBTP** | 605 Hz | 11.0% |
| 存量 AI 配乐 B（片尾） | 44.1 kHz | -13.1 | **+0.1 dBTP** | 641 Hz | 8.2% |
| 旁白（定稿音色合成） | 32 kHz 单声道 | -23.7 | -4.6 dBTP | — | — |

两条存量的**频谱指标都合规**（重心 600 多 Hz、1~4 kHz 只有 8~11%），
但**采样率是 44.1 kHz、真峰值顶到 0 dBTP 以上**——所以它们不能进正文 BGM 通道，
只用于品牌片（品牌片有自己的混音链路，见 §5.5）。

## 五、混音规则

### 5.1 目标电平的推导

混音最终要满足的是**相对关系**，不是绝对值：

```
旁白（定稿音色实测）      -23.7 LUFS
BGM（归一化后 -20 LUFS）  -20 LUFS
compose 基础增益          -15 dB  →  -35 LUFS
```

于是 **BGM 比旁白低 11.3 dB**，这是音乐铺底的常规区间（10~15 dB）。
旁白出现时再 duck 7 dB（§5.2），那一段共低 **18.3 dB**，旁白清晰度就有保证了；
句子之间的停顿处 BGM 回到 -35 LUFS，音乐能「呼吸」，这是固定增益做不到的。

### 5.2 ducking：为什么不用 sidechaincompress

ffmpeg 有 `sidechaincompress`，一行就能挂上。但**实测下来它不能用来定规则**：

标定用的是一段电平与真实旁白活跃段一致的合成语音（-25.7 dBFS RMS），
扫 threshold 从 -20 dB 到 -60 dB、ratio 4~20、detection rms/peak：

| threshold | 实测压深 |
| --- | --- |
| -30 dB | 3.3 dB |
| -36 dB | 3.9 dB |
| -48 dB | 4.1 dB |
| -60 dB | 4.2 dB |

**压深在 4 dB 附近封顶，改参数基本没用**。原因是压缩器的压深取决于
语音包络与 attack/release 的耦合：包络一抖，压缩器的增益也跟着抖，
同一组参数在不同的稿子上能差 2 dB 以上。自然语音里这种包络抖动是常态
（实测真实旁白只有 55%~65% 的时间高于 -45 dBFS，其余是词间空隙）。

规则要能被机器判定，**深度就得是确定的数**。所以改成自己算：
按旁白包络生成增益曲线，深度精确可控。

| 参数 | 值 | 实测 |
| --- | --- | --- |
| duck 深度 | **-7.0 dB** | 持续旁白下实测 **-6.89 dB**（16 bit 量化与起落沿的误差） |
| 起落时间 | 上升 120 ms / 下降 600 ms | 跟得上语音，又不在句子边界抖 |
| 触发阈值 | 高于 -45 dBFS 起，低于 -50 dBFS 停 | 双阈值迟滞，防抖 |

「持续旁白下实测 -6.89 dB」就是这条规则的**机器判据**：拿一段恒定电平的
旁白跑一遍 duck，测 BGM 的电平差，应为 7 ± 0.5 dB。

### 5.3 避让 EQ

旁白的清晰度区是 1~4 kHz，BGM 在这一段要让开。做法是给 BGM 挂一个
bell 滤波器：**1800 Hz，-6 dB，Q = 1.0**。

实测（粉噪信号，滤前滤后对比）：

| 频段 | 滤前 | 滤后 | 削减 |
| --- | --- | --- | --- |
| 1~4 kHz（voice） | 11.6% | 5.5% | **-6.57 dB** |
| 4~10 kHz | 7.7% | 7.5% | -0.28 dB |
| 400~1000 Hz | 7.6% | 6.7% | -1.12 dB |

只在旁白要的那一段下刀，其他频段基本不动。

另外加一个 **30 Hz 高通**：砍掉无用的超低频，把动态余量让给旁白。

### 5.4 混音链

```
BGM（-20 LUFS 归一化母版）
  └→ numpy 按旁白包络 duck（深度 -7 dB，精确可控）
      └→ ffmpeg: highpass 30 Hz → bell 1800 Hz/-6 dB → 增益 -15 dB
          └→ amix（旁白、品牌片音轨）
```

混音参数全部写死在 `bgm.py` 里，没有一个自适应值——同样的输入必须出同样的片。

### 5.5 流水线接入

`compose.py` 的接法（`bgm` 模块在 `compose.py` 里别名为 `bgm_rules`——
函数参数 `bgm` 会把同名模块遮住）：

| 步骤 | 做的事 |
| --- | --- |
| 正文区间 | `_body_range()` 取第一个 code 场景的起点到最后一个 code 场景的终点 |
| ducking | `bgm_rules.duck_bgm()` 按旁白包络生成增益曲线，只处理正文区间那一段 |
| 通道链 | `bgm_rules.bgm_chain()` = 上混 + 高通 + 避让 bell + 固定增益 |
| 对位 | BGM 的延迟 = 正文起点，与旁白同一时间轴（两者都在正文起点开始） |

BGM 与旁白在**正文相对时间**上是对齐的：旁白文件本身从 0 开始，
在混音里延迟到正文起点；BGM 取自己文件的前 `正文时长` 秒，也延迟到正文起点。
所以 ducking 时两边的时间轴天然一致。

### 5.6 与品牌片的关系

品牌片（`brand/`）有自己独立的音轨链路：片头片尾各 3 秒，
BGM 在 `make_audio_brand.py` 里挑 3 秒窗口、以 -19 dB 增益混进去，
**不做 ducking**（3 秒的 punch 不需要，ducking 反而让音乐起不来）。

正文 BGM 与品牌片音乐**不叠**：正文 BGM 只铺正文区间
（从第一个正文场景起点到最后一个正文场景终点），
片头片尾各用各的音乐。

## 六、系列一致性

系列感不靠每期换不同的音乐，靠**同一首曲子反复出现**。

| 角色 | 用途 | 数量上限 |
| --- | --- | --- |
| `motif` | 系列主题动机，片头/片尾/转场反复出现 | **1 首**（多了就没有标识了） |
| `bed` | 正文段落铺底 | 每期 ≤ 2 首 |
| `sting` | 转场音效（几秒的点缀） | 不限 |

规则：

- **每期必须用同一个 `motif`**。片头片尾的 3 秒窗口从 `motif` 里挑，
  于是观众听到第一期和第五期的片头是同一段旋律——这是系列的听觉标识。
- **正文铺底可以换**，但换的时候要保证风格连续（同一 `artist` 或同一授权来源优先）。
- 每期开头与结尾的 `motif` 片段要**首尾相接**（片尾接回片头），形成闭环。

## 七、可机检规则

规则实现在 `pipeline/pyv/bgm.py`，编号必须与本节表格一一对应。

| 编号 | 级别 | 判据 | 触发的样子 |
| --- | --- | --- | --- |
| `bgm.sample-rate` | 硬 | 采样率必须 48 kHz | 44.1 kHz 的原曲 |
| `bgm.channels` | 硬 | 必须立体声 | 单声道 |
| `bgm.duration` | 硬 | 时长 ≥ 目标视频时长 | 曲子太短，循环点找不到 |
| `bgm.true-peak` | 硬 | 真峰值 ≤ -3.0 dBTP | 母带顶到 0 dBTP |
| `bgm.voice-band` | 硬 | 1~4 kHz 占比 ≤ 30% | 音乐在旁白清晰度区太重 |
| `bgm.air-band` | 硬 | >10 kHz 占比 ≤ 10% | 刺耳 |
| `bgm.centroid` | 硬 | 频谱重心 ≤ 2000 Hz | 亮音乐，像广告 |
| `bgm.license` | 硬 | 授权类型在白名单里 | CC-BY-NC、非商用 |
| `bgm.attribution` | 硬 | 需要署名时必须写署名串 | 署名栏是空的 |
| `bgm.fingerprint` | 硬 | 本地文件 sha256 与台账一致 | 文件被换过 |
| `bgm.series-role` | 硬 / 倾向 | 角色合法；`motif` 只能有 1 首 | 登记了两首主题动机 |

用法：

```bash
cd docs/life/aiv/pipeline
python -m pyv.cli bgm check --music <文件>          # 判一条曲子合不合格
python -m pyv.cli bgm library                       # 查台账自洽性
python -m pyv.cli bgm mix                           # 打印当前混音参数
```
