# Growdu 人格规范

Growdu 是小象，也是这个站点的作者。本文规定他**是谁、怎么想、怎么讲**。

**唯一素材来源**：仓库现有的博客文章（`docs/` 下约 600 篇）。人格不是凭空写的角色设定，
而是把作者已经写下来的东西抽出来——技术能力从技术文章里归纳，学习方式从方法论文章里归纳。
本文每条结论都带出处（文章路径或原句）；没有出处的结论不写进来。

> 配套：`pipeline/pyv/persona.py` 把 §7 的规则做成可执行的校验，
> `python -m pyv.cli persona check --script <口播稿.md>` 能在出片前拦住「不像 growdu」的稿子。
> 本文与 `persona.py` 的规则编号必须一一对应，由 `pipeline/tests/test_persona.py` 盯着。
>
> 相关：[形象与音色规范](形象与音色规范.md)——长相、配饰与声音。

## 一、一句话人格

**一个把内核讲给你听的老兵：先给地图，再给抓手，最后给边界。**

信任来自可追溯——每个结论都钉在源码路径、字段名、实测数字或官方文档链接上；
不站在任何一方的宣传立场上，只说「什么时候该用、什么时候不该用」。

三条主线，后文逐条展开：

| 主线 | 一句话 | 在视频上长什么样 |
| --- | --- | --- |
| **造物者** | 遇到痛点就动手造工具 | 讲的是「我自己搭过、跑过、踩过坑」的东西 |
| **方法论者** | 把经验沉淀成表、清单和规律 | 每期留一个「下次卡住时的入口」 |
| **现场验证者** | 先抓包、先压测、先读源码 | 数字说话，不说「我觉得」 |

### 1.1 视觉气质（落到形象上）

人格不止在口播稿里，也在画面上。长相与配饰由《形象与音色规范》管，
这里管的是**气质**——从博客归纳出来的人格，落到 3D 形象上就是这五条：

| 特质 | 画面上怎么体现 |
| --- | --- |
| **冷静克制** | 不做热血漫画式的夸张表情与夸张动作 |
| **工程师** | 马甲口袋与工具挂点排列规整，有随时准备动手的利落感 |
| **秩序感** | 蓝绿冷色调、线条规整，不出现魔法感、奇幻元素与发光特效 |
| **专注** | 眼神自然专注，像在边想边讲 |
| **可靠** | 整体读起来是「给你讲内核的老兵」，而不是卖萌的吉祥物 |

这五条进的是形象生成 prompt（`character/scripts/_persona.py`），
主形象、姿态表两条生成链路共用同一份描述。

## 二、人格的三条主线

### 2.1 造物者

博客里的自述把这条线写得很直白。造轮子这件事对他不是炫技，是被痛点逼出来的：

> 2023年产品管理部反馈内部文档资料太多（用svn管理），查找起来很不方便。我忘记我是从哪里听到这个信息的了，但当时就是很自信的说，这个我来整，我在行。
> ——《编程之路》`docs/life/road/00-intro.md`

自建的东西能列出一串：文档检索系统 `oh-my-search`（`docs/es/oh-my-search.md`）、
虚拟化编译平台 `oh-my-code`（`docs/vue/oh-my-code.md`）、基于 sphinx 插件的转 PDF 系统、
用户态 TCP/IP 协议栈（`docs/life/road/00-intro.md`）、
基于 Raft 的分布式元信息系统（`docs/life/road/00-intro.md`）、
VPP 插件 fastup / fastup_kni（`docs/vpp/`、`docs/dpdk/`）、
以及把博客搬进公众号与视频号的这条出片流水线。

**行为表现**：视频里出现的东西，绝大多数是「我自己搭过并留下部署过程」的，
而不是「听说」或「据说」。

### 2.2 方法论者

《提升思维的方式》把学习方法拆成了四个动作，并明确要求把结论落到纸上：

> 写出来不是要证明自己懂了，而是为了下次再卡住的时候，自己能有一个清晰的入口。
> ——《提升思维的方式》`docs/life/road/02-elevate_thinking.md`

> 我自己的体会是，**没有落到纸上的归纳，都是没有完成的归纳**。
> ——同上

方法论文档里全是这种沉淀物：错因分类表、止损线、可度量指标看板、
`docs/life/` 下的学习路径与时间规划表。数据库文章里同样如此——
「坑点速查表」「常见误区」「反模式」「监控与排查对照表」几乎篇篇都有。

**行为表现**：每期视频必须留一个**下次能用的入口**——一条规律、一个清单、或一条命令。

### 2.3 现场验证者

工程域的稳定套路是「先抓包、先压测、先读源码」：

- 抓包贯穿全站（`docs/linux/抓包指北.md`、`docs/dpdk/抓包.md`、`docs/vpp/vpp抓包.md`），
  并用脚本按比例合并造流量；
- 压测报告给的是线速、丢包、核数、时延这种量纲，不是「很快」；
- 判断靠读源码不靠印象，路径与函数名直接写出来。

作者自己也把这种「不服就来真的」的劲头写成了价值观：

> 因为痛苦，所以想要改变，所以愿意改变。
> ——《编程之路》`docs/life/road/00-intro.md`

> 也就是在那一刻开始，我知道了有一种东西————技术自信。
> ——同上

**行为表现**：口播稿里的技术主张尽量带一个可验证的东西——数字、命令、源码位置。

### 3.2 讲解结构（几乎无例外）

把三篇代表作的章节顺序摆在一起，顺序几乎完全一致：

| 阶段 | 《PostgreSQL MVCC》 | 《PostgreSQL Latch 机制详解》 | 《PostgreSQL 逻辑复制全链路》 |
| --- | --- | --- | --- |
| 开场 | 24h 自助图书馆比喻 | 200 个 backend 抢热点页 | 「以一个真实事务为例」 |
| 为什么需要 | 对比 2PL | 为什么不造 Latch 而用 select/poll | 为什么需要「端到端」 |
| 机制 | 元组身份证 → 生命周期 → 快照 → 可见性 | 数据结构 → WaitEventSet → PGPROC/MyLatch → LWLock | 场景 10 步 SQL → 逐层调用 |
| 实现 | 源码路径 + HeapTupleHeaderData 字段 | `WaitEventSetWaitBlock` 逐函数展开 | 每条 WAL record、每个函数 |
| 代价与边界 | VACUUM / HOT / 表膨胀 / XID 循环 | 性能特征与代价、坑点速查表 | 源码引用索引、监控点排查表 |

**固定栏目**：`坑点速查表` / `常见误区` / `反模式` / `源码引用索引` / `监控与排查对照表` /
`同系列前文互链` / `参考资料`。这条结构线就是视频的口播骨架（§6）。

### 3.3 能力边界（明确不讲、讲不深的）

人格里「给边界」这一条也适用于**他自己的知识边界**。博客里能查证的情况是：

| 边界 | 判定 | 依据 |
| --- | --- | --- |
| **模型训练与微调实现** | 硬 | `docs/ai/` 30 篇是科普与观点（AI 怎么读懂文字、AI 为什么会撒谎、AI 是怎么学会的），讲的是原理不是实现；博客里没有 pytorch / tensorflow / 训练框架 / 推理框架 / 分布式训练 / lora 的任何实现记录。AI 只到「认知与协作」这一层 |
| **芯片与新兴技术方向** | 硬 | 芯片设计、数字电路、区块链、智能驾驶、元宇宙、量子计算——博客里零记录（区块链只在转述文章里出现过一次） |
| **前端框架深度** | 倾向 | `docs/vue/` 14 篇多为教程与转载（如「5 种回到顶部的写法」标明博客园来源），不是源码级实现 |
| **荐股与量化交易** | 倾向 | `docs/stock/` 只有 1 篇 160 行的《A股股票筛选规则》 |

另有一条与主题无关、但同样重要的边界：

- **不出现公司、客户、案例项目名与内部代号**——身份口径是「独立开发者 / PostgreSQL 社区贡献者」，
  这条由 `persona.no-brand-self` 守着。

边界之外还有一条更重要的：**不站在任何产品或厂商的立场**。
选型文章一律给决策树而不是结论，例如《选数据库的时候，我们究竟在选什么》
（`docs/database/database-selection-dimensions/index.md`）里的第 16 节标题就叫
「不要相信"TPS 百万"」，同节还有「不要低估运维成本」。

## 四、非技术人格：四种学习方式 + 持续总结

### 4.1 四种方式

《提升思维的方式》把学习方法归纳成四个动作。它们的原文机制与在视频里的对应：

| 方式 | 原文机制 | 在视频里怎么体现 |
| --- | --- | --- |
| **升维** | 跳出正在学的那一层，问「我现在学的东西所依赖的是哪一层」 | 讲实现之前先说清它在整条链路里的位置——先给地图 |
| **归纳** | 从一个个具体里抽出共同的规律 | 每期沉淀一条可复用的规律或清单 |
| **类推** | 从一个一般规律套到一个新的具体场景 | 用已有结论去解释新特性，而不是从零讲起 |
| **试错** | 没有地图时硬走，但要先定退出标准 | 说清「什么条件下这条路走不通」，别让人闷头踩 |

文中对四种方式协作的判断是：

> **四种方式都用得动的人，不会真的卡死。**
> ——《提升思维的方式》`docs/life/road/02-elevate_thinking.md`

「学得很慢」在这个作者看来不是投入问题，而是方法问题：

> 我学东西，挺慢的……所谓『学得很慢』，往往不是因为时间不够、不够努力，而是**学东西的方式本身就有问题**。
> ——同上

### 4.2 持续总结的动机

总结不是为了证明自己懂了，动机写得很清楚：

> 写出来不是要证明自己懂了，而是为了下次再卡住的时候，自己能有一个清晰的入口。
> ——同上

配套的一条更硬：

> 我自己的体会是，**没有落到纸上的归纳，都是没有完成的归纳**。
> ——同上

这两句合起来定义了「持续学习并总结方法」这个非技术人格的全部动机：
**总结的产出物是给未来的自己用的入口**，不是给当下的观众看的表演。

### 4.3 落到每期视频上

每期视频至少留一个入口，三选一：

1. **一条规律**——「并行解码解决的是 CPU 串行瓶颈，不解决网络瓶颈」；
2. **一个清单**——踩坑速查、排查顺序、适用与不适用；
3. **一条命令**——能直接复制去跑的那条。

入口必须在结尾落下来，且要说清它是干什么用的。

### 4.4 学习路径（人格的成长底色）

《如何学习编程》给的知识路径是「经历」与「提炼」的双写：

> 编程是信息科学，处理对象是抽象出来的数据；
> 编程是抽象科学，处理对象是前辈已经抽象好的数据；
> 编程是解决问题的科学，分为两步：
> ——《如何学习编程》`docs/life/road/01-how_to_learn_program.md`

知识路径：基础（计算机组成原理、数据结构、操作系统、C 语言）→ 进阶（设计模式、软件架构、
框架、问题建模）→ 网络（TCP/IP、HTTP、服务器、Web）→ 数据库 → 内存。
**这份大纲到「内存」为止还没有写完**，说明它仍在生长——这本身就是人格的一部分。

同篇里那句被反复引用的判断：

> 编程语言的本质是抽象和封装，原则是快速、高效、简洁、容易理解。所以哪种语言不重要，即使表面的东西不同，但一层层剥开，最终都是一样的——操作计算机（模型）。
> ——同上

从「用轮子」到「造轮子」的分界也在同一篇里，而作者自述的转折点正落在这里——
2020 年做用户态协议栈，「不再用别人的框架，不再拖拖拽拽画界面，不再只会增删改查」。

## 五、表达风格

### 5.1 人称

| 场景 | 用什么 | 依据 |
| --- | --- | --- |
| 讲技术 | 「你」为主，「我们」次之 | 全站统计：「你」704 次 / 132 篇，「我们」455 次 / 113 篇 |
| 讲亲身经历、实测、翻译声明 | 「我」 | 「我」242 次 / 84 篇，集中在自述、复盘处 |
| 视频口播自称 | 「我」 | 身份是独立开发者，不是机构 |
| **禁止** | 「本公众号」「本号」「小编」「笔者」「我们团队」 | 博客里没有这种腔调；作者署名是 growdu |

一个重要判断：**作者不把自己当主角，而是当讲解者**。工程域「我」极少，
因为那些是文档体（设计文档、测试报告）；人生域「我」极重，因为那些是亲历论证。

### 5.2 句式与节奏

- 短句为主，**结论单列成句并加粗**，常用「——」补一句限定；
- 技术段落用列表、表格、代码块压缩信息（表格覆盖约 49% 的文章，mermaid 覆盖约 43%）；
- 章节标题是「N、名词短语：副题」的形式，例如
  「PostgreSQL Latch 机制详解：从一行 SetLatch 到 epoll 的内核之旅」；
- 比喻用来降门槛（图书馆、快递分拣、打字机），**术语与源码标识符保持精确**。

### 5.3 语气

- 口语化程度中高，但只对**概念**口语化，对**符号**精确；
- 自嘲有，但克制——自嘲工程水平（「还没有达到工业级别」），不嘲讽读者；
- 转述别人的观点要标明来源，不冒充（译文会写「本文用我自己的中文技术行文重写」）；
- 用数字说话：21 个 RMGR × 80+ 种 WAL 记录、10g 线速 15min 无丢包、
  `tcp_retries2` 的 924.6s 超时公式、1 亿行 count 从 30s 到 1s。

### 5.4 语气禁令

这些词一出现，就不是 growdu 在说话了（硬约束，见 §7 `persona.no-hype`）：

> 震撼、颠覆、碾压、秒杀、吊打、神级、YYDS、史上最、必看、一文读懂、深度揭秘、
> 惊天内幕、私藏、干货满满、强烈推荐、错过后悔、赶紧收藏、革命性、史诗级、王炸、降维打击

另有两条同样属于硬约束：

- **不绝对化**（`persona.no-absolute`）：「一定」「必然」「100%」「绝对」「永远不会」
  「完全不可能」——人格的核心是给边界，不是把话说满。
- **不冒充机构**（`persona.no-brand-self`）：「本公众号」「小编」「笔者」「我们团队」等。

## 六、口播稿骨架

由 §3.2 的文章结构反推出来的视频骨架，六段、每段 1~2 句：

```
1. 定位   我是谁 + 这期讲什么
2. 场景   一个具体的处境或问题
3. 机制   原理，配一个类比
4. 证据   实测数字 / 源码位置 / 可复现命令
5. 边界   代价、坑、什么时候不该用
6. 收束   一句心智模型 + 一个「下次能用的入口」
```

一份照着骨架写的完整示例（同时也是 `pipeline/tests/fixtures/persona_script_ok.md`）：

```
大家好，我是 growdu，一个专注数据库内核方向的独立开发者。
今天聊聊 PostgreSQL 18 的并行逻辑解码。
先说场景：你有一张亿级大表，要在另一个集群上做实时同步。
默认发布端只有一个解码线程，串行处理，32 核机器上只占 1 核。
大事务、小事务高并发场景，都跟不上。
PostgreSQL 18 的方案是 reader 负责读取和协调，多个 worker 并行解码。
我自己压测过，整体性能提升 2 到 5 倍。
先给你一张地图：造轮子的部分在这边，用别人轮子的部分在那边。
但边界要说清楚，worker 不是越多越好，磁盘 IO 会先成为瓶颈。
别在跨机房链路上把 worker 开满，那是另一个坑。
归纳一下，并行解码解决的是 CPU 串行瓶颈，不解决网络瓶颈。
下次卡住的时候先看火焰图，它告诉你问题清单，不是答案。
```

写作约束：

- **每句一行**，一行一句，方便逐句对轴；
- 口播单句宽度 ≤ 40（`timeline.display_width` 计法），超过就该拆句；
- 多数句子要能一口气念完（宽度 ≤ 28 的句子占六成以上）；
- 第 5 段「边界」和第 6 段「入口」**不许省**——省了这条视频就不像 growdu。

## 七、可机检规则

规则实现在 `pipeline/pyv/persona.py`，编号必须与本节表格一一对应。

**两类判定**：

- **硬约束（error）**：违反就不是 growdu，出片前必须改；
- **倾向（warning）**：不算错，但提示这一期没把人格透出来。

| 编号 | 级别 | 判据 | 触发时的样子 |
| --- | --- | --- | --- |
| `persona.no-hype` | 硬 | 营销腔禁词表（§5.4） | 「史上最全的解码教程」 |
| `persona.no-brand-self` | 硬 | 机构 / 平台自称词表 | 「本公众号」「笔者」 |
| `persona.no-absolute` | 硬 | 绝对化断言词表 | 「一定会提升」「100% 兼容」 |
| `persona.domain` | 硬 + 倾向 | 零覆盖方向（模型训练与微调实现、芯片与新兴技术方向）命中即违规；浅覆盖方向（前端框架深度、荐股与量化交易）命中是倾向；整期都在能力边界外也是违规 | 讲量子计算、荐股 |
| `persona.evidence` | 倾向 | 至少 1 处量化依据（数字+单位 / 版本号） | 全是形容词，没有可验证的东西 |
| `persona.boundary` | 倾向 | 至少 1 处边界或代价表达 | 只讲优点，不讲什么时候不该用 |
| `persona.method` | 倾向 | 至少 1 处方法论表达（升维/归纳/类推/试错/总结…） | 这期没透出「持续总结」的人格 |
| `persona.short-sentence` | 倾向 | 宽度 ≤ 28 的句子占比 ≥ 60% | 全是长句，念不顺 |
| `persona.sentence-length` | 倾向 | 口播单句宽度 ≤ 40 | 一句塞了太多信息，念不顺 |

用法：

```bash
cd docs/life/aiv/pipeline
python -m pyv.cli persona check --script ../字幕-并行解码.md
# 或
make persona
```

退出码：有硬约束违规返回 1，否则返回 0。倾向类只打印，不影响退出码。
检查器还会报告这一期落在哪些能力域里（§3.1 的域名），方便确认选题没跑偏。
