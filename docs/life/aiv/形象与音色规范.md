# AIV 模型形象与音色规范

后续视频统一使用这套「模型形象」与「音色」。本文记录**规范本身**（入库、可评审），
图像与音频成品留本机（`character/`、`voice/`，不入库）。

> 形象原型的唯一来源：`docs/life/aiv/growdu2.jpeg`。
> 音色的唯一参照：`docs/life/aiv/ddl-voiceover.mp3`。

| 项 | 规格 |

### 1.3 与代码场景的合成方式

透明底 PNG 贴到 cairo 画布即可，文字区保持右侧留白：

```python
# 参考 pipeline/pyv/render.py 的 _frame_bytes 与 elephant.py 的 _pil_to_cairo
surface = cairo.ImageSurface(cairo.FORMAT_ARGB32, 1920, 1080)
ctx = cairo.Context(surface)
ctx.set_source_rgb(1, 1, 1); ctx.paint()
# 形象：等比缩放到画布高 66%，锚点左下 (0.05*W, 0.90*H)
ctx.set_source_surface(img_surface, int(W * 0.05), int(H * 0.90 - img_h))
ctx.paint()
```

配色、字体、文字排版沿用 `pipeline/pyv/palette.py`（`#2B4C7E` 主色、`#F5A623` 强调色、
`PingFang SC`），保证形象与代码画面属于同一套视觉系统。`character/style_preview.png`
是这套合成规则的实际效果。

### 1.4 为什么铭牌要留空

模型生成的文字会乱码。生成 6 姿态设定表时，铭牌上的 `growdu` 出现
`giowdu` / `grawdu` 等变形；改成「铭牌留空、文字后期渲染」后完全干净。

这与 `brand/scripts/fix_plates.py` 记录的同一类问题——**AI 生成的文字不可信，
所有文字用真实字体渲染**。铭牌文字用 `PingFang SC` 在 cairo 阶段绘制。

主形象这次模型**碰巧**把 `growdu` 写对了，但这不能当规范用：规范要的是
「画面上永远只有代码渲染的文字」。所以 `character/scripts/blank_badge.py`
在生成之后把铭牌刷成纯白，定位方式是自动的（不硬编码坐标）：

1. 找「近白色」的连通块，排除与画布边缘相连的（那是背景）；
2. 候选必须是横向长方形、边长与面积都够大；
3. 铭牌是「被深藏蓝马甲围住的一小块白」，所以四周一圈马甲色占比最高的那个就是它。

当前素材实测：铭牌矩形 `(1118, 1319, 1265, 1380)`，四周马甲色占比 52%。

### 1.5 与旧 2D 形象的关系

仓库原有的 `growdu.png`（2D 扁平形象，1220×1289）是**另一套形象**，服务于
`pipeline/pyv/elephant.py` 的部件切分动画：它按颜色连通块定位头/双耳/双臂，
阈值和绝对坐标都是为这张 2D 图硬编码的。

**3D 新形象不能喂进 `elephant.py`**——连通块切分依赖扁平色块，3D 渲染的渐变与高光
会直接破坏阈值分割。两条路：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| A（推荐） | 新形象作为**静帧素材**贴入场景，配合整体位移/缩放/淡入做动效 | 形象统一，无代码改动 |
| B | 为 3D 形象重写部件切分 | 3D 渲染下连通块不可靠，需换分割算法，成本高 |

后续视频走方案 A。

**已落地**：`pipeline/pyv/character.py` 是形象接入的统一入口，按优先级降级：

| 优先级 | 素材 | 位置 | 动效 |
| --- | --- | --- | --- |
| 1 | 新 3D 形象（透明底） | `aiv/character/growdu_character_2k_nobg.png`（媒体产物，不入库） | 静帧 + 位移 / 缩放 / 淡入 |
| 2 | 旧 2D 形象 | 仓库根 `growdu.png`（已入库） | `elephant.py` 部件动画（挥手 / 点头） |
| 3 | 都没有 | — | 不画形象，不报错 |

降级的原因是**媒体产物不入库**：新克隆的机器上没有 3D 形象，但仓库根的
`growdu.png` 在，流水线照样画得出小象。

旧 2D 形象原本只放在 `aiv/growdu.png`，场景里写死那个路径 → `make render` 直接
`FileNotFoundError`。现在统一由 `character.py` 给出路径，场景不再自己拼路径。

落版头像同理：原来的 `growdu.jpg` 从未入库、现已丢失，改用仓库根
`themes/matery/source/medias/avatar.jpg`（已入库）。头像缺失时整块跳过，
标签位置不变。

## 二、音色规范

### 2.1 参照音色的实测特征

对 `ddl-voiceover.mp3`（29.27 s / 单声道 / 32 kHz）做声学测量：

| 指标 | 实测值 | 判读 |
| --- | --- | --- |
| 基频 F0 中位 | **116.7 Hz** | 男声，且偏低沉 |
| F0 p5 – p95 | 87 – 188 Hz（跨 102 Hz） | **动态幅度大**，有强弱起伏 |
| 第一共振峰 F1 | 273 Hz | 男声区间（280–400）下限 |
| 第二共振峰 F2 | 961 Hz | 略低于男声典型值（1100–1900） |
| 频谱重心 | 1222 Hz | 偏暗、不尖锐 |
| 语速 | **7.72 字/秒** | 偏快（226 字 / 29.27 s） |

结论：**成年男声，偏低沉、偏暗，语速偏快，情绪起伏明显**——技术讲解口吻，
不是播音腔也不是广告腔。

### 2.2 选定音色

在 MiniMax 327 个音色中实测合成 22 个中文男声候选，用同一套指标
（F0 半音差 + F1/F2 绝对差 + 频谱重心 + 语速 + **F0 动态跨度**）排序，
再在真实口播稿上做 speed × pitch 网格微调。

**定稿：**

```json
{
  "voice_id": "Chinese (Mandarin)_Radio_Host",
  "voice_name": "电台男主播",
  "pitch": -1,
  "speed": 1.33,
  "emotion": "neutral"
}
```

实测对齐度：

| 指标 | 参照 | 定稿 | 偏差 |
| --- | --- | --- | --- |
| F0 中位 | 116.7 Hz | 117.2 Hz | **+0.1 半音** |
| F1 | 273 Hz | 312 Hz | +39 Hz |
| F2 | 961 Hz | 992 Hz | +31 Hz |
| 频谱重心 | 1222 Hz | 1131 Hz | −7.5% |
| F0 动态跨度 | 102 Hz | 107 Hz | +5 Hz |
| 总时长 | 29.27 s | 29.65 s | +0.38 s |
| 语速 | 7.72 字/秒 | 7.62 字/秒 | −1.3% |

### 2.3 备选

| 音色 | pitch | speed | 说明 |
| --- | --- | --- | --- |
| `Chinese (Mandarin)_Radio_Host` | −2 | 1.35 | 备选一：F0 动态跨度 103 Hz，与参照最接近；F2 偏差更小（+16 Hz） |
| `Chinese (Mandarin)_Southern_Young_Man` | 0 | 1.5 | F1 完全吻合（+0 Hz），但 F0 动态只有 40 Hz，**听感过于平直**，不建议 |

三个音频样本在 `voice/` 下可试听。

### 2.4 调用方式

```bash
mcode-tools connector call connector__matrix__synthesize_speech --args '{
  "text": "大家好，我是growdu。今天我们聊一聊数据库内核。",
  "voice_id": "Chinese (Mandarin)_Radio_Host",
  "pitch": -1,
  "speed": 1.33,
  "emotion": "neutral",
  "output_file": "narration.mp3"
}'
```

参数速查：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `pitch` | **−1** | 半音。降到 −2 更低沉，但 F0 略低于参照 |
| `speed` | **1.33** | 语速倍率。1.5 在真实稿上偏快 12% |
| `emotion` | `neutral` | 讲解场景用中性；需要强调时改 `happy` / `surprised` |

**注意**：`pitch` 与 `speed` 的最优值是相对参照稿标定的。换了口播稿（字数/断句不同），
应重跑 §2.1 的测量并重新定标，不要直接套用。

### 2.5 与旧品牌片音的关系

`brand/scripts/make_audio.sh` 用的是 macOS `say`（Sandy 童声 + 升 1.5 半音），
和本规范不一致，**只服务旧的 8 秒品牌片**。当前 3 秒片头/片尾的旁白已经按 §2.2
定稿音色合成（`brand/audio/voice_intro.mp3` / `voice_outro.mp3`）。
