## 一、外网基础:把原理搞明白,别再瞎折腾

这一节不推荐任何具体的订阅源或机场,只讲**技术原理与合规使用方法**。工具本身是公开的,怎么用是你的自由,但请遵守所在地区的法律法规和单位的规定。

### 1.1 你真正在解决的问题

简单说,你的机器访问不了某些境外服务器,问题出在这三段链路的任意一段:

```text
你的应用 (浏览器 / curl / Node)
        │
        ▼
   本地客户端 (mihomo / Clash Verge Rev)
        │  ← 负责:DNS 劫持、规则分流、流量转发、TUN 接管
        ▼
   中转节点 (你的服务商提供的出口)
        │
        ▼
   目标站点 (google.com / api.openai.com)
```

四个环节,任何一环没配好都会"看起来能上但就是打不开"。所以排查的时候要**分段定位**,而不是反复换节点。

### 1.2 客户端怎么选

| 客户端 | 平台 | 内核 | 推荐度 | 说明 |
| --- | --- | --- | --- | --- |
| **Clash Verge Rev** | Win / macOS / Linux | mihomo | ★★★★★ | 图形界面最成熟,内置订阅管理,新手首选 |
| **mihomo Party** | Win / macOS / Linux | mihomo | ★★★★☆ | 界面更现代,内置订阅管理,TUN 可视化做得好 |
| **mihomo**(纯命令行) | 全平台 | mihomo | ★★★★☆ | Docker / 服务器 / 极简党,配置全是 YAML |
| **Clash Meta for Android** | Android | mihomo | ★★★★ | 手机端主力 |
| **Stash** | iOS | 自研 | ★★★★ | iOS 上少数支持 TUN 的客户端之一 |

> 💡 **一句话**:桌面用 **Clash Verge Rev**,手机用 **Clash Meta for Android**,服务器用 **mihomo** 原生。三个都是 mihomo 内核,配置文件通用。

### 1.3 规则分流:为什么必须开

这是新手最容易忽略、但对体验影响最大的一环。

如果所有流量都走境外出口,会出现这些症状:

- 国内网站(淘宝、京东、公司的内网系统)变慢或直接打不开
- 网银、支付、企业 SSO 频繁风控
- 动态 IP 让同一家公司把你识别成"异常流量"
- 阿里云/腾讯云的服务器 SSH 延迟飙升

**规则分流的逻辑**:让国内流量走直连,只有"匹配代理规则"的流量走代理。

```yaml
# mihomo 配置片段示例(放在 rules 之前)
proxy-groups:
  - name: PROXY
    type: select
    proxies:
      - 🚀 节点选择
      - ♻️ 自动选择
      - DIRECT

rules:
  # 1) 内网与私有地址直连
  - IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
  - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  - IP-CIDR,172.16.0.0/12,DIRECT,no-resolve
  # 2) 局域网服务直连
  - DOMAIN-SUFFIX,local,DIRECT
  # 3) 国内常用服务直连(示例,生产请用 GEOSITE 规则集)
  - GEOSITE,CN,DIRECT
  - GEOIP,CN,DIRECT,no-resolve
  # 4) 私有 API 与流媒体分流
  - DOMAIN-SUFFIX,openai.com,PROXY
  - DOMAIN-SUFFIX,anthropic.com,PROXY
  - DOMAIN-SUFFIX,google.com,PROXY
  - DOMAIN-SUFFIX,youtube.com,PROXY
  # 5) 兜底
  - MATCH,PROXY
```

### 1.4 三种接管方式,你需要知道区别

| 模式 | 原理 | 能接管什么 | 推荐场景 |
| --- | --- | --- | --- |
| **系统代理** | 设置 HTTP/SOCKS 代理 | 浏览器、显式支持代理的 App | 日常上网,最省心 |
| **环境变量** | `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` | CLI 工具(curl、git、npm、pip) | 写代码时最常用 |
| **TUN 模式** | 虚拟网卡,接管所有 TCP/UDP | 不支持代理设置的 App、游戏、某些客户端 | 需要"全都要"时开 |

命令行工具走代理最常被忽略,结果就是 `git clone` 卡死、`npm install` 超时:

```bash
# 临时生效
export HTTP_PROXY=http://127.0.0.1:7890
export HTTPS_PROXY=http://127.0.0.1:7890
export ALL_PROXY=socks5://127.0.0.1:7890

# 验证
curl -I https://api.openai.com

# git 单独配置(更常用)
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890

# npm
npm config set proxy http://127.0.0.1:7890
npm config set https-proxy http://127.0.0.1:7890

# pip
pip config set global.proxy http://127.0.0.1:7890
```

> ⚠️ 别忘了**取消**:`unset HTTP_PROXY HTTPS_PROXY ALL_PROXY`,以及 `git config --global --unset http.proxy`。很多"公司内网访问不了"的锅就是代理没关。

### 1.5 DNS:80% 的"打不开"都是它

典型症状:浏览器显示 `ERR_NAME_NOT_RESOLVED` / `DNS_PROBE_FINISHED_NXDOMAIN`,但节点明明是好的。

```yaml
# mihomo DNS 配置片段
dns:
  enable: true
  listen: 0.0.0.0:53
  ipv6: false
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16
  fake-ip-filter:
    - '*.lan'
    - '*.local'
    - '+.msftconnecttest.com'
    - '+.msftncsi.com'
  default-nameserver:
    - 223.5.5.5
    - 119.29.29.29
  nameserver:
    - https://doh.pub/dns-query
    - https://dns.alidns.com/dns-query
  proxy-server-nameserver:
    - https://doh.pub/dns-query
  nameserver-policy:
    'geosite:cn,private':
      - https://doh.pub/dns-query
    'geosite:geolocation-!cn':
      - https://dns.cloudflare.com/dns-query
```

三个关键词解释:

- **fake-ip**:让域名先映射成一个假 IP,由客户端按真实域名转发。优点是分流准确、避免污染。
- **nameserver-policy**:按域名后缀指定解析器。国内域名走国内 DoH,国外域名走国外 DoH,避免国外 DoH 被干扰导致大量空结果。
- **default-nameserver**:给上面这些 DoH 域名本身用的解析器,必须是国内可达的 IP,否则会死锁。

### 1.6 故障排查速查表

| 症状 | 最可能的原因 | 排查动作 |
| --- | --- | --- |
| 浏览器打不开境外站点,国内正常 | 规则分流把目标域名分到 DIRECT | 打开客户端日志,搜域名看命中了哪条规则 |
| `ERR_TIMED_OUT` 但节点延迟正常 | TUN 没开 / 应用不走系统代理 | 该应用是否支持代理?必要时开 TUN |
| `DNS_PROBE_FINISHED_NXDOMAIN` | DNS 被污染或 fake-ip 配置错误 | 换 DoH,检查 `nameserver-policy` |
| CLI 工具超时,浏览器正常 | 命令行没设代理环境变量 | `export HTTPS_PROXY=...` |
| 视频网站提示"不可用" | 出口 IP 被判为机房 IP / 区域限制 | 换节点类型,选住宅或流媒体解锁 |
| 频繁掉线 | 节点拥塞或 MTU 不合适 | 换协议,试试调小 MTU 或开启分片 |
| 公司内网访问不了 | 代理没关 / 规则没直连内网网段 | 取消代理,补 `IP-CIDR,10.0.0.0/8,DIRECT` |

一条万能命令,直接看出请求走到哪了:

```bash
# 看 DNS 解析结果和连通性
nslookup github.com

# 详细握手过程(看是否卡在 TLS)
curl -v --connect-timeout 10 https://api.openai.com

# 只看耗时
curl -o /dev/null -s -w 'dns:%{time_namelookup}s tcp:%{time_connect}s tls:%{time_appconnect}s total:%{time_total}s\n' https://api.openai.com
```

> 📌 **合规提醒**:请遵守你所在地区的法律法规、单位网络管理规定与相关服务条款。不要用于任何违法违规用途,不要传播或售卖账号,不要在生产环境里用不合规的出口做业务。

## 二、Google:不只是搜索引擎

对开发者来说,Google 的价值分三层:**搜索(找答案)、AI Studio/Gemini API(调模型)、开发者生态(Colab / Firebase / Cloud)**。

### 2.1 账号体系先搞清楚

注册一个 Google 账号是第一步,但很多人卡在"注册后收不到验证码"。常见原因和对策:

| 问题 | 原因 | 对策 |
| --- | --- | --- |
| 收不到短信验证码 | 号码被风控 / 发送频率超限 | 换号段、隔一段时间重试、优先用语音验证 |
| 提示"此浏览器无法验证" | 自动化检测 | 关闭无痕、手动点"我不是机器人" |
| 登录后立刻掉线 | Cookie / UA 被识别为脚本 | 用正常浏览器配置,别在脚本里裸奔 |
| 提示"此账号无法使用 Google 付款" | 区域策略 | 见 10.1「账号与区域」 |

**账号安全三件套**:

```text
1. 主号 + 找回邮箱 + 备用邮箱 —— 别只留一个
2. 开启两步验证(2FA):优先用 Passkey 或 TOTP 验证器,别只靠短信
3. 开启登录告警:有新设备登录时收到邮件通知
```

### 2.2 搜索技巧:把 Google 当数据库用

这是投入产出比最高的一段。学会下面这些,你能少问 AI 一半的问题(因为有些答案你直接搜得到原文)。

| 语法 | 作用 | 例子 |
| --- | --- | --- |
| `"精确短语"` | 只匹配完整短语 | `"connection pool exhausted"` |
| `site:` | 限定站点 | `site:github.com postgres deadlock fix` |
| `filetype:` | 限定文件类型 | `filetype:pdf system design interview` |
| `-关键词` | 排除 | `golang 协程 -教程` |
| `*` | 通配 | `"how to * in postgres"` |
| `inurl:` | 路径包含 | `inurl:docs python asyncio` |
| `related:` | 相似站点 | `related:stackoverflow.com` |
| `cache:` | 找缓存快照 | `cache:site:example.com` |
| `OR` | 逻辑或 | `postgres OR mysql "connection limit"` |

**开发者最常用的三条组合**:

```text
# 找官方文档里的具体段落
site:docs.python.org "asyncio.wait_for"

# 找某个报错的原因(带上完整报错)
"ECONNRESET" "npm install" node 18

# 找 GitHub 上被解决过的 issue
site:github.com/denoland/deno/issues "permission denied" macOS
```

> 💡 **技巧**:搜报错时,把**完整错误信息**用引号包起来,命中率比用关键词高一个量级。

## 三、YouTube:免费的技术大学

如果你觉得中文技术教程不够用,**YouTube 是全世界最大、最免费、最系统的技术学习库**。很多英文技术视频有自动字幕,配合 AI 摘要,效率直接翻倍。

### 3.1 先把客户端调到位

| 设置项 | 在哪 | 建议 |
| --- | --- | --- |
| 字幕 | 播放器右下角 `CC` | 英文视频必须开 |
| 字幕语言 | 设置 → 字幕 → 字幕语言 | 优先"英语(自动生成)" |
| 播放速度 | 设置 → 播放速度 | 1.25x~1.5x 是甜点区,2x 适合已知内容 |
| 章节 | 播放器下方进度条 | 找重点直接跳转 |
| 跳过广告 | 点击"跳过广告"按钮 | 手动比插件可靠 |
| 画质 | 设置 → 画质 | 1080p 足够,省带宽 |

### 3.2 找内容:比搜索引擎还准的搜索语法

YouTube 搜索框支持这些高级语法:

| 语法 | 作用 | 例子 |
| --- | --- | --- |
| `""` | 精确短语 | `"react server components" tutorial` |
| `-` | 排除 | `rust -game` |
| `intitle:` | 标题包含 | `intitle:"full course"` |

实战例子,搜"带字幕的完整课程":


### 3.3 用 yt-dlp 拉字幕,喂给 AI

这是把 YouTube 变成"你的私有知识库"的关键一步。

```bash
# 安装
pip install -U yt-dlp

# 只下自动字幕(不下载视频),英文字幕
yt-dlp --skip-download --write-auto-sub --sub-lang en,en-orig \
  --sub-format vtt "https://www.youtube.com/watch?v=VIDEO_ID"

# 也下载中文自动字幕
yt-dlp --skip-download --write-auto-sub --sub-lang "zh-Hans,en" \
  --sub-format vtt "https://www.youtube.com/watch?v=VIDEO_ID"

# 批量下载一个频道最近的 20 个视频
yt-dlp --playlist-items 1:20 --skip-download --write-auto-sub \
  --sub-lang en --sub-format vtt "https://www.youtube.com/@CHANNEL_NAME/videos"
```

拿到的 `.vtt` 文件是带时间轴的,喂给 AI 之前先清洗一下,效果好很多:

```python
import re


def vtt_to_text(path: str) -> str:
    with open(path, encoding="utf-8") as f:
        raw = f.read()
    # 去掉 WEBVTT 头、序号行、时间轴行、标签
    lines = []
    for line in raw.splitlines():
        s = line.strip()
        if not s or s.startswith("WEBVTT") or s.startswith("Kind:"):
            continue
        if "-->" in s or re.fullmatch(r"\d+", s):
            continue
        s = re.sub(r"<[^>]+>", "", s)
        s = s.replace("&nbsp;", " ").replace("&#39;", "'").replace("&amp;", "&")
        lines.append(s)
    # 去掉字幕常见的重复行
    out, prev = [], None
    for l in lines:
        if l != prev:
            out.append(l)
        prev = l
    return "\n".join(out)


text = vtt_to_text("video.en.vtt")
with open("video.txt", "w", encoding="utf-8") as f:
    f.write(text)
print(len(text), "chars")
```

然后就是 AI 的活了。

### 4.4 API 计费:别用错模型

ChatGPT 订阅**不包含** API 额度,API 要单独按 token 付费。这是很多人踩坑的地方。

省钱三原则:

1. **分类路由**:简单任务(改个变量名、提取字段)用小模型,复杂推理用大模型
2. **缓存提示词前缀**:系统提示 + 长文档固定不变的部分用 prompt caching,能省一大截
3. **限制输出**:明确写"不超过 200 字",比事后截断省钱

```bash
curl https://api.openai.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{
    "model": "gpt-4.1-mini",
    "messages": [
      {"role": "system", "content": "你是资深 Go 工程师,输出简洁,给可直接运行的代码"},
      {"role": "user", "content": "写一个带超时和重试的 HTTP GET 客户端"}
    ],
    "max_tokens": 800,
    "temperature": 0.2
  }'
```

### 4.5 提示词模板:代码场景直接抄

**代码审查**(把代码放在最后一个 `---` 之后):

```text
你是资深代码审查者。下面这段代码请按以下维度检查:
1. 正确性(边界条件、空值、并发安全)
2. 性能(N+1 查询、无界内存增长、阻塞 IO)
3. 安全(注入、越权、敏感信息日志输出)
4. 可维护性(命名、单一职责、错误处理)

按严重程度排序输出,每条给出:问题 → 具体行 → 建议改法(带代码)。
如果没有问题,明确说"未发现明显问题",不要为了凑数编造。

---
(把代码贴在这里)
```

**重构**:

```text
重构下面的代码,目标:
- 消除重复逻辑,提取公共函数
- 用类型约束表达状态(比如用 enum 代替魔法字符串)
- 保持对外接口完全不变
- 补上单元测试骨架

先列出你的重构计划(3-5 条),等我确认后再改代码。
```

**读陌生代码库**:

```text
这个项目的目录结构如下(我贴了 tree 输出)。
请推断:
1. 技术栈与主要框架
2. 代码组织的分层方式
3. 入口在哪、从请求进入到响应返回的完整调用链
4. 测试怎么跑
5. 如果我要新增一个 REST 接口,应该改哪些文件

不确定的地方明确标"不确定",不要编造文件名。
```

### 4.6 避坑清单

| 坑 | 表现 | 对策 |
| --- | --- | --- |
| **幻觉** | 编造不存在的 API、函数、参数 | 涉及具体 API 时要求它给出官方文档链接,并自己验证 |
| **过时知识** | 用的是老版本写法 | 给它版本号,或先让它读 `package.json` / `go.mod` |
| **上下文污染** | 上传了含密钥的文件 | 上传前先扫一遍,敏感信息脱敏 |
| **过度自信** | 语气笃定但全错 | 要求它标注"确定"和"推测"的区别 |
| **隐私** | 代码被用于训练 | 个人项目无所谓;公司项目必须走企业版或关闭训练 |
| **长上下文陷阱** | 塞 50 页文档,回答跑偏 | 关键信息放最前面和最后面,中间部分靠摘要 |

**关闭数据训练**(个人版):

```text
Settings → Data Controls → "Improve the model for everyone" → 关闭
```

这个开关很多人从来没看过,但它直接决定了你的代码会不会出现在别人的对话里。

### 5.3 CLAUDE.md:给 AI 写项目说明书

`CLAUDE.md` 是 Claude Code 的项目级记忆文件,放在项目根目录。它会被自动读进每次会话。

```markdown
# CLAUDE.md

## 项目简介
这是一个用 Go 写的订单聚合服务,对接 3 个上游渠道,日订单量约 200 万。

## 技术栈
- Go 1.22 / PostgreSQL 15 / Redis 7 / Kafka
- 使用 chi 做路由,sqlc 生成 SQL 代码
- 部署在 Kubernetes,配置走 viper

## 常用命令
- 构建:make build
- 测试:make test(单测) / make test-integration(需要本地起 PG)
- Lint:golangci-lint run
- 生成 sqlc 代码:make gen-sqlc

## 代码规范
- 所有 SQL 必须用参数化查询,禁止字符串拼接
- 错误统一用 fmt.Errorf("...: %w", err) 包装
- 导出的函数必须有 GoDoc 注释
- 不要在 controller 层写业务逻辑,逻辑放 service 层

## 注意事项
- 上游渠道 B 的接口返回结构不稳定,统一在 adapter 层做归一化
- 本地开发用 docker-compose 起依赖,不要真的连生产库
```

**进阶用法**:在 `CLAUDE.md` 里引用子文件,做成分层记忆。

```markdown
## 详细文档
- 数据库设计见 @docs/schema.md
- 上游渠道协议见 @docs/channels.md
- 部署流程见 @docs/deploy.md
```

`@路径` 语法会被 Claude Code 自动展开并加载,不用把所有东西塞进一个文件。

## 七、ZCode:智谱的 vibe coding 桌面端

ZCode 是智谱(Z.ai)推出的 **Agentic Development Environment(ADE)**,定位不是"AI 插件",而是一个完整的 AI 编程桌面工作台。

### 7.1 基本信息

| 项目 | 信息 |
| --- | --- |
| 官网 | `zcode.z.ai`(国内 `zcode.z.ai/cn`) |

| 登录方式 | Z.ai 账号、Bigmodel.cn 账号、API Key |

### 7.2 它和 VS Code + Copilot 有什么不同

这是理解 ZCode 的关键:

| 维度 | VS Code + Copilot | ZCode / Claude Code 这类 ADE |
| --- | --- | --- |
| 交互模型 | **你写,AI 补全** | **你描述目标,AI 编排执行** |
| 主动性 | 逐行建议 | 主动规划、跨文件修改、跑测试、自我修复 |
| 单位 | 一行代码 | 一个任务 / 一个 Goal |
| 过程 | 看不见 | 有计划列表、进度、终端输出,全程可观测 |

一句话:**IDE 是你指挥 AI 打字,ADE 是你派 AI 干活。**

### 7.3 Goal 模式:长程任务管理

ZCode 的核心工作流是 Goal 模式,一个 Goal 内部会经历:

```text
目标描述 → 生成计划(可审阅/修改) → 分步实现 → 自动跑测试 → 识别失败 → 修复 → 验收
```

这正好解决纯聊天式 AI 的老问题:你提一个"把用户系统重构到微服务"的需求,它给你一段代码,再提下一个需求,再给一段代码——永远拼不起来。Goal 模式是把它当**一个项目**来做。

**一个能用的 Goal 描述长这样**:

```text
目标:给现有的 FastAPI 项目加上基于 JWT 的用户认证。

要求:
1. 新增 /api/auth/register 和 /api/auth/login 两个接口
2. 密码用 bcrypt 存储,禁止明文
3. 引入依赖前先更新 requirements.txt
4. 补充 pytest 测试:注册成功、密码错误、token 过期三种场景
5. 不要改动现有业务逻辑代码,只做增量

约束:
- 现有的 database.py 里已有 Session 工厂,直接复用
- 风格遵循项目里已有的模块(参考 src/api/items.py)
```

带**要求 + 约束 + 参考样例**的三段式,比一句话效果高一个量级。

### 7.4 多 Agent 并行

ZCode 支持多个 Agent 并行干活,配置方式类似 Claude Code 的 `.claude/agents/` 风格:

```text
    ├── tester.md        # 测试补全 agent
    └── migrator.md      # 数据迁移 agent
```

典型的并行拆分:

```text

├── Agent A: 写单元测试
├── Agent B: 写 API 文档(Swagger 注释)
└── Agent C: 检查安全漏洞与依赖风险
```

对大重构来说,这比单 agent 串行改快好几倍。

## 八、MiniMax Design:多模态创作工作台

前面六个工具解决的是"**写代码、找资料、读文档**",MiniMax Design 解决的是另一类需求:**做图、做视频、做包装、做短剧、做数字人**。

### 8.1 基本信息

| 项目 | 信息 |
| --- | --- |
| 官网 | `design.minimax.io`(国内 `design.minimaxi.com`) |
| 形态 | Web 平台 + 桌面客户端 |
| 桌面端 | macOS 13+(M1~M5 / Intel)、Windows 10+ x64、Linux(beta) |
| 体系 | 隶属 MiniMax 海螺 AI |

它不是一个"文生图"输入框,而是一个**多模态创作工作台**:图片、视频、音频、文本在同一个项目里联动。

### 8.2 五步工作流(核心)

这是 MiniMax Design 官方定义的工作流,理解了它你就知道怎么用:

```text
AGENT MODE → CANVAS FLOW → SKILL READY → LOCAL INDEX → OUTPUT SYNC
   对话驱动      多模态画布     技能固化      本地索引     成品输出
```

逐步解释:

#### 第 1 步:AGENT MODE(对话驱动)

先用自然语言把需求说清楚,让 Agent 理解你要做什么、搭好整体框架。

```text
我要做一个「城市咖啡」品牌宣传片,受众是 25-35 岁白领,
调性:高级、克制、有一点点复古,不要那种大红大绿的土味风。
需要包含:品牌 logo 展示、产品特写、门店环境空镜,
最后有一个 CTA。整体时长控制在 15 秒。
```

#### 第 2 步:CANVAS FLOW(多模态画布)

Agent 会把需求落到画布上,变成一个个可编辑的节点——图片、视频、音频、文本块在这里排布、替换、调整。

```text
这一步的关键词是「画布」:不是一次生成完就结束,
而是可以逐个素材替换、调节奏、重新生成某一段。
```

#### 第 3 步:SKILL READY(技能固化)

把跑通的流程**存成 Skill**,下次直接调用。这是从"一次性创作"变成"可复用产能"的关键。

```text
比如存一个「电商主图」Skill:
输入 = 产品名 + 卖点 + 目标人群
输出 = 主图 + 3 张场景图 + 详情页横幅,统一配色与字体
```

#### 第 4 步:LOCAL INDEX(本地索引)

把你的素材库(本地图片、参考视频、品牌资料)建立索引,让 Agent 能检索、引用、风格对齐。

```text
把公司的 logo、品牌色板、字体规范、产品照片丢进去,
之后所有生成的内容都会自动对齐品牌规范。
```

#### 第 5 步:OUTPUT SYNC(成品输出)

导出成品到本地或云端,进入交付环节。

## 十、安全、合规与账号风险

这一节是我认为整篇文章**最重要**的部分。工具再好用,踩了红线就是给自己埋雷。

### 10.1 账号与区域

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| **区域限制** | OpenAI / Anthropic / Google 官方对部分地区的注册有明确限制 | 使用前确认服务条款中关于你所在区域的条款;不要用虚假信息注册 |
| **支付方式** | 部分订阅仅支持特定地区的信用卡 | 优先选择支持本地货币或本地支付的服务(如 MiniMax) |
| **多账号** | 同一设备频繁切换账号、频繁注册 | 封号几乎必然发生;别为了薅免费额度建小号 |
| **共享账号** | 账号租借、成品号买卖 | 封的是你,不是卖家;且可能泄露你的对话记录 |
| **封禁连带** | 同一支付方式或设备指纹下的账号被批量封 | 一荣俱荣一损俱损 |

> 📌 **底线**:不要为了访问而伪造身份信息、不要购买或出售账号、不要用同一份密钥多人共享。

### 10.2 API Key 管理

密钥泄漏是**最高频**、损失最大的事故。给你一份可以直接抄的规范:

```text
1. 永远不把 Key 写进代码仓库
2. 永远不用 ChatGPT / Claude 直接生成后原样提交 —— 它可能把读到的 .env 内容打印出来
3. Key 放环境变量或密钥管理服务,按需注入
4. 生产 / 测试 / 本地 用不同 Key,出事能快速定位
5. 设置用量上限和告警(OpenAI / Anthropic / MiniMax 都支持项目级预算限制)
6. 定期轮换,尤其是离职交接、成员变动时
7. 检查 .gitignore 里有没有 .env、*.pem、id_rsa、credentials
```

**验证仓库是否已经泄漏**:

```bash
# 1) 确认 .gitignore 覆盖
grep -nE '\.env|\.pem|credentials|secret' .gitignore

# 2) 扫描历史提交里的密钥特征(需要装 gitleaks 或 trufflehog)
gitleaks detect --source . --redact

# 3) 检查历史提交里是否曾经提交过 .env
git log --all --diff-filter=A --name-only | grep -E '\.env$'
```

如果发现泄漏过,**光删文件不够**,必须先去平台后台吊销并轮换 Key,再改历史。

### 10.3 代码与数据隐私

| 场景 | 风险 | 做法 |
| --- | --- | --- |
| 把公司代码贴进免费版 AI | 可能用于训练 | 关训练开关;敏感项目用企业版 |
| 把客户数据、生产数据贴进去 | 数据泄露 | 先脱敏,用假数据 |
| 让 agent 读取 `.env` | 密钥进上下文 | 在 CLAUDE.md / 项目指令里明确禁止读密钥文件 |
| agent 自动执行危险命令 | 误删、误推 | 用权限模式 + 白名单;生产环境加人工确认 |
| 自动 commit / push | 意外推送 | 在 hook 里禁止自动 push,只允许本地 commit |

**CLAUDE.md 里的安全条款示例**:

```markdown

- 涉及数据库写操作,必须先向我确认
- 不要把密钥、内部域名、真实客户数据写进代码或日志
```

## 写在最后

工具会一直变。今天是 Claude Code,明天可能是别的名字;今天是 M3,下个月可能就 M4 了。

但有两件事不会变:

1. **你通过网络获取信息的能力**,决定你能看到多大的世界
2. **你把 AI 组织进工作流的能力**,决定你能交付多少东西

工具只解决"能不能",工作流解决"好不好"。真正拉开差距的从来不是用了哪个模型,而是你有没有把模型接进自己每天的真实流程里。

建议你先**只挑两个工具用满一周**——比如 Google + YouTube 解决输入问题,Claude Code 或 ChatGPT 解决输出问题。一个月之后你大概就知道,自己到底缺什么了。
