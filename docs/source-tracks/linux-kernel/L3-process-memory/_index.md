# 进程与内存

进程与线程在内核里怎么工作：fork 复制了什么、execve 怎么换掉进程镜像、缺页与 COW 怎么把内存管起来、EEVDF 又怎么在核之间调度它们。

「进程与内存」这一站解决三个问题：**一个新的进程是怎么被创建的**、**它的内存是怎么被管理的**，
以及**它什么时候轮到 CPU**。

内核里只有一个 `struct task_struct`，没有独立的「线程」概念：线程就是共享地址空间、
文件描述符表和信号处理方式的另一个任务。而「创建进程」在内核里从来不是一步到位——
`fork()` 复制出一个几乎一样的任务，`execve()` 再把它的内存镜像整个换掉，
两步合起来才是一个用户熟悉的 `system()` 调用。

这一站从 `fork` 的调用链开始，跟着 `copy_process` 看它到底复制了什么、
又有哪些东西只是加个引用计数；然后看 `execve` 怎么在**同一个任务**上原地换掉代码和数据；
接着落到内存这一层：COW 为什么让 `fork` 变便宜，缺页又是怎么把物理页分给进程的；
最后回到调度器，看这个任务怎么被搬上 CPU、又怎么在核之间迁移。
