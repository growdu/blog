## 一、为什么选这一篇

试点要覆盖尽可能多的转换路径，同时必须**同时满足三道闸门**
（标题 ≤ 32 字、原始正文 ≤ 20000 字、渲染后 ≤ 20000 字符）。

| 候选 | 覆盖路径 | 标题 | 渲染后长度 | 结果 |
| --- | --- | --- | --- | --- |
| `db/postgresql/postgresql-logical-replication-add-guc` | mermaid×6 + 代码×28 + 表格×41 + 外链×1 | **41 字 ❌** | 92368 ❌ | 被两道闸门拦下 |

| `linux/cpu-affinity-top-guide` | mermaid×14 + 代码×35 + 表格×12 + 外链×3 | 27 ✅ | 57173 ❌ | 渲染后超限 |
| **`dpdk/vpp与dpdk的关系`** | mermaid×1 + 代码×7 + **图片×1** + 外链×2 | **11 ✅** | **13960 ✅** | **采用** |

第一轮选的 `add-guc` 是最有代表性的深潜文章，**被真实地卡住了**：
标题 41 字超过官方 32 字上限，渲染后 92368 字符是上限的 4.6 倍。
这正是试点要暴露的问题——它不是 bug，是**平台对技术长文的结构性限制**。

## 三、mermaid 两条路径都验过

### 成功路径

`dpdk/vpp与dpdk的关系` 的 1 个 mermaid 图渲染成 PNG：

```
weixin/out/mermaid/ff516a6e9b5328fd.png
```

PNG 按源码 sha1 命名，重跑不会重复渲染。

### 失败路径（更重要的那条）

用 `postgresql-logical-replication-add-guc`（6 个 mermaid）验证：

```text
mermaid 总数: 6
  62c897ebb8e9539c -> PNG
  5c282cf976180f85 -> PNG
  3b7cf74e79038f47 -> 失败: Error: Evaluation failed: Error: Parse error on line 9:
  73be5cd235f99ec7 -> PNG
  bc0c67f5eb15c546 -> PNG
  fd5b0dbd07c3d802 -> PNG
降级提示出现: True
```

失败的图在正文里变成：

```html
<p style="color:#888;font-size:13px">图表渲染失败，以下为图表源码：</p>
<pre style="background:#f6f8fa;padding:12px;overflow-x:auto;font-size:13px;line-height:1.5"><code style="font-family:Menlo, Consolas, monospace">flowchart TB
    A[PG 收到 ALTER SYSTEM SET ...] --&gt; B{context...
</code></pre>
```

**读者看到的是「图表渲染失败 + 图表源码」，而不是一段突然断掉的文字。**
错误信息取的是 stderr 开头（真正的报错），不是结尾那坨 JS 堆栈。

## 四、试点暴露并修掉的四个问题

试点不是走过场，它抓出了四个真问题：

| # | 问题 | 怎么发现的 | 怎么修的 |
| --- | --- | --- | --- |
| 1 | **占位符撞正文** | 全量渲染时发现 `life/blog-to-wechat` 的占位符下标越界——那篇文章的正文里就写着「占位符 `{{img:0}}`」 | 占位符改成 `{{img:N:随机token}}`，token 每次渲染随机生成，正文里的字面量撞不上 |
| 2 | **标题上限错了** | 拿官方文档核对时发现是 **32 字**不是 64（二手资料写的是编辑器 UI 的限制） | 改 `TITLE_LIMIT = 32`，补作者 16 字、正文 1 MB 两道检查 |
| 3 | **HTML 体积超限 45.6%** | 试点文章渲染出 92368 字符 | 样式串压缩 + Pygments 空白 span 解包，中位从 16276 降到 10970 |
| 4 | **封面可能为空** | 集成测试发现无图文章的 `thumb_media_id` 是空串 | 无图又没指定封面时**明确报错**，而不是提交空串让微信返回一个费解的错误码 |

另外补了官方新的封面裁剪格式 `cover_info.crop_percent_list`
（`ratio` 只支持 `2.35_1` / `1_1`，坐标是 0–1 百分比字符串）。

### 拿到凭据之后

```bash
export WX_APPID=你的AppID
export WX_APPSECRET=你的AppSecret
export WX_SOURCE_URL=https://growdu.cn

# 先建草稿（不发表）
cd weixin && python3 -m wechat.cli publish dpdk/vpp与dpdk的关系

# 确认草稿无误后，再加 --publish 提交发表
```
