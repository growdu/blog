## 三、mermaid 两条路径都验过

### 成功路径

## 四、试点暴露并修掉的问题

试点不是走过场，它抓出了一串真问题：

### 转换阶段

| # | 问题 | 怎么发现的 | 怎么修的 |
| --- | --- | --- | --- |
| 1 | **占位符撞正文** | 全量渲染时发现 `life/blog-to-wechat` 的占位符下标越界——那篇文章的正文里就写着「占位符 `{{img:0}}`」 | 占位符改成 `{{img:N:随机token}}`，token 每次渲染随机生成，正文里的字面量撞不上 |
| 2 | **标题上限错了** | 拿官方文档核对时发现是 **32 字**不是 64（二手资料写的是编辑器 UI 的限制） | 改 `TITLE_LIMIT = 32`，补作者 16 字、正文 1 MB 两道检查 |
| 3 | **HTML 体积超限 45.6%** | 试点文章渲染出 92368 字符 | 样式串压缩 + Pygments 空白 span 解包，中位从 16276 降到 10970 |
| 4 | **封面可能为空** | 集成测试发现无图文章的 `thumb_media_id` 是空串 | 无图又没指定封面时**明确报错**，而不是提交空串让微信返回一个费解的错误码 |
| 5 | **原始 HTML 绕过清洗** | `<iframe>` 在 mdparse 的白名单里，原样透传会把 `class` 属性带出去 | 透传前清洗：删 script/style/iframe、去 `class` 与事件属性 |
| 6 | **`<hr>` 没接上样式压缩** | `HR_STYLE` 常量定义了却没用，样式串多留着空格 | 改用 `HR_STYLE` |

### 发布阶段（只有打真实接口才会暴露）

| # | 问题 | 怎么发现的 | 怎么修的 |
| --- | --- | --- | --- |
| 7 | **凭据字段名不对** | `stable_token` 返回 `41004 appsecret missing`——文档写 `appsecret`，服务端实际只读 `secret` | 两个字段都发，覆盖两种实现 |
| 8 | **上传端点不认 Bearer header** | `media/uploadimg` 返回 `41001 access_token missing` | token 同时走 query 参数 |
| 9 | **外链图被静默删除** | **从微信侧拉回草稿核对**，发现本地 2 张图只剩 1 张——外链那个被整个删掉，不留痕迹 | 外链图也走占位符，发布时下载并转存；转存失败的降级为可见提示 |

第 9 个影响最大：全语料 **440 张外链图、50 篇文章**（8.9%）会静默缺图。
详见 [01-转换规则.md §四](01-转换规则.md)。

另外补了官方新的封面裁剪格式 `cover_info.crop_percent_list`
（`ratio` 只支持 `2.35_1` / `1_1`，坐标是 0–1 百分比字符串）。

## 五、待办：用自己的号实测接口

**这一步必须你来做**，本文给的是链路，不是你这个号的结论。

### Phase 0 检查清单

- [x] 登录 [微信公众平台](https://mp.weixin.qq.com/) → 左侧「设置与开发」→「基本配置」
- [x] 复制**开发者 ID (AppID)**
- [x] 点 AppSecret 旁边的「重置」（首次是「启用」），管理员扫码，当场复制
- [x] 在同一页下方填 **IP 白名单**：**要用报错里的 IP，别用 `curl ifconfig.me`**
      （本机走分流代理，两个出口不一样——`curl` 是 `43.166.8.75`，
      微信看到的是 `171.213.162.214`）
- [x] 凭据落地：写进 `weixin/secrets.json`（已被 gitignore）
- [x] 调一次 `stable_token`，确认能拿到 token
- [x] 调一次 `media/uploadimg` 传一张图，确认返回 mmbiz URL
- [x] 调一次 `material/add_material` 传封面，确认返回 `media_id`
- [x] 调一次 `draft/add` 建一篇测试草稿
- [x] 调一次 `freepublish/submit`，**errcode = 48001 api unauthorized**
      —— 该账号没有发表接口权限，草稿箱就是自动化能到的最远一步
- [x] 把结论回填到本节的「实测结论」表

### 实测结论（2026-11-11 填）

| 项目 | 预期 | 实测 |
| --- | --- | --- |
| `stable_token` | 返回 `access_token` | ✅ 通过。**凭据字段名必须用 `secret`**——只发 `appsecret` 会被回 `41004 appsecret missing`；两个都发才行 |
| `media/uploadimg` | 返回 mmbiz `url` | ✅ 通过。**token 必须走 query 参数** `?access_token=`，只放 `Authorization` header 会被回 `41001 access_token missing` |
| `material/add_material` | 返回 `media_id` | ✅ 通过（封面已上传成功） |
| `draft/add` | 返回 `media_id` | ✅ 通过。草稿 media_id `08QUqqaDBm_vIgdclIU8XFsB4RHp_C9Yhc7o0fzH-PXn-JCFyKlTX7uR1OBOa4OG` |
| `freepublish/submit` | 返回 `publish_id`，或 `48001` | ❌ **48001 api unauthorized** —— 账号没有发表接口权限，什么都没发出去 |
| `freepublish/get` | `publish_status` = 0 | ⏸️ 没走到这步（submit 就被拒了，没有 `publish_id` 可查） |

另外确认了 `stable_token` 的复用窗口真的生效：连调两次返回**同一个** token，
第二次的 `expires_in` 减 1 秒（7200 → 7199）。

### 幂等验证

同一篇文章跑两次 `publish`：

```text
第一次：已建草稿: dpdk/vpp与dpdk的关系
        media_id: 08QUqqaDBm_vIgdclIU8XFsB4RHp_C9Yhc7o0fzH-PXn-JCFyKlTX7uR1OBOa4OG
第二次：内容未变，复用已有草稿 08QUqqaDBm_vIgdclIU8XFsB4RHp_C9Yhc7o0fzH-PXn-JCFyKlTX7uR1OBOa4OG
```

正文指纹命中，**没有产生第二篇草稿**。三层幂等的第一层（内容层）验证通过。

### 拿到凭据之后

```bash
export WX_APPID=你的AppID
export WX_APPSECRET=你的AppSecret
export WX_SOURCE_URL=https://growdu.cn

# 先建草稿（不发表）

# 确认草稿无误后，再加 --publish 提交发表

```

或者把凭据写进 `weixin/secrets.json`（gitignore 已挡），之后直接跑命令即可，
不用每次 export。

**建议先只建草稿**，到公众号后台看一眼排版效果再发表。草稿箱就是天然的

## 七、试点结论

**转换链路：全通。** 564 篇文章零解析异常、零 `class` 属性、
零 `<script>`/`<iframe>`；mermaid 成功与失败两条路径都验过；
幂等、长度闸门、封面必需这些约束都有测试兜着。

**发布链路：到草稿箱为止，全通。**

| 环节 | 结果 |
| --- | --- |
| 凭据与 IP 白名单 | ✅ 通（IP 要用报错里的那个，见上文） |
| `stable_token` | ✅ 通 |
| `media/uploadimg`（正文图） | ✅ 通 |
| `material/add_material`（封面） | ✅ 通 |
| `draft/add`（建草稿） | ✅ 通，草稿已在草稿箱 |
| 幂等 | ✅ 跑两次复用同一个 `media_id`，没有第二篇草稿 |
| `freepublish/submit`（发表） | ❌ **48001 api unauthorized** |

**最终结论：这个账号的自动化边界是「自动生成 + 自动进草稿箱」。**
`freepublish/submit` 对该账号类型没有权限，调用会被直接拒绝——**没有任何内容
被发出去**，草稿原样躺在草稿箱里。

这正是设计时就预判的情况。48001 不是失败，是**答案**：它说明「最后点一下发表」
这一步必须留给人。但自动化并没有因此失去价值——

| 环节 | 手工 | 自动化后 |
| --- | --- | --- |
| Markdown → 公众号 HTML | 手工改格式、传图、调样式，**30~60 分钟** | **0 分钟** |
| 进草稿箱 | 同上 | 自动完成 |
| 发表 | 点一下 | 点一下（账号权限所限，绕不开） |

而且**草稿箱天然是审批闸门**：人看一眼再发，比全自动群发更稳妥。

### 失败时的行为也验证过了

```text
$ python3 -m wechat.cli publish dpdk/vpp与dpdk的关系 --publish
微信接口报错: /cgi-bin/freepublish/submit failed: [48001] api unauthorized
```

- 退出码 **3**（API 错误），不是 0——**没有静默成功**

- 草稿仍然在草稿箱里，内容完好
