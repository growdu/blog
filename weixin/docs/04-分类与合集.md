# 分类与合集：能自动到哪一步

> 核对日期：2026-11-11。结论基于**官方文档**与**真实账号实测**。
> 实现见 `weixin/wechat/collection.py`（领域逻辑）、`weixin/wechat/hexo.py`
> （复用站点构建的 slugize）。

---

## 一、结论先说

**「把文章归到某个分类 / 某个合集」这件事，公众号没有开放接口，做不了。**
但「分类信息」和「合集内容」这两样东西本身，是可以自动生成的。

| 想要的效果 | 能不能自动 | 怎么做的 |
| --- | --- | --- |
| 文章正文里显示它属于哪个分类 | ✅ 能 | front-matter 的 `categories` 渲染成一行分类标签 |
| 知道哪些文章属于同一个合集、按什么顺序 | ✅ 能 | 按分类（或自配置）生成合集计划 |
| 生成一个合集目录页（可进草稿箱） | ✅ 能 | `publish-collection` 生成合集导览文章 |
| 后台「添加已有内容」逐条勾选 | ✅ 半自动 | 生成勾选清单，人照着勾 |
| **把文章挂到平台上的合集对象上** | ❌ **不能** | 只能后台人工，或写依赖登录态的浏览器自动化 |

---

## 二、平台侧的四条硬事实

### 1. `draft/add` 没有 category / album 字段

官方字段表里 `article` 的全部字段是：`article_type` / `title` / `author` /
`digest` / `content` / `content_source_url` / `thumb_media_id` /
`need_open_comment` / `only_fans_can_comment` / `pic_crop_*` / `image_info` /
`cover_info` / `product_info`。

**没有分类字段，也没有合集字段。** 建草稿那一刻，文章不属于任何分类或合集。

### 2. `api.weixin.qq.com` 没有分类 / 合集接口

拿真实账号的 token 逐个探测候选路径，响应分三类：

```text
/cgi-bin/totally_bogus_endpoint_zzz  -> 空响应      （路径不存在）
/cgi-bin/material/album             -> 40066 invalid url
/cgi-bin/draft/album                 -> 40066 invalid url
/cgi-bin/appmsg/album                -> 空响应
/cgi-bin/album                       -> 空响应
/cgi-bin/appmsg/category             -> 空响应
/cgi-bin/category                    -> 空响应
/cgi-bin/material/category           -> 40066 invalid url
/cgi-bin/appmsg/category/list        -> 空响应
/cgi-bin/category/list               -> 空响应
```

`40066` 说明 `cgi-bin/material/`、`cgi-bin/draft/` 这两个前缀被路由器认得，
但 `album` / `category` 不是它们的合法叶子。其余的直接连路由都没有。

### 3. 合集管理页是后台网页，不是开放接口

合集在后台的位置是：

```text
https://mp.weixin.qq.com/cgi-bin/appmsgalbummgr?action=list&token=TOKEN&lang=zh_CN
```

这个路由确实存在（不带登录态访问会返回登录错误页），但它走的是**登录 Cookie +
每次会话动态的 token**，不是 `access_token`。要自动化就得驱动一个登录态的
浏览器，那条路见 §五。

### 4. 合集只能装「已发布」的文章

后台「添加已有内容」选的是**已发表**的图文，草稿加不进去。

> 「⚠️重点:只能添加已发布文章,草稿无法添加」——公众号后台操作文档与实操教程一致。

这一条把浏览器自动化也堵死了大半：**本号的 `freepublish/submit` 返回
`48001`**，文章永远停在草稿箱。就算写一套浏览器自动化去点合集，也没有
已发布的文章可以加进去。

### 附：公众号的「分类」到底是什么

现行后台里没有独立于合集的「图文分类」功能。内容归类就是合集；
另外还有一个**服务类目**（账号要卖什么业务），那是账号资质，**仅认证账号
可设置**，本号是个人主体未认证，改不了。

## 三、工具侧做了什么

### 分类标签（`--category-tag`）

front-matter 的 `categories` 渲染成正文顶部的一行：

```html
<p style="font-size:13px;color:#888;margin:0 0 18px">分类 ·
<span style="color:#3d7ea6;font-weight:700">数据库深入</span> ·
<span style="color:#3d7ea6;font-weight:700">数据库</span></p>
```

- 位置可选：`top`（默认）/ `bottom` / `none`
- 是**纯文本**不是链接：微信会把正文里的站外锚点剥掉，做成链接只会得到一个
  点不动的样子
- 参与草稿的幂等键——标签一改就重建草稿，否则改动永远到不了读者那里

### 合集计划（`collections`）

合集默认**按分类自动生成**：文章数 ≥ 2 的分类就是一个合集。实测语料：

```text
561 篇文章 → 42 个分类 → 29 个合集
（13 个分类只有 1 篇，那是标签不是系列）
最大的一类：数据库，154 篇
```

文章按**发布时间**排序，不按文件路径——合集是连着读的东西。

想手工指定，写 `weixin/collections.json`（可选，文件不存在就用自动模式；
格式见 `weixin/collections.example.json`）：

```json
{
  "collections": [
    {
      "title": "PostgreSQL 源码修炼之路",
      "description": "从编译到执行器，逐篇读源码。",
      "categories": ["PostgreSQL 源码修炼之路"],
      "slugs": ["db/postgresql/learning-path/00-index"],
      "exclude": ["db/postgresql/learning-path/99-appendix"],
      "order": "asc"
    }
  ]
}
```

| 键 | 作用 |
| --- | --- |
| `title` | 合集名（必填，重复会报错） |
| `description` | 合集简介 |
| `categories` | 按 front-matter 分类选文章 |
| `slugs` | 额外按 slug 补进来的文章（不存在的 slug 会报错，不会静默跳过） |
| `exclude` | 排除的文章 |
| `order` | `asc`（默认，按时间）或 `desc` |

### 合集导览文章（`publish-collection`）

一个可以进草稿箱的目录页：合集简介 + 逐篇的标题、日期、摘要、原文链接。

「阅读原文」指向站点上真实的分类归档页——那是公众号正文里**唯一能点开的
链接**（正文里的站外锚点会被剥掉，所以每篇文章的链接以纯文本列出）。

```bash
cd weixin && python3 -m wechat.cli publish-collection "PostgreSQL 源码修炼之路"
```

封面取合集里第一篇有图的文章的首图；没有图就用 `--cover` / `WX_COVER` 指定，
否则明确报错，不提交空 `thumb_media_id`。

### 后台勾选清单（`collections --write`）

```bash
cd weixin && python3 -m wechat.cli collections "PostgreSQL 源码修炼之路" --write
```

产出两个文件：

```text
weixin/out/collections/PostgreSQL 源码修炼之路/article.html   ← 导览文章正文
weixin/out/collections/PostgreSQL 源码修炼之路/plan.md        ← 后台勾选清单
```

`plan.md` 长这样：

```markdown
# 合集「PostgreSQL 源码修炼之路」勾选清单

文章数：14

## 勾选顺序

1. [ ] 01 编译调试与代码布局
   - 日期：2026-08-18
   - 原文：https://growdu.cn/2026/08/18/db/postgresql/learning-path/01-build-and-codebase/
2. [ ] 02 进程架构与生命周期
   ...

## 后台操作

1. 登录 mp.weixin.qq.com → 内容与互动 → 合集 → 新建合集
2. 名称填「PostgreSQL 源码修炼之路」，简介与封面按需填写
3. 点「添加已有内容」，按上面的顺序逐条勾选（只列得出已发表的文章）
4. 排序与上面的顺序保持一致，开启「连续阅读」
5. 保存，合集会自动显示在公众号主页
```

**这是「合集」这件事上唯一真正需要人工的一步**，而且它是机械劳动：照着
清单勾，不用自己回忆哪些文章属于这个系列。

## 四、分类归档路径：为什么不能直接拼

站点的分类页挂在祖先目录下，段名用 `slugize` 而不是 `%20`：

```text
/categories/数据库深入/数据库/PostgreSQL-源码修炼之路/
/categories/数据库深入/数据库/
/categories/数据库深入/
/categories/数据库/
/categories/Go-Web/
```

「数据库」同时出现在两个深度（它既是根分类，又是「数据库深入」的子分类）。
本工具取**最浅的那条**，因为那是列出文章最多的那个页面，也是站点自己的
分类索引指向的那个。

段名的 slugize 规则**不重新实现**，直接复用 `tools/sync-hexo.py` 里的那个
函数（`weixin/wechat/hexo.py` 用 `importlib` 加载它）——那个文件里已经写明
它是对 `hexo-util` 的复刻，复制一份迟早会漂移。

算出来的路径与 `public/categories/index.html` 里的真实链接逐条核对过。

## 五、为什么不做浏览器自动化

技术上做得到：复用后台登录态，调 `appmsgalbummgr` 那套内部路由，把文章
批量塞进合集，社区里确实有这类方案。

**但本号用不上，也不该用**：

1. **文章发不出去**——合集只收已发布文章，本号 `freepublish/submit` 是 48001，
   草稿箱里的东西永远进不了合集。自动化一个填不满的合集没有意义。
2. **依赖登录态**——要用户扫码登录、要维护 Cookie，接口一变就断。
3. **有风控**——高频操作后台内部接口有被判定为异常的风险，账号比几篇草稿值钱。

所以这一层留给人工，而工具把人工要做的事（挑哪些、什么顺序、叫什么名字、
简介怎么写）全部准备好。

---

## 六、边界

- **平台上的合集对象仍然是人工建立的**，工具只负责内容与清单。
- **合集上限**以平台为准（后台会拦），工具不预判。
- **自动合集是按分类切的**，分类即合集是多数博客的自然形态；如果要按
  「主题」而不是「分类」组织，写 `collections.json` 手工指定。
- **分类标签是正文内容**，会占字符预算（每篇文章约 40–80 字符）。
  `audit` 复算的体积统计会把它们算进去。
- **分类标签不改变文章的分类归属**，那件事只有后台能做（或者干脆不做）。
