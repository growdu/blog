# 转换规则：Markdown → 公众号 HTML

> 本文是 `weixin/wechat/render.py` 的规格说明。每一条规则都对应代码里的一个分支，
> 表格里的「实现」列指向具体的函数。
>
> 设计背景见 [10-设计.md](10-设计.md)，接口细节见 [02-接口与发布.md](02-接口与发布.md)。

## 一、公众号的渲染环境

三条硬约束决定了全部规则：

| 约束 | 后果 |
| --- | --- |
| 只认写在元素上的 `style=""` | `class`、`id`、`<style>` 块、外部 CSS 一律无效；本工具产出的 HTML 里 **0 个 `class` 属性** |
| 没有 JavaScript | `mermaid` 必须预渲染成 PNG；代码高亮必须服务端完成 |
| 正文按 **HTML 源码字符数** 计费，上限 2 万字符 + 1 MB | 每个元素的样式都要精打细算，见 §六 |

第三条是最容易被低估的：**HTML 标签和样式都算进 2 万字符**。一篇文章的
Markdown 是 3000 字，渲染成带 inline style 的 HTML 后可能变成 11000 字符。

## 二、块级构造映射

| Markdown | 输出 | 样式 |
| --- | --- | --- |
| `# H1` | 进 `title` 字段，正文里不出现 | —— |
| `## H2` | `<h2>` | `font-size:17px;font-weight:700;margin:24px 0 12px;border-left:4px solid #3d7ea6;padding-left:10px` |
| `### H3` | `<h3>` | `font-size:16px;font-weight:700;margin:20px 0 10px` |
| `#### H4` | `<h4>` | `font-size:15px;font-weight:700;margin:18px 0 10px` |
| 段落 | `<p>` | `font-size:15px;line-height:1.75;margin:0 0 12px` |
| ```` ```lang ```` 代码块 | `<pre><code>` | `pre` 用 `background:#f6f8fa;padding:12px;overflow-x:auto;font-size:13px;line-height:1.5`，`code` 用 `font-family:Menlo, Consolas, monospace` |
| ```` ```mermaid ```` | `<img>`（渲染成功）或 `<pre>` + 提示（失败） | 图片 `max-width:100%` |
| 表格 | `<section style="overflow-x:auto">` 包 `<table>` | `table`：`border-collapse:collapse;width:100%;font-size:13px`；单元格：`border:1px solid #dfe2e5;padding:7px 9px` |
| 无序列表 | `<ul>` | `padding-left:22px` |
| 有序列表 | `<ol>` | 同上 |
| 任务列表 | `<li>` 前加 `☑ ` / `☐ ` | `color:#3d7ea6` / `color:#999` |
| 引用块 | `<section>` | `border-left:3px solid #d0d0d0;padding-left:12px;color:#666` |
| 分割线 | `<hr>` | `border:none;border-top:1px solid #e5e5e5;margin:24px 0` |
| 图片 | `<img>` | 见 §四 |

### 行内构造

| Markdown | 输出 |
| --- | --- |
| `**粗体**` | `<strong>` |
| `*斜体*` | `<em>` |
| `` `代码` `` | `<code style="background:#f6f8fa;padding:2px 5px;border-radius:3px">` |
| `[文字](链接)` | 见 §三 |
| `![说明](图片)` | 见 §四 |

### 解析顺序

行内解析用**一次正则扫描**，不是多轮替换。这个顺序很重要：

```
!图片  →  [链接]  →  `行内代码`  →  **粗体**  →  ~~删除线~~  →  *斜体*
```

- 行内代码在粗体/斜体**之前**匹配，所以 `` `**x**` `` 不会被当成粗体。
- 图片在链接之前，避免 `![alt](x)` 被当成 `[alt](x)` 再留一个感叹号。

### 代码块优先

块级解析先切围栏代码块，再处理其他构造。所以代码块里的 `#`、`|`、`-`
不会被误判成标题、表格、列表。

### 嵌套列表

列表项的续行按**标记宽度**计算内容缩进：`- ` 是 2 列，`1. ` 是 3 列。
续行缩进大于标记宽度时归入当前项，于是嵌套列表成为父项的子块。

## 三、链接降级

| 链接类型 | 处理 | 理由 |
| --- | --- | --- |
| 站外 `http(s)://` | 去掉 `<a>` 只留文字，全部收集到文末「参考链接」区块 | 公众号正文内的 H5 外链会被拦截，点进去是「非微信环境」提示页 |
| 站内 `/2026/11/09/...` | 同样只留文字 | 站内链接在微信里点开也是外部浏览器，体验同样差 |
| 「阅读原文」`content_source_url` | 保留完整 URL | 这是公众号里唯一能放外链的地方 |

文末「参考链接」区块的形式：

```html
<section style="margin:24px 0 0;padding-top:12px;border-top:1px solid #e5e5e5;">
<p style="color:#888;font-size:13px">参考链接</p>
<ul style="padding-left:22px;"><li>标题文字：https://example.com/a</li></ul>
</section>
```

> 全站有 1208 处站外链接，全部这样处理。

## 四、图片：两段式

图片 URL 只有上传之后才知道，所以 HTML 里先放**占位符**：

```
{{img:0:3f7a91c2}}     ← 第一个本地图片
{{img:1:3f7a91c2}}     ← 第二个
{{ext:0:3f7a91c2}}     ← 第一张外链图片
```

- `token` 是每次渲染随机生成的 8 位十六进制。**必须随机**：本仓库自己的
  设计文档里就写着「占位符 `{{img:0}}`」，如果用固定语法，那段正文会在
  替换时被误伤。随机 token 让正文里的字面量无法被预测到。
- 同一张图被引用多次只占一个序号，只上传一次。
- 上传后按序号把占位符换成 mmbiz URL（`RenderResult.substitute()`）。

### 外链图片：必须转存，否则会被静默删除

**微信的规则是「正文图片 URL 必须来自 `media/uploadimg`」**。外链图片
（`https://img2018.cnblogs.com/...` 这类）留在正文里，微信会把整个 `<img>`
元素**删掉，不留任何痕迹**——读者看到的是一段突然断掉的正文，还以为是原文
就这样。

所以外链图片也走占位符，只是用独立的编号空间 `{{ext:N:token}}`：

| 阶段 | 外链图怎么处理 |
| --- | --- |
| 渲染 | 记入 `RenderResult.external_images`，HTML 里放 `{{ext:N:token}}` |
| 发布 | 下载 → 压缩到 ≤ 1 MB → 上传 `media/uploadimg` → 替换成 mmbiz URL |
| 下载失败 | 替换成可见提示：「（此处的原图未能转存，点击「阅读原文」查看完整图文）」 |

**失败绝不能变成静默缺图**——读者至少要知道这里原本有张图。

> 全语料有 **440 张外链图、涉及 50 篇文章**（8.9%）。有的文章 32 张全是
> 外链图，不转存的话发到公众号基本没法看。

### 尺寸与体积

| 处理 | 规则 | 原因 |
| --- | --- | --- |
| 宽度 > 1080 | 等比缩到 1080 | 公众号正文宽度就是 1080 逻辑像素 |
| 体积 > 1 MB | 先降 PNG 量化，再退 JPEG（质量 90→20） | `media/uploadimg` 的硬上限 |
| 仍超限 | 逐步缩图（每次 0.75 倍）直到达标 | 纯噪声这类病态图任何质量都压不下 |

正文图只接受 JPG/PNG；封面走 `material/add_material`，返回永久素材
`media_id`，作为 `thumb_media_id`。

> 封面按四级链取用：① `--cover` / `WX_COVER` 指定的图 → ② 文章首张
> **本地图** → ③ 首张**外链图**（本来就要转存，顺手复用） → ④ 仓库自带的
> 默认封面 `assets/default-cover.png`。
>
> 为什么要有兜底：444 篇合格文章里 **380 篇一张图都没有**（另有 39 篇只有外链
> 图）。没有兜底的话这 419 篇永远进不了草稿箱——微信不接受空
> `thumb_media_id`。默认封面是通用图，后台可以自己换。
>
> 但显式指定的封面路径不存在时**仍然硬报错**，不静默降级到默认封面。

## 五、mermaid：失败必须显式降级

站点用客户端 JS 渲染 mermaid，公众号没有 JS，所以每个 mermaid 围栏都要
预渲染成 PNG。

| 情况 | 处理 |
| --- | --- |
| 渲染成功 | `<img src="{{img:N:token}}" alt="mermaid diagram">` |
| **渲染失败** | `<p>图表渲染失败，以下为图表源码：</p>` + `<pre>` 源码块 |

**失败绝不能静默丢图**。全站 1280 个 mermaid 图块里有约 8% 在 mermaid 10.9
下解析失败（见 `tools/mermaid-audit.md`），公众号里一个空 div 是最糟的结果：
读者看到一段文字突然断了，没有任何线索。

渲染用 `mermaid-cli@10.9.1`（对齐站点用的 mermaid 10.9.8），通过
`PUPPETEER_EXECUTABLE_PATH` 复用系统 Chrome，不额外下载 chromium。
PNG 按源码 sha1 缓存，重跑不重复渲染。

## 六、体积预算

`content` 字段按 **HTML 源码字符数** 计费，上限 2 万。实测各部分占比
（564 篇全语料，22.2M 字符）：

| 部分 | 占比 | 说明 |
| --- | --- | --- |
| `<span>`（代码高亮） | 24.4% | 每个 token 一个 span |
| `<p>` | 10.0% | 38267 个段落 |
| `<code>`（行内代码） | 9.9% | 34273 处 |
| `<td>` | 7.8% | 32370 个单元格 |
| `<pre>` | 3.2% | 7745 个代码块 |

### 三条压缩手段

1. **样式串去掉可选空格**：`font-size: 15px; line-height: 1.75` →
   `font-size:15px;line-height:1.75`。一篇文章有上千个 style 属性，
   每个省十几个字符。
2. **解包只含空白的 span**：Pygments 把代码里的空格也当成一个 token，
   包成 `<span style="color:#BBB"> </span>`。把标签去掉、**文字留下**，
   一个可见字符都不少。
3. **高亮可降级**：超限时改用不带高亮的纯文本代码块。
   高亮是锦上添花，内容完整才是底线。

### 效果

| 版本 | 正文中位长度 | 超 2 万字符 |
| --- | --- | --- |
| 初始实现 | 16276 | 257/564（45.6%） |
| 压缩样式后 | 13672 | 237/564（42.0%） |
| **最终（样式压缩 + 高亮压缩）** | **10970** | **215/564（38.1%）** |
| 最终 + 关闭高亮 | 8632 | 191/564（33.9%） |

**38% 的文章仍然超限**，而且这部分省不下来：HTML 标签本身就占大头，
表格单元格尤其费字符（一个 20 行 5 列的表格，光单元格样式就 4400 字符）。

这类文章现在由工具**自动拆成多篇**：超限时按标题边界切成若干篇，每篇
各自成稿，编号并互相衔接。规则见 [06-超长文章拆分](06-超长文章拆分.md)。

> 拆不动的情况只有一种：某一整块（一个段落、一张表格、一段代码）自己就
> 超了 2 万字符，且块内没有可切的边界。这时文章被**跳过**并记下原因，
> 不截断——被截断的深度文章比没有文章更糟。

## 七、代码高亮

用 Pygments 的 `HtmlFormatter(nowrap=True, noclasses=True)`：

- `nowrap=True` → 只输出 inline style，**不带 class**，正好满足公众号
- 未知语言 → 退回转义纯文本，不抛异常（语料里有 54 种语言标签）
- `text` / `plain` / 空语言 → 不高亮

```html
<pre style="background:#f6f8fa;padding:12px;overflow-x:auto;font-size:13px;line-height:1.5"><code style="font-family:Menlo, Consolas, monospace">SELECT<span style="color:#000080"> 1</span>;</code></pre>
```

## 八、原始 HTML

语料里几乎不用原始 HTML（564 篇里 0 块），所以不做完整实现：
遇到 `<div>`、`<table>` 等块级标签时按原样透传——**但透传前会清洗**：

| 处理 | 规则 | 原因 |
| --- | --- | --- |
| `<script>` / `<style>` / `<iframe>` | **整个元素连内容一起删掉** | 微信会拦掉（错误码 `45166`） |
| `class="..."` 属性 | 删掉 | 公众号只认 inline style，`class` 是死代码 |
| `on*="..."` 事件属性 | 删掉 | 公众号没有 JavaScript |

清洗在 `render.py` 的 `sanitize_html()` 里，是**兜底**而不是主要路径——
渲染器自己产出的标签本来就不带 `class`。

> 一个单独的 `<script>` 不算原始 HTML 块（mdparse 的白名单里没有它），
> 会走段落路径被转义成 `&lt;script&gt;`，读者看到的是源码文本。

### 为什么不能用裸子串 `'class=' in html`

那样写会误报 **6 篇**，而且是**假阳性**——命中的是正文里被转义的示例代码：

| 文章 | 命中的实际内容 |
| --- | --- |
| `blog/同名文章-html-与-md-版本管理` | `&lt;div class="mermaid"&gt;`（讲 hexo 迁移的示例代码） |
| `blog/视频嵌入指南` | `&lt;div class="movie-item"&gt;`（讲视频嵌入的示例代码） |
| `life/blog-to-wechat` | `&lt;div class="mermaid"&gt;`（讲公众号发布的示例代码） |
| `edit/pandoc自定义过滤器` | `&quot;&lt;div class=&#39;custom-class&#39;&gt;`（pandoc 过滤器示例） |
| `database/postgresql-wal-record-types` | `pg_class=1259`（catalog oid 的注释） |
| `blog/同步到公众号方案` | `<code>` 元素里的 `class=` 文本（讲「只支持内联样式」的那句） |

这些是**文本内容**（`<` 已转义成 `&lt;`），不是任何元素的属性——微信的过滤器按
DOM 解析，不会把它们当属性。校验必须按**真实标签**来查，而不是按裸子串。

`wechat/wechat/audit.py` 的 `check_html()` 就是按真实标签解析的：

```python
TAG_RE = re.compile(r'<([a-zA-Z][a-zA-Z0-9-]*)((?:\s+[^<>]*?)?)\s*/?>')
```

`&lt;div ...&gt;` 不以 `<` 开头，所以不会被当成标签；真正的 `<div class="x">`
会被匹配到，从而报出 `class@div`。
