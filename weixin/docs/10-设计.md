## 一、目标与非目标

### 目标

1. 把 `source/_posts/` 下的博客文章，转换成**公众号可直接发布**的 HTML（inline style、无 JS 依赖、图片走 mmbiz）。
2. 自动推到**公众号草稿箱**（`draft/add`）。
3. 全流程**幂等**：同一篇文章不会发两遍。
4. 每一步的失败都**显式暴露**，不静默降级成「看起来成功」。

### 非目标（本期明确不做）

| 不做 | 原因 |
| --- | --- |
| 视频号 | 微信没有面向普通账号的公开发布 API。见前作 §5。 |
| CI 自动发布 | 微信后台要求调用机出口 IP 加白名单，GitHub 托管 runner 的 IP 是动态的。本期**本地执行**。 |
| 自动拆分超长文章 | 拆分会破坏深潜文章的结构。超限文章跳过并记录。 |
| 改写 `tools/sync-hexo.py` | 转换器**复用**它，不改它。避免影响现有站点构建。 |
| 站点侧 mermaid 改动 | 本期只给公众号渲染 PNG，站点继续用客户端 JS。 |

## 二、真实语料盘点（决定了设计）

转换器的输入是 `source/_posts/`（`tools/sync-hexo.py` 的产物）。全量统计 564 篇：

| 指标 | 数值 | 对设计的影响 |
| --- | --- | --- |
| 文章总数 | 564 篇 `.md`（另有 3 篇 `.html`，本期不处理） | — |
| 代码围栏 | 7689 = **mermaid 1280** + 普通代码 6409 | **mermaid 是最大成本项**，必须预渲染 |
| 表格 | 1676 张 / 13512 行 | 窄屏溢出处理 |
| 图片 | 568（77 篇有图） | mmbiz URL + 1MB 限制 |
| 站外链接 | 1208 | 降级到文末「参考链接」 |
| 列表 | ul 12502 / ol 4332 | 嵌套层级处理 |
| 引用块 | 2265 | 左边框样式 |
| 标题 | h2 3590 / h3 5980 / h4 1006 | 三级样式 |
| 行内代码 / 粗体 / 斜体 | 26542 / 16157 / 4832 | 行内解析优先级 |
| 分割线 | 2065 | `<hr>` |
| 任务列表 | 264 | 复选框字符 |
| 原始 HTML 块 | 0 | 不实现 |
| **标题 > 64 字**（编辑器上限；API 实测到 85） | **18 篇需裁剪**（原 105 篇按 32 字口径统计） | 按内容裁剪，原标题进摘要 |
| 原始正文 > 20000 字 | 73 篇 (12.9%) | 跳过并记录（预检） |
| **渲染后 > 20000 字符** | **215 篇 (38.1%)** | **权威闸门**，跳过并记录 |
| 字数中位 / 均值 | 3204 / — | 63.3% 的文章最终可发布 |

**关键结论**：最终可发布率 63.3%，难点集中在含 mermaid 的 148 篇文章上。设计资源应向 mermaid 倾斜。

### 2.1 mermaid 解析失败率 8.2%

`tools/mermaid-audit.md` 记录：在 **`docs/` 全域**的 1239 个图块中 102 个解析失败（58 个页面受影响）。
（`source/_posts/` 口径下 mermaid 围栏共 1280 个——两个口径统计范围不同，审计清单覆盖得更全。）
根因是 mermaid v10 的类名与 `:::` 之间不允许空格、标签里的括号需要加引号等。

**设计含义**：预渲染必然遇到失败。**失败的处理方式必须是显式降级（源码块 + 标注），不能是静默丢图**——
公众号里一个空 div 是最糟的结果：读者看到一段文字突然断了，没有任何线索。

## 三、输入架构

### 3.1 三个候选

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A（采纳）** | 吃 `source/_posts/` | 图片已改写、链接已改写、H1 已剥、front-matter 已重建 | 需先跑 sync（3m13s）；`source/` 是 gitignore 产物 |
| B | 吃 `docs/**` 自己解析 | 可单篇直转 | 重复实现图片改写/链接改写/permalink = 两份真相 |
| C | 吃 `public/**/index.html` | 所见即所得 | 需本地全量 `npm install`（当前 `node_modules` 缺失）；mermaid 源码要从转义 div 反解 |

### 3.2 方案 A 的实现要点

**用 `importlib` 把 `tools/sync-hexo.py` 加载成模块**，直接复用它的函数：

| 复用 | 用途 |
| --- | --- |
| `git_date()` | 文章 permalink 的日期部分 |
| `rewrite_images()` | 图片相对路径 → `images/...` |
| `rewrite_links()` | 相对链接 → 绝对 permalink |
| `resolve_post_categories()` | 分类 |

**转换器因此一行图片改写逻辑都不写**，permalink 也用同一套规则算出来，站点与公众号不会分叉。

```python
# weixin/wechat/posts.py
import importlib.util
from pathlib import Path

_REPO_ROOT = Path(__file__).resolve().parents[2]
_SYNC_PATH = _REPO_ROOT / 'tools' / 'sync-hexo.py'

def load_sync_module():
    """Load tools/sync-hexo.py as a module.

    The filename contains a hyphen, so it cannot be imported by name.
    Loading it by path is the only way to reuse git_date() /
    rewrite_images() / rewrite_links() without copying them, which would
    create a second source of truth for permalinks and image paths.
    """
    spec = importlib.util.spec_from_file_location('blog_sync_hexo', _SYNC_PATH)
    module = importlib.util.module_from_spec(spec)
    spec.loader.exec_module(module)
    return module
```

### 3.3 sync 是前置步骤，不是转换器的一部分

`sync-hexo.py` 要 3m13s（`git_date()` 对 564 个文件 × 22 个分支跑 `git log`），
**转换器不自己跑 sync**。`scan` 命令检测 `source/_posts/` 不存在时，提示先执行：

```bash
python3 tools/sync-hexo.py
```

## 五、数据流

```
docs/**/index.md
  │  tools/sync-hexo.py（唯一内容入口，纯标准库，3m13s）
  ▼
source/_posts/**/*.md          ← 转换器输入
  │
  │ ① discover   posts.py       解析 front-matter、算 permalink、校验硬限制
  ▼                              → 候选清单 + 不合格原因
  │ ② parse      mdparse.py     Markdown → 块级 AST
  ▼
  │ ③ assets     mermaid.py     mermaid 围栏 → PNG（按源码哈希缓存）
  │              assets.py      本地图片 → 去重清单 + 压缩到 ≤1MB
  ▼
  │ ④ render     render.py      AST → 公众号 HTML（inline style + {{img:N:token}} 占位符）
  ▼
  │ ⑤ upload     publish.py     正文图 → mmbiz URL；封面 → thumb_media_id
  ▼                              → 占位符替换为真实 URL
  │ ⑥ draft      publish.py     draft/add → media_id
  ▼
  │ ⑦ publish    publish.py     freepublish/submit → publish_id → 轮询 publish_status
  ▼
out/report.md                  每篇的结果清单 + 不合格文章清单
```

**⑤ 必须在 ④ 之后**：图片 URL 只有上传后才知道，而 HTML 结构依赖 URL 的宽高。
用占位符 `{{img:N:token}}` 解决——顺带保证同一张图引用多次只上传一次。
`token` 是每次渲染随机生成的 8 位十六进制：**必须随机**，否则讲占位符机制的文章
（比如本仓库自己的设计文档）正文里的 `{{img:0}}` 会在替换时被误伤。

## 六、模块规格

### 6.1 `posts.py` — 发现与硬限制校验

```python
@dataclass(frozen=True)
class Post:
    path: Path          # source/_posts 下的路径
    slug: str           # 相对 source/_posts 的路径（去掉 .md），用作 state 键
    title: str
    digest: str         # ≤120 字
    permalink: str      # /2026/11/09/database/xxx/
    body: str           # 去掉 front-matter 的正文
    categories: tuple[str, ...]

@dataclass(frozen=True)
class Eligibility:
    ok: bool
    reasons: tuple[str, ...]   # 不合格原因（人类可读）
```

硬限制：

| 限制 | 阈值 | 不合格时的处理 |
| --- | --- | --- |
| 正文字数 | ≤ 20000（去空白计） | 跳过，记录原因 |
| **标题长度** | **≤ 64 字符**（编辑器上限；`draft/add` 实测接受到 85，86 报 `45003`） | **按内容裁剪**，原标题进摘要 |
| 作者 | ≤ 16 字符 | 跳过，记录原因 |
| 摘要 | ≤ 120 字 | 从首个有效段落截取（必定能取到） |

> 官方限制的是 **HTML 源码字符数**（标签和样式都算进去），所以正文的**权威闸门**
> 是渲染后的 `content` 长度 ≤ 20000 字符 + < 1 MB，不是原始 markdown 字数。
> 原始字数只是必要条件——全语料有 142 篇过了原始预检、渲染后仍然超限。

**正文不做静默截断**：截断出来的正文对读者没有意义，反而掩盖了问题。
**标题是例外**——它按内容裁剪（不是砍到一半），保留主标题，
并把**原标题完整放进摘要**（`原标题｜摘要`，≤120 字），信息不丢。
详见 [12-标题裁剪与封面.md](12-标题裁剪与封面.md)。

### 6.1b `titles.py` — 标题裁剪

```python
TITLE_LIMIT = 64      # 编辑器上限；API 实测接受到 85
SUFFIX_RESERVE = 3    # 给拆分编号「（一）」留位

def flatten(title: str) -> str: ...        # markdown 链接拍平成文字
def shorten(title: str, limit: int) -> str: ...  # 在分隔符处切，不是硬砍
def topic(title: str, limit: int = 18) -> str: ...  # 第一个分隔符之前的主题
def effective_title(title: str, limit: int = TITLE_LIMIT) -> str: ...
```

切点阶梯：强分隔符（`：` `:` `——` `—` `---` ` - `）→ 弱分隔符（空格、`｜`、`·` 等，
取**最长的放得下的**头部）→ 硬切加 `…`。切出来的头部至少 6 个字符，
括号要配平，`https://` 里的冒号不算切点。

### 6.1c `cover.py` — 封面卡

用 Pillow 画 900×383（2.35:1）的封面卡：按 slug 的 sha1 取品牌蓝紫色相画竖向渐变，
左侧色条 + 分类 + 主题（≤2 行）+ `growdu.cn`。

- 缓存：`out/covers/{sha1(slug|title|category|text)[:12]}.png`
- 字体：按候选列表找中文字体（macOS 的 Hiragino Sans GB / Songti / STHeiti，
  Linux 的 Noto CJK / 文泉驿）
- **画不出来就回落默认封面**，绝不因为画不出封面卡而丢掉一篇文章

取用链：指定封面 → 首张本地图 → 首张外链图 → **封面卡** → 默认封面。

### 6.2 `mdparse.py` — Markdown → 块级 AST

纯函数。输入 Markdown 字符串，输出 `list[Block]`。

```python
@dataclass
class Heading:  level: int; text: str; inlines: list[Inline]
@dataclass
class Paragraph: inlines: list[Inline]
@dataclass
class Code:      lang: str; code: str
@dataclass
class Table:     header: list[list[Inline]]; rows: list[list[list[Inline]]]; align: list[str]
@dataclass
class ListBlock: ordered: bool; items: list[list[Block]]
@dataclass
class Quote:     blocks: list[Block]
@dataclass
class Hr:        pass
```

行内元素：`Text` / `Bold` / `Italic` / `InlineCode` / `Link` / `Image`。

实现要点：

- **围栏代码块优先**：先按 ```` ``` ```` 切块，避免代码块里的 `#`、`|`、`-` 被误解析。
- **表格识别**：当前行以 `|` 开头且下一行是 `|---|` 分隔行。
- **列表**：支持嵌套（按缩进层级），任务列表 `- [ ]` / `- [x]`。
- **行内解析顺序**：先提取行内代码（内容不再解析），再处理链接/图片，再处理粗体/斜体。
  避免 `` `**x**` `` 被当成粗体。

### 6.3 `render.py` — AST → 公众号 HTML

纯函数。给定 `Block` 列表与一个资源解析器，输出公众号可用的 HTML。

```python
class AssetResolver(Protocol):
    def image_url(self, path: str) -> str: ...          # 本地路径 → mmbiz URL
    def mermaid_url(self, index: int) -> str | None: ... # 渲染成功的 PNG → mmbiz URL
```

**关键约束**：公众号**只认 inline style**，`class` 无效，外部 CSS/JS 一律不生效。
所有样式必须写进 `style="..."`。

样式基线：

| 元素 | 样式要点 |
| --- | --- |
| `<p>` | `font-size:15px; line-height:1.75; margin:0 0 16px` |
| `<h2>` | `font-size:18px; font-weight:700; border-left:4px solid #3d7ea6; padding-left:10px` |
| `<h3>` | `font-size:16px; font-weight:700` |
| `<h4>` | `font-size:15px; font-weight:700` |
| `<pre>` | `background:#f6f8fa; padding:12px; overflow-x:auto; font-size:13px; line-height:1.5` |
| `<code>`（行内） | `background:#f6f8fa; padding:2px 5px; border-radius:3px` |
| 表格 | 外层 `<section style="overflow-x:auto">`，`<table style="border-collapse:collapse; width:100%">` |
| 引用 | `<section style="border-left:3px solid #ccc; padding-left:12px; color:#666">` |

**链接降级**：站外链接去掉 `<a>` 只保留文字，并收集进文末「参考链接」区块。
站内链接（`/2026/...` 开头）保留为纯文字（公众号正文内点站内链接体验同样差）。

### 6.4 `highlight.py` — 代码高亮

用 Pygments 的 `HtmlFormatter(nowrap=True)`：输出**只有 inline style，没有 class**，
正好满足公众号的约束。

```python
def highlight_code(code: str, lang: str) -> str:
    """Return HTML with inline-styled tokens and no class attributes.

    nowrap=True drops the class attributes that WeChat ignores anyway.
    Unknown languages fall back to plain escaped text rather than failing.
    """
```

未知语言 → 退回纯文本（不抛异常）。`text` / `plain` 视为无语言。

### 6.5 `mermaid.py` — mermaid → PNG

```python
@dataclass
class MermaidAsset:
    index: int
    source: str
    png: Path | None    # None = 渲染失败
    error: str | None
```

执行：

```bash
PUPPETEER_EXECUTABLE_PATH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  npx -y @mermaid-js/mermaid-cli@10.9.1 -i in.mmd -o out.png -w 1080 -b white
```

- **用系统 Chrome，不下载 chromium**（`PUPPETEER_EXECUTABLE_PATH`）
- 宽度 1080（公众号正文宽度）、白底
- **按 `sha256(源码)` 缓存**到 `out/mermaid/`，重跑不重复渲染
- 失败 → `png=None`，由 `render.py` 降级为源码块 + 标注，并记入报告
- 固定到 10.9.x（站点用 mermaid 10.9.8），避免与站点渲染结果不一致

### 6.6 `assets.py` — 图片资产

```python
def compress_for_wechat(path: Path, limit_bytes: int = 1024*1024) -> bytes:
    """Return JPEG/PNG bytes within limit_bytes.

    Tries PNG quantisation first, then falls back to JPEG quality steps.
    """
```

- Pillow 9.4 已装
- 上限 1MB（微信 `media/uploadimg` 的限制）
- 宽度 > 1080 的图等比缩小（公众号正文宽度就是 1080 逻辑像素）
- 按路径去重：同一张图引用多次只上传一次

### 6.7 `publish.py` — 微信 API 客户端

**只做网络**，用标准库 `urllib`（不引入 requests）。multipart 手写（约 30 行）。

| 接口 | 方法 | 关键点 |
| --- | --- | --- |
| `stable_token` | POST | **不用** `token`（老接口每次调用作废前一个，并发会互相踩） |
| `media/uploadimg` | POST multipart | 字段名 `media`，返回 `url`（mmbiz） |
| `material/add_material?type=image` | POST multipart | 字段名 `media`，返回 `media_id`（封面） |
| `draft/add` | POST JSON | `articles[].title/author/digest/content/content_source_url/thumb_media_id` |
| `freepublish/submit` | POST JSON | body `{media_id}`，返回 `publish_id`（**异步**） |
| `freepublish/get` | POST JSON | body `{publish_id}`，返回 `publish_status` + `article_id` |

**所有 `errcode != 0` 必须抛异常，不吞掉。** 流水线里的每一个「成功」都必须是显式确认过的成功。

### 6.8 `state.py` — 幂等状态机

```python
@dataclass
class PublishState:
    fingerprint: str | None   # sha256(正文)
    media_id: str | None      # draft/add 返回
    publish_id: str | None    # freepublish/submit 返回
    publish_status: int | None
```

三层幂等键：

| 层 | 键 | 判定 |
| --- | --- | --- |
| 内容 | `fingerprint` | 指纹未变且已有 `media_id` → 不重建草稿，只查状态 |
| 草稿 | `media_id` | 已有 → 不重复 `draft/add` |
| 发布 | `publish_id` | 已有 → 不重复 `submit`，只轮询 |

状态文件：`weixin/out/state.json`（本地执行，gitignore）。

### 6.9 `cli.py` — 命令行入口

```bash
python3 -m wechat.cli scan                       # 盘点，输出合格/不合格清单
python3 -m wechat.cli convert <slug> --dry-run   # 只产出 HTML 到 out/，不调接口
python3 -m wechat.cli publish <slug>             # 完整链路到草稿箱
python3 -m wechat.cli publish <slug> --publish   # 额外提交发表

```

**默认只到草稿箱**，`--publish` 才调 `freepublish/submit`。理由：2025-07 起部分账号类型
发表接口返回 `48001`（未实测），且草稿箱天然是人工审批点。

## 十、风险与兜底

| 风险 | 概率 | 影响 | 兜底 |
| --- | --- | --- | --- |
| 发表接口 `48001` | 高 | 只能到草稿箱 | 不算失败，草稿箱流程价值仍有 90% |
| IP 白名单挡住调用 | 中 | 全部接口失败 | 本地执行；把本机出口 IP 加进后台 |
| token 互相顶掉 | 低 | 随机 `40001` | 用 `stable_token`；单进程串行 |
| 重复发布 | 中 | 账号刷屏 | 三层幂等键 |
| 接口返回码变了 | 中 | 链路静默失败 | `errcode != 0` 一律抛异常 |
| mermaid 渲染失败 | **高（8.2%）** | 图静默消失 | 降级为源码块 + 标注 + 记入报告 |
| 正文图 > 1MB | 中 | 上传报错 | Pillow 自动压缩 |
| 文章被删 / 改名 | 低 | state 键失效 | state 以 slug 为键，缺失即重建 |
| 公司物料混入 | 中 | 信任受损 | 个人号物料独立；本工具只处理 `source/_posts/` |

**通用原则：流水线的每一个「成功」，都必须是显式确认过的成功，不能是「没报错就算成功」。**
在发布场景里，**发重了比发慢了糟糕得多**。
