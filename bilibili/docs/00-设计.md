# B站 adapter 设计规格

> **状态**：2026-11-13 实施中（`manual` 档已可用，已跑通一次真实投稿）。
>
> **上游契约**：[../../publish/spec/07-视频发布契约.md](../../publish/spec/07-视频发布契约.md) §6.3、§6.5。
> 规格是上位权威，本文档只讲 B站 这一侧怎么落地。

## 两档

| 档 | 行为 | outbox `status` |
| --- | --- | --- |
| `manual` | 出包，人工上传 | `packaged` |
| `api_publish` | 调 arcopen 上传 + 投稿，轮询审核态 | `submitted` → `published` |

切换**只改 `publish/capabilities/bilibili.toml` 里的 `automation` 一行**——
这就是能力模型存在的全部意义。

快照里的 `automation` 字段**从那份 TOML 读**，不写死。写死的话，
改完 TOML 快照还在说旧档位，那是静默的假话。

## 依赖方向

规格 §3.3 定的规矩：`channels/` 与 `bilibili/` 平级独立，
adapter **只 import `pyv.epmeta` 与 `pyv.preflight`**。

所以：

- 字幕用 `bilibili/subtitle.py` 里的 `SubtitleEventLike`（Protocol）描述事件，
  **不 import `pyv.timeline`**；
- storyboard 由调用方（CLI）用 `subtitle.events_from_storyboard()` 读原始 JSON，
  出包函数收的是**字幕事件列表**，不是 storyboard 对象；
- 「字幕从哪来」这条规则因此写了两遍（`pyv.timeline` 一份、这里一份），
  `publish/tests/test_video_publish_contracts.py` 拿真实 storyboard 对照两边，
  规则一改就会红。

## 限额

| 项 | 限额 | 出处 |
| --- | --- | --- |
| 标题 | < 80 字 | B站《视频稿件提交》 |
| 简介 | < 250 字 | 同上 |
| 标签 | 逗号分隔后总长 < 200 字，单项 < 20 字 | 同上 |
| 封面 | jpeg/png ≤ 5 MB，建议 ≥ 1146×717，最低 ≥ 960×600 | B站《封面上传》 |

限额数字**只写在 `publish/capabilities/bilibili.toml`** 里，adapter 不自己抄一份。
超限一律**报错，不截断**——悄悄裁一刀比报错更坏：人以为填了完整的简介。

标签是**英文逗号分隔的一串**（不是 `#` 井号），拼接时不加井号。

## 封面

从成片抽一帧，**按比例居中裁切再缩放**，不拉伸变形。

- 源 16:9（1.78）比目标 1146:717（1.60）**宽** → 切左右两边；
  源比目标窄时切上下。切错方向会切掉画面主体。
- 直接 `resize` 到目标尺寸会把画面横向压扁——封面变形在信息流里一眼能看出来。

## 字幕

从 `aiv/storyboard_<期号>.json` 的字幕事件生成 `.srt`。
时间轴是本机产物，所以字幕文件也是本地产物，**不入库**。

规则：有 `subtitles` 用 `subtitles`，没有就退化成按场景出字幕。

## 分区

`tid` 写在 `aiv/publish/<期号>.json` 里，**不硬编码在代码里**。

B站正在灰测 `tid_v2` 分区体系，老 `tid` 与新号不是同一套，
提交前用 `GET /arcopen/fn/archive/type/list` 查证并回填。

**实测（2026-11-13，EP06「row-lock」）**：投稿页跑的是「人选分区」灰测体系，
下拉是 31 个扁平项（`human_type2` id 1001–1031），
规格里写的二级分区「计算机技术」（`tid = 231`）**不可选**。
下拉里选「科技数码」（id 1012）投稿后，B站落库成「科技 → 软件应用」，
稿件接口回读的 **`tid = 230`**（父分区 188 科技）。
所以元数据里的 `tid` 写 **230**（落库那个老号），不是人选分区号 1012。
清单：`GET /x/vupre/web/archive/human/type2/list`；
回读：`GET /x/vupre/web/archive/view?bvid=…`。

公开接口 `GET /x/web-interface/view?bvid=…` 会**同时**回读
`tid = 230` 与 `tid_v2 = 2103`——两套号并存，老的仍在 `tid` 字段。
`add-by-utoken` 收的是 `tid`，所以元数据里写 **230**。

## 人工发布实测（2026-11-13，EP06「row-lock」）

第一期真的在 B站 上发出去的实录，**投稿页现状**与**事后查证的接口**：

| 环节 | 现状 |
| --- | --- |
| 视频 | 投稿页上传完显示「上传完成」即可提交 |
| 封面 | 两个上传位：**16:9 个人空间封面** + **4:3 首页推荐封面**，各传一张 |
| 分区 | 「人选分区」下拉，31 项扁平列表 |
| 创作声明 | 下拉选「含AI生成内容」；稿件回读 `creation_statement.content` |
| 内容授权声明 | 选「内容为自制：未经作者允许，禁止转载」；回读 `copyright=1` + `no_reprint=1` |
| 字幕 | 投稿页「更多设置 → 视频元素 → 字幕设置 → 上传字幕」传 `.srt` |
| 提交 | 底部「立即投稿」→ 页面出「稿件投递成功」→ 转码完成 → 审核 → 开放浏览 |

**字幕传完就已经是「已发布」，不用再去字幕管理提交。**
字幕管理页（`/platform/upload-manager/audience-zimu`）显示
「中文 → 已发布」，且该轨的 `subtitle_id` 与投稿时上传的那条一致。

> **一个会把人带沟里的假阴性**：用**未登录**的请求调
> `GET /x/player/v2?bvid=…&cid=…`，返回里是
> `subtitle.subtitles: []` 且 `need_login_subtitle: true`——
> 看着像「字幕没挂上」。其实只是**没登录，字幕列表不返回**。
> 带 cookie（登录态）再调一次，`subtitles` 里就有
> `{lan: "zh", lan_doc: "中文"}` 了。
> 判断字幕有没有生效，看**登录态**的接口，或看字幕管理页那行「已发布」。

查证稿件实际字段（都要登录态）：

- `GET /x/vupre/web/archive/view?bvid=…` —— 稿件全量字段
  （`tid` / `tp_info` / `human_type2` / `creation_statement` / `copyright` / `no_reprint` /
  `cover` / `cover43` / `subtitle` / `state`）；
- `GET /x/player/v2?bvid=…&cid=…` —— 字幕轨与 `need_login_subtitle`。

`state`：`0` = 开放浏览（`state_desc` 写「开放浏览」），`-1` = 复核中。

## 幂等三件事（规格 §7.1）

| 东西 | 绑什么 | 成片没变时 |
| --- | --- | --- |
| 抽帧（封面）、软链（成片） | 成片 sha256 | **复用** |
| 标题、简介、标签、清单 | 当前元数据 | **每次重写** |
| 发布状态 | 成片 sha256 | **保留** |

第二条最容易被漏：成片没变 ≠ 文案没变（改了标题再重跑很常见）。
只认成片 sha256 的幂等会让包里的标题停在旧版本，而命令还报「成功」。

## 状态快照

`publish/outbox/<EP>__bilibili.json`，字段与视频号**完全一致**（规格 §7.5），
只有 `platform` 不同。`package_dir` 记**相对路径**——快照要入库，
绝对路径换台机器就对不上。内容没变就不重写文件（`updated_at` 不动），
否则每次重跑都把工作树弄脏，而内容一个字都没变。

## 什么入库、什么不入库

| 入库 | 不入库 |
| --- | --- |
| 能力声明 `publish/capabilities/bilibili.toml` | 发布包 `bilibili/out/` |
| 发布元数据 `aiv/publish/<EP>.json` | 成片 `aiv/out/*.mp4` |
| 状态快照 `publish/outbox/` | 封面、字幕、时间轴 |
| 本文档与契约 | 凭据 `secrets.json` |
