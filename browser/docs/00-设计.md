# 发布执行器（Playwright + Chromium）

## 一、这是什么

**用真实浏览器把「人在平台后台上手动做的事」做成脚本。**

首批目标平台是微信视频号——它**没有面向普通创作者的公开发布 API**
（[发布契约](../../publish/spec/07-视频发布契约.md) §6.1.1）。所以「把视频传上去」
这件事原本只能人肉做。本包把它变成一条命令。

```
aiv/publish/<EP>.json ──┐
                        ├─→ browser/ ─→ 真实 Chromium ─→ 平台页面
channels/out/<EP>/    ──┘
```

## 二、它不是什么

**它不是 adapter。** adapter（`channels/`、`bilibili/`）负责「这个平台的限额怎么裁、
包怎么出」，是平台知识；两个 adapter **互不引用**（契约 §3.3）。而「点哪个按钮、
往哪个框里填字」是另一种平台知识——**浏览器交互知识**——它不产生包，只消费包。

塞进 adapter 会让「出包」这件事必须装浏览器才能跑。所以分成三层：

| 层 | 干什么 | 位置 |
| --- | --- | --- |
| 生产者 | 成片合不合格、这期叫什么 | `aiv/` |
| adapter | 平台限额怎么裁、包怎么出 | `channels/`、`bilibili/` |
| **执行器** | **打开浏览器，把包里的东西填进去** | **`browser/`** |
| 状态快照 | 对外公开的事实 | `publish/outbox/` |

**它不 import 任何 adapter。** 回填快照靠调外部命令
（`python3 -m channels.cli mark published …`），不靠 import——
这样执行器可以给任意平台用，平台不会被焊死在代码里。

## 三、为什么是 Playwright

| | 内置浏览器（手工点） | Playwright + Chromium |
| --- | --- | --- |
| 换台机器 | 装不了、也复制不过去 | `pip install playwright` 就行 |
| 可重复 | 每次都要人点一遍 | 同一份发布包，结果一样 |
| 登录态 | 手工，存不存看心情 | 持久化 profile，扫码一次长期有效 |
| 出错时 | 靠眼睛 | 报错带选择器、带失败截图 |

Linux 上一键装：

```bash
sudo bash browser/scripts/bootstrap_linux.sh
```

装完自检：

```bash
cd browser && python3 -m browser.cli doctor
```

**Chromium 的版本必须跟 playwright 的版本对上**，所以浏览器本体不单独指定版本——
让 `playwright install` 跟着 playwright 走。

## 四、目录

```
browser/
├── browser/
│   ├── session.py      # 持久化 profile 的会话（登录态活过一次）
│   ├── driver.py       # 页面动作原语（填字 / 上传 / 点击 / 截图）
│   ├── plan.py         # 从发布包读出「要填什么」
│   ├── probe.py        # 探测页面结构
│   ├── doctor.py       # 环境自检
│   ├── cli.py          # 命令行入口
│   └── flows/
│       └── channels.py # 视频号流程
├── selectors/
│   └── channels.json   # 选择器表（数据，不是代码）
├── docs/00-设计.md      # 本文档
├── tests/
├── scripts/bootstrap_linux.sh
├── requirements.txt
└── .gitignore          # profile/（登录态）与 out/（产物）都不入库
```

## 五、登录态放哪

`browser/profile/`——一个浏览器用户目录，跟人自己用浏览器登录一次是同一个心智模型。

- **永不入库**（`.gitignore` 挡着）。里面是 cookie 与 localStorage，
  等同于凭据（契约 §7.5）。
- 换机器时**重新扫一次码**比拷贝目录靠谱——token 有有效期，
  拷一份过期的 profile 只会得到一个「看起来登录了、其实没登录」的鬼状态。
- 想换个位置：`export BROWSER_PROFILE_DIR=~/.config/blog-browser`。

**扫码这一步必须由人完成。** 微信扫码是拿手机对着屏幕，自动化代替不了。

## 六、怎么用

### 1. 探测：先看页面长什么样

```bash
cd browser && python3 -m browser.cli probe
```

它会打开视频号助手（弹出真实窗口），等你扫码；你按回车后，
它把页面上所有能填、能点、能传文件的元素连同**建议的 CSS 选择器**打出来，
并存一份原始数据到 `browser/out/probe/structure.json`。

**这一步不需要任何选择器**——所以它能用来「先探页面，再填选择器」。
选择器表一开始是空的，照着探出来的结构填 `browser/selectors/channels.json` 即可。

### 2. 填表：不发表

```bash
cd browser && python3 -m browser.cli prepare row-lock
```

上传成片 → 等平台处理 → 填标题简介话题 → 选封面 → 勾原创声明，
然后**停在发表之前**，留下：

- `browser/out/row-lock/prepare.png` —— 页面截图
- `browser/out/row-lock/prepare.json` —— 填了什么

### 3. 发表

```bash
cd browser && python3 -m browser.cli submit row-lock
```

`submit` 会**重新走一遍填表**（浏览器一关表单就没了），
在点「发表」前把截图路径打出来并等一次确认。确认后发表、取回链接、
回填 `publish/outbox/`。

## 七、选择器表怎么维护

**选择器是数据，不是代码。** 页面改版时改 `browser/selectors/channels.json`，
不用改 Python。

- 每个键的值是**候选列表**，按顺序试，挨个不中就换下一个。
- `text_layout` 决定文案怎么填：
  - `separate` —— 有独立的标题框与描述框，分别填；
  - `combined` —— 只有一个描述框，标题是它的第一行。

  **哪一种是探测出来的，不是猜的。**

- 某一项还没探出来时留空数组。流程会明确报「选择器表里没有 X，
  先跑 probe」，**不会静默跳过那一步**。

## 八、失败了怎么办

**不静默成功、不静默截断。** 每一处失败都会说清：想要什么、试了哪些选择器、
等了多久、失败时页面在哪个 URL，并附一张失败瞬间的截图。

```
ERROR 页面操作失败：
等了 20000 ms，元素没等到「visible」状态
试过的选择器：#desc | textarea[placeholder="填写描述"]
失败时页面 URL：https://channels.weixin.qq.com/platform/post/create
失败时截图：/Users/.../browser/out/row-lock/fail-01-wait.png
```

## 九、测试

```bash
python3 -m pytest browser/tests -q
```

- **不依赖网络**：所有涉及浏览器的测试跑在本地假页面上
  （`browser/tests/fixtures/post.html`），用 `file://` 打开。
- 没装 playwright 的机器会**跳过**浏览器相关的测试，而不是把套件拖红。
- 覆盖：计划读取、字数限制、选择器表、动作原语、完整填表流程、
  发表取链接、探测、自检、命令行。

## 十、实测记录：视频号（2026-11-13，账号 growdu）

用真实账号探过视频号助手，得到的都是**页面上真读回来的**，不是文档抄的。

| 项 | 实测结论 |
| --- | --- |
| 投稿页 URL | `https://channels.weixin.qq.com/platform/post/create` |
| 表单结构 | 上传区在**主文档**，表单在 **iframe** `micro/content/post/create` —— 定位必须跨 frame |
| 短标题 | **独立输入框**（`填写短标题有机会获得更多流量`），与描述分开 → `text_layout = "separate"` |
| 描述 | `div[contenteditable][data-placeholder="添加描述"]` |
| 话题 | 在描述框里打 `#XXX`，编辑器**自动变成真话题**（`<span class="hl topic">`），不用点「#话题」按钮去搜索 |
| 短标题禁符 | **中文逗号「，」被拒**，原话：「标题包含特殊字符，符号仅支持书名号、引号、冒号、加号、问号、百分号、摄氏度，逗号可用空格代替」。改成空格即通过 |
| 声明原创 | **两层勾选**：勾主框会弹「原创权益」弹窗，要再勾一次同意、再点弹窗里的「声明原创」，主框才算勾上 |
| 封面 | 平台自动生成**两张**：个人主页卡片 **3:4**、分享卡片 **4:3**，各带「编辑」按钮，可上传自定义图。**不是 16:9 也不是 9:16** —— 传 16:9 会被居中裁掉左右两边 |
| 视频大小 | 页面写明：8 小时以内、不超过 **20GB**、建议 1080p 及以上、H.264/H.265、码率 10Mbps 以内、60fps 以内；音频 AAC、128kbps 及以上、48kHz 及以上 |

**这些规则都写进了代码**，不是写在注释里：

- 短标题的禁符在 `flows/channels.py` 的 `TITLE_REJECTED`，
  `check_limits()` 会在填之前拦住并说清怎么改；
- 「声明原创」的两层勾选在 `declare_original()` 里，
  最后**读 DOM 的 `checked` 核对**——视觉上勾着不等于状态落下了；
- `prepare()` 结束时会把页面上的内容**读回来核对**（`verify_filled()`）：
  短标题一字不差、简介没被截断、4 个话题都成了真话题 chip，才算填好了。

## 十一、已知边界

1. **视频号的字数上限没实测。** 标题 22 字是公开口径的保守值
   （契约 §十四 第 1 条待验证）。`flows/channels.py` 里标着「未实测」。
2. **封面比例已实测，但我们的封面素材还没改。** 平台要 3:4 与 4:3，
   而 `channels` adapter 现在出的是 16:9（1080×608）与 9:16（1080×1920）——
   直接传会被裁。**当前发布用的是平台自动生成的封面**，
   adapter 的封面规格待改（契约 §十四 第 2 条）。
3. **平台改版会让选择器过期。** 表现是 `prepare` 报「元素没等到」——
   重新跑一次 `probe`，照着新结构改 JSON。
4. **纯服务器上扫码登录需要 xvfb。** `bootstrap_linux.sh` 会装，
   跑的时候用 `xvfb-run -a python3 -m browser.cli …` 包一层。
5. **发布链接不一定能自动取到。** 取不到时 `submit` 会打印出回填命令，
   人复制一下链接再跑那条命令——**不会拿一个编出来的链接回填快照**。
