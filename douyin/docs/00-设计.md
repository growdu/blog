# 抖音 adapter 设计规格

> **状态**：2026-11-14 实施中。
>
> **上游契约**：[../../publish/spec/07-视频发布契约.md](../../publish/spec/07-视频发布契约.md) §6.6。

## 一句话

抖音**有**公开发布接口，但开放平台的内容发布能力（scope `video.create.bind`）
要求**党政机关或事业单位**主体——本账号是个人主体，批不下来。
所以这一档是 `manual`：自动出包，人工点发布。

## 产物结构

| 文件 | 内容 |
| --- | --- |
| `video.mp4` | 成片的软链（成片是本机产物，不复制） |
| `cover.jpg` | 抽一帧，**与成片同比例** |
| `title.txt` | 标题（首屏钩子，≤ 55 字） |
| `description.txt` | 正文（≤ 500 字） |
| `topics.txt` | `#话题 #话题` |
| `text.txt` | **平台真正要的那一个字段**：标题、正文、话题拼好的整段 |
| `publish.md` | 照着做就能发完的清单 |
| `meta.json` | 机器可读的状态 |

**封面比例不猜。** 抖音的封面规格没有公开文档，我们也没投过一条，
所以不猜比例：先给与成片同比例的图（抖音这一档发的是竖版 9:16，
封面也就是 1080×1920），投完一条看后台实际怎么裁再定。
猜一个比例做版式，猜错了就是白做。

## 出包前的三道闸

| 闸 | 谁出 finding | 管什么 |
| --- | --- | --- |
| 文案层 | `pyv.epmeta.check_meta` | 各段自己的上限（title / description / 话题） |
| 技术层 | `pyv.preflight.check_video` | 成片的技术门槛（编码、时长、体积、音频） |
| **抖音专属** | `douyin.contract` | **拼装后的 `text` 总长** 与 **站外引流** |

后两条不能并进前两层：

- `pyv.epmeta` 逐字段查，查不出「三段加起来超了 1000 字」；
- `pyv.epmeta` 不知道抖音禁站外引流——那是平台规则，不是元数据格式。

| 级别 | 行为 |
| --- | --- |
| `error` | **报错并停止**，不出包 |
| `warning` | **告警但继续**，并写进 `publish.md` 的「预检告警」一节 |

超限一律报错，**不静默截断**——让作者改元数据，而不是悄悄裁一刀。

## 站外引流这道闸拦什么

拦的是**形态**，不是白名单：

| 类别 | 例子 |
| --- | --- |
| 网址 | `https://growdu.cn/…`、`www.growdu.cn` |
| 域名 | `example.com`、`foo.xyz`（按形态收；文件后缀与产品词除外） |
| 微信 | 「加微信」「加V」「vx」「wx」「VX: abc」 |
| QQ | 「QQ」「qq123456」「扣扣」 |
| 电话 | `13800138000`、`138-0013-8000`、「手机号」「电话」「联系」 |

**「私信」不在表里**——抖音私信是站内功能，不是站外引流，不能误伤。

**规则按形态写，就得每种形态都拦得住。** 大小写算同一种（`VX:` 与 `vx:`
都是微信号）；手机号不能靠 `\b` 断（中文与数字之间没有词边界，
「手机号13800138000」在 `\b1[3-9]\d{9}\b` 下根本匹配不上）。

误伤也是错：正文里写文件名（`README.md`）、写模型名（`gpt-4o.mini`）、
写库名（`wxPython`）都不该被拦。所以域名那条放行**肯定不是域名的后缀**
（文件后缀 + 产品词），微信那条前后用字母数字挡一下。

真遇到了误伤就把那句话挪到别处去，**不要把闸拆了**：闸拆了之后，
下一次就没人拦了。

## 回填：必须有发布包

`mark published` **要求发布包存在**。没有包就没有「发出去的是哪一版」——
回填出来的「已发布」指向一个空的 `package_dir`，下一个人照着快照去找，
什么都找不到，而「已发布」已经记上去了。所以缺包时**报错退出**：
不写状态、不写快照。

**失败的回填不许留下状态。** 顺序是「先把会失败的事做完，都成了才落状态」：
先读元数据、再写发布包，最后才写状态与快照。反过来（先存状态再做事），
中途失败就留下一条假的「已发布」。

## 幂等

内容层键是**成片的 sha256**：成片重出（换了旁白、修关键帧）就重新出包。
文案每次都按当前元数据重写——成片没变 ≠ 文案没变。

**复用不是「目录还在就算数」。** 复用之前要复查包里每一件东西都还在
（软链可能悬空——成片被挪走或删了；别的文件也可能被人删）。少任何一件
就重出——否则命令报「成功」，而那个包根本发不出去。

**封面每次重抽。** 复用时封面也得重抽一次：包里那张是上一次抽的，
而元数据里的取帧点（`cover_at`）可能改了。封面与 `meta.json` 记的取帧点
对不上，人按清单选封面就会选错那一帧。

## 通知措辞

「发布包已生成，**待你上传**」与「已发布」是两句话，不许混。

这一档**没有 `drafted`**：抖音创作者后台的草稿能力没核实过，
设一个没验证过的档位，等于给「其实存不下来」发一张通行证。

## 依赖

`pyv` 住在 `aiv/pipeline/` 下面，没有装成 wheel，所以 `douyin/__init__.py`
把它挂上 `sys.path`。adapter 只**读** `pyv.epmeta` 与 `pyv.preflight`，
不 import 契约层或 `weixin/` 的任何包，也不修改 aiv 侧的文件。

与 `channels/`、`bilibili/` 平级、互不引用。
