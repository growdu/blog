## 实测记录

### R1 · 2026-11-12 · 头条号后台找不到「开放平台」入口

**现象**：登录头条号后台（`mp.toutiao.com`）→ 设置，**找不到「开放平台」入口**。
（用户找的是「开发平台」——**不是**同一个名字，别再按错名字找了。）

**判定**：**不是路径走错，是账号条件没到。** 三条依据：

1. **入口的正式名字是「开放平台」，不是「开发平台」。**
   第三方对接文档（php 中文网《讯飞绘文怎么发布到头条号》）写的路径是
   「头条号创作者中心 → 设置 → 开放平台 → **API 权限管理**」。
2. **开通条件写明**：同源文档写「仅企业认证号、媒体认证号、个人认证号（**粉丝 ≥ 1000**）
   可开通此权限；普通未认证账号即使完成 OAuth2 登录，也会在发布时返回『权限不足』」。
3. **头条号后台的权益入口遵循同一套「达标才渲染」规则**：
   第三方攻略对「图文赞赏」的描述是「系统仅在满足条件后自动释放该权益入口，
   未达标账号不会显示该开通入口」。「开放平台」入口属于同一类。

> **处置**：这一项**从阶段一移到阶段二**（它依赖认证，本就不该在阶段一）。
> `publish/capabilities/toutiao.toml` 的 `automation` 维持 `manual`——
> 本来就是现在的取值，**轨道 A 不受任何影响**。
>
> 阶段一剩下要做的是**账号状态自查**与**手工发一篇测试文章**，
> 后者完全不依赖 API 权限，今天就能做。

#### 排查顺序（按这个顺序查，不要跳着试）

| # | 检查项 | 怎么查 | 不达标的后果 |
| --- | --- | --- | --- |
| 1 | 名字对不对 | 找「**开放平台**」，不是「开发平台」 | — |
| 2 | 账号认证状态 | App「我的」头像旁的认证标识；或后台「设置 → 账号详情 → 帐号自证」 | 未认证 → **入口不渲染** |
| 3 | 账号主体类型 | 必须是个人 / 企业 / 媒体；**不能是国家机构 / 新闻媒体 / 其他组织** | 类型受限 → 职业认证也申请不了 |
| 4 | 粉丝数 | 今日头条 + 西瓜视频合计；个人认证号需 ≥ 1000 | 不足 → **入口不渲染** |
| 5 | 入口不在「设置」顶层 | 逐个点「设置 → 账号详情」「设置 → 功能设置」「左侧 → 工具」 | 路径在二级菜单里 |
| 6 | 登录的是不是同一个号 | 后台登录手机号 vs App 登录账号 | 账号不对 → 什么都看不到 |

> **第 2、4 项是主嫌。** 头条号后台 2022 年改版公告里，「设置」页的功能位置调整只列了三处
> （安全中心 → 帐号详情、帐号自证 → 帐号详情、自定义菜单 → 功能设置），**没有提「开放平台」**——
> 因为它是条件渲染的，未达标账号连菜单项都没有。

#### A · 标题

| 探针 | 结果 |
| --- | --- |
| 上限 | **30 字**（占位符原文「2～30个字」） |
| 输入框拦不拦 | **不拦**：逐字敲到 40 字进得去，计数器显示「40 / 30」并变红 |
| 平台自己的校验接口 | `title_check` → `{"valid":1}`；`word_check` → `{"hit_words":[]}` —— **说标题合法** |
| 保存时会不会被拒 | **没验成**：那时保存**一律**返回 7050（账号侧，见 §R2.F），标题超限这条被掩盖了 |

> **别信校验接口**：同一时刻校验说合法、保存说失败。限额的依据只能是
> 占位符原文 + 保存结果，而保存结果这次被账号侧挡住了。
> 所以 `title_chars = 30` 的依据是**占位符原文**（平台自己写的上限），
> 不是「保存被拒」。

#### B · 摘要

**编辑器里没有摘要输入框**：把设置面板整段 DOM 扫一遍，「摘要」出现 **0** 次
（同一份扫描里「封面」「声明」「定时」都命中了）。保存请求参数
`search_creation_info.abstract` 传的是**空串**。

→ **摘要由平台自动生成**，我们产出的摘要正文没有地方放。
`digest_chars` 约束的是**我们自己产出摘要的长度**（写进包里的 `title.txt` 第二行），
不是平台的。

#### C · 正文排版

真剪贴板 + `Meta+V`，`changed: true`。

| 源里是什么 | 编辑器里变成什么 |
| --- | --- |
| `<h2>` × 10 | **`<h1>` × 10**（平台改写，class `pgc-h-forward-slash`），h2 归零 |

| `【图1】` / `【图2】` / `【图3】` | 全保留 |
| 纯文本 URL `1.http://mysql.taobao.org/...` | **原样保留，不自动变成链接**（正文里 4 个 `<a>` 全是图片节点自带的「编辑/搜图」浮层，href 为空） |
| 图位 | 插图后**图位前多出一个空段落** |

#### C2 · 平台字数口径（编辑器底部「共 N 字」不是字符数）

公式：**非 ASCII 字符逐字 + ASCII 字符每两个折一个**（`⌈ASCII/2⌉`），空白不计。

探针（追加一段再撤销，读计数增量）：

| 追加 | 平台字数增量 | 原始字符增量 |
| --- | --- | --- |
| `测试` | +2 | +2 |
| `abcd` | +2 | +4 |
| `12345678` | +4 | +8 |
| ` `（一个空格） | +0 | +0 |
| `。` | +1 | +1 |

整篇复核：1318 个 ASCII + 1207 个非 ASCII → 1207 + ⌈1318/2⌉ = **1866**，
与编辑器显示的「共 1866 字」逐字对上。

> 这套口径已落地成 `toutiao/toutiao/wordcount.py` 的 `platform_word_count()`；
> 出包清单的字数行打的是平台口径：`字数：2717 字符（平台计 1866 字）`。

#### C3 · 正文长度与单段长度

| 探针 | 结果 |
| --- | --- |
| 正文**总量**上限 | **没有**：20000 字整段粘进去，计数器照实显示 20000，不截断 |
| 单段阈值（纯汉字） | **200 平台字不告警，201 开始报「1 处段落字数过多」**（二分定位） |
| 平台判单段用哪套口径 | **平台字**，不是字符数 |

> `body_chars = 3000` 因此**降级**为「我们的编辑预算」（运营手册 §2.2「头条号图文 3K」），
> 不是平台上限。平台侧真正会拦人的是**单段**，阈值落在
> `limits.paragraph_words = 200`（**平台字**）。
> 一段 216 个原始字符的中英混排段落，平台计 178 字——按字符数判就会误报。

#### D · 正文图片

- 面板原文：「支持jpg、jpeg、png等多种格式，单张图片最大支持 **20MB**」
- **webp 实测能传**（面板没列它）：`POST /mp/agw/spice/image?upload_source=20020002`
  返回 `{"code":0,"message":"success"}`；回读字节流开头是 `RIFF….WEBP` ——
  **平台原样存、原样吐，不转码**
- 流程是三步：**上传 → 面板暂存 → 点「确定」才插入编辑器**（按 Escape 会丢弃暂存）
- 正文图张数上限：**未测**（这轮只放了 2 张）

#### E · 封面

- 面板原文：「封面图尺寸建议大于 `672*462`，不可小于 `452*352`」
- 封面框 152×118（**1.288:1**）；平台把正文首图自动裁成 1620×1261（1.285:1）——
  与 452:352 吻合
- → **封面是横图**。旧假设的「3:4 竖图」不会被平台拒绝，只会被**再裁一次上下两半**，
  宽图被切成一条窄竖片，图里的字就没人看得清了
- webp 也能当封面（`upload_source=20020003&need_cover_url=1`）：我们那份 1143×1524 竖图
  被裁成 **1143×890**（上下各丢 317 像素）
- radio 有「**无封面**」→ **封面非必填**
- **首图自动成为封面**（自动生成 `tplv-tt-cover-v2` 1620×1261）

#### F · 发表：**草稿保存失败 ≠ 发不出去**

**这一节原来写错了。** 原来写的是「账号侧 7050，发不出去」——
2026-11-13 14:05 和 14:11 **两篇文章都发成功了**。

错在把**同一个接口的两个分支**当成一件事：

```text
POST https://mp.toutiao.com/mp/agw/article/publish?source=mp&type=article&aid=1231&...
├─ save=0（存草稿）→ {"code":7050,"data":{"pgc_id":"0"},"err_no":7050,"message":"保存失败"}
└─ save=1（发表）  → 成功，返回 pgc_id
```

编辑器底部一直跳的那个「保存失败」是 **`save=0` 那个分支**。
它被平台拒绝，但**发表走 `save=1`，不通同一个闸**。

> ⚠️ **「保存失败」不等于「发不出去」。** 脚本报红、看着像整篇废了，
> 实际上只是自动存草稿那条路被堵。真正的发表是**两步**：
> 点「**预览并发布**」→ 弹出「**预览确认发布**」面板 → 点面板里的「**确认发布**」。

**save=0 为什么被拒**：逐项单变量实测，**全都还是 7050**：

| 改了什么 | 结果 |
| --- | --- |
| 删掉正文里的外链 URL | 7050 |
| 取消「头条首发」 | 7050 |
| 取消「发布得更多收益」 | 7050 |
| **最小草稿**（纯键入标题 + 一句话，无图、无封面、无外链） | 7050 |

→ **与内容无关**，是平台在这个分支上的已知问题。第三方同场景报道过一模一样的情况：
「草稿接口稳定返回 7050『保存失败』，新建失败，已有草稿也失败，换内容长度还是失败」，
他们的绕行办法也是**绕开草稿箱**，走编辑器自己的提交。

**实际发表结果**（2026-11-13）：

| 项 | 值 |
| --- | --- |
| 发表时间 | **14:05** 与 **14:11**，两篇 |
| 内容 | 完全一致：2525 字符、2 张正文图、结尾 `完整版见 growdu.cn` + 纯文本外链 |
| 标记 | 两篇都带**首发**（「声明首发」默认是勾上的） |
| 平台副作用 | 每篇自动生成 1 条微头条（「由文章生成」），共 2 条 |
| 账号内容数 | 89 → **93**（2 篇文章 + 2 条微头条） |
| 消息中心 | **没有任何处罚 / 封禁 / 权限变更通知**（最新一条是 11-13 的话题邀请，平台反而在邀请发文） |

> ⚠️ **拦请求做「干跑」不可靠**：这轮为了确认发表分支通不通，我试着在页面上拦下
> publish 请求再点按钮，想让它发不出去——**其中一次照样把文章发出来了**。
> 平台除了那条被拦下的请求，还有别的通道能把 `save=1` 送出去。
> **别再拿「拦请求」当干跑手段**：要试就在草稿箱里试，或者拿不重要的内容试。
>
> 14:11 那篇可以确定是排查时那次点击造成的（时间吻合）；
> **14:05 那篇的触发点没能完全定位**——它发生在两轮干跑之前，只可能是同一路径上的另一次提交。

> **待办（2026-11-13 用户拍板）**：两篇重复稿**删掉 14:11 那篇，保留 14:05 那篇**
> （它已有展现）。删除在后台做：**作品管理 → 该条「更多」→「删除作品」**。

### R3 · 2026-11-13 · 编辑器的定位口径（自动化用）

这一节记的是「**怎么用代码碰到平台**」，不是平台规则。工具脚本本身**不入库**
（放仓库外的临时目录），所以定位口径得留在这里——不然下次要重填一遍，
这些选择器得从头再摸一遍。

| 目标 | 定位 |
| --- | --- |
| 发文页 | `https://mp.toutiao.com/profile_v4/graphic/publish` |
| 标题框 | `textarea[placeholder="请输入文章标题（2～30个字）"]` |
| 正文 | `div.ProseMirror[contenteditable=true]` |
| 底部字数 | 页面文本里的 `共 N 字` |
| 工具栏 | 17 个可见 `button.syl-toolbar-button`，**没有区分属性**，靠 SVG path 认：图片按钮的 path 含 `12.5l7.921` |
| 发文设置面板 | `.footer-back-content`（点一下展开/收起），面板里有 `.edit-label`「展示封面」 |
| 封面 radio | `.article-cover-radio-group`（单图 / 三图 / 无封面），选中的那格 class 含 `checked` |
| 封面预览 / 替换 | `.article-cover-img-wrap img` / `.article-cover-img-replace` |
| 图片抽屉 | `.byte-drawer-wrapper`；**`.byte-drawer-mask` 在淡出期间仍会拦截点击**，点编辑器前必须等遮罩从 DOM 里消失 |
| 上传入口 | 文案「本地上传」；暂存提示「已上传 N 张图片」；**点「确定」才插入编辑器**（按 Escape 会丢弃暂存） |
| 勾选项 | 勾选标记在 **`<label>` 自身的 class**（`byte-checkbox-checked`）上，**不在** `.byte-checkbox-wrapper` 的子孙里 |
| 粘贴 | 真剪贴板（`text/html` + `text/plain`）+ `Meta+V`，走平台自己的 paste 处理器；**不要直接改 `innerHTML`** |
| 草稿保存 / 发表 | **同一个接口的两个分支**：`POST /mp/agw/article/publish`，`save=0` 存草稿（本账号一律 `err_no 7050`「保存失败」）、`save=1` 发表（**成功**）。见 §R2.F |
| 「预览并发布」 | 点它**只弹面板**，不发表：弹出「**预览确认发布**」，面板里才是「**确认发布**」主按钮 |

**重填一篇的顺序**（实测可用，约 40 秒）：

1. 标题框填标题（平台不拦字数，填完自己核长度）
2. 正文：真剪贴板 + `Meta+V`
3. 正文图：对每个 `【图N】` 占位符，用 Selection API 把光标定位到该段落段首
   → 点工具栏图片按钮 → 「本地上传」选文件 → 等「已上传 N 张图片」→ 点「确定」
4. 封面：`.footer-back-content` 打开面板 → `.article-cover-img-replace` →
   「上传图片」标签 → 「本地上传」选 `cover.webp` → 点「确定」
5. 勾选项回到默认（头条首发、发布得更多收益勾上；作品声明全不选）

> **编辑器会重渲染**：观测过程中正文曾被还原成空（`element was detached from the DOM`）。
> 填完之后要**再读一次正文长度**，别相信填完那一刻的读数。

### 2. 手工发一篇测试文章（**最值钱的一步**）

**怎么做**：后台「创作」→「文章」，走完「上传图片 → 排版 → 发表」全流程。
