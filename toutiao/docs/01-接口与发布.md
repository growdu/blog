## 一、授权模型

头条号创作开放平台走 **OAuth2.0**，账号侧在
「设置 → 开放平台 → API 权限管理」手动开启权限后，绑定应用拿 token。

| 项 | 值 |
| --- | --- |
| 授权方式 | OAuth2.0（具体是授权码还是客户端凭证，**待实测**） |
| 需开启的权限 | 「文章发布」「图片上传」 |
| client_id / client_secret | 本地 `toutiao/secrets.json`，**永不入库** |
| token 存放 | 本地 `toutiao/secrets.json` 或环境变量 `TT_ACCESS_TOKEN` |
| IP 约束 | **待实测**（公众号有 IP 白名单，头条是否有同类约束需确认） |

> **未认证账号即使完成 OAuth2 登录，发布时也会返回「权限不足」。**
> 这是本项目当前的头号约束。

## 二、已核实的平台约束

### 2.1 规格与限额

| 项 | 规则 | 来源 | 状态 |
| --- | --- | --- | --- |
| 标题 | ≤ 30 字 | 第三方对接说明转述 | ⚠️ 待实测 |
| 摘要 | 首段自动提取，不可为空 | 同上 | ⚠️ 待实测 |
| 正文图片 | 转 webp，≤ 5MB | 同上 | ⚠️ 待实测 |
| 封面图 | 单张竖图，3:4，≥ 600×800 | 同上 | ⚠️ 待实测 |
| 正文长度 | 约 3K（《运营手册》§2.2 的版本表） | 自定 | — |

> ⚠️ **限额本身来自第三方工具的对接说明转述，不是官方文档。**
> 实测后回填 `publish/capabilities/toutiao.toml` 的 `[limits]`。

### 2.2 禁止与限制

| 项 | 规则 | 影响 |
| --- | --- | --- |
| 微信公众号二维码 | 禁止 | 跨平台复用时须剔除 |
| 外链跳转代码 | 禁止 | 正文里不放可点击站外 URL，链接降级为纯文本 |
| 正文插入外链 | **独立创作者权益**，需单独开通 | 未开通时 URL 不会变成链接 |
| 简介含网站链接 / 邮箱 / 联系方式 | 禁止 | 博客地址不能挂简介 |
| 简介含第三方平台引导语 | 禁止（账号基本信息审核规范） | 简介只写职业身份 |
| 图片外链 | 不生效，图要在编辑器重新上传 | 图越少越好 → 最多 3 张（0 张也行） |
| 话题 | 上限 5 个，超出退化为普通文本；无关话题词蹭流量是明确扣分项 | 不挂无关话题 |

### 2.3 账号规范（与内容无关但会踩）

- 账号名不得含「今日」「头条」等易被误解为官方的字样
- 不得使用第三方品牌 Logo 作为头像
- 分类由机器根据正文判定，**PC 端展示的分类不影响推荐**；频繁修改会影响推荐
- 标签由系统自动匹配，不存在「必填」门槛

## 三、状态机

```
                    ┌──────────┐
                    │ packaged │  manual 档：出包完成，等人工上传
                    └────┬─────┘
                         │ 人工上传（不进系统）
                         ▼
                    ┌──────────┐
                    │ drafted  │  api_draft 档：草稿已建，等人点发表
                    └────┬─────┘
                         │ 人点发表
                         ▼
                    ┌──────────┐
                    │ reviewing│  平台审核中
                    └────┬─────┘
                         │ 审核通过
                         ▼
                    ┌──────────┐
                    │ published │  ✅ 真的发出去了
                    └──────────┘

  任何一步失败 → status = failed + reason，**不静默成功**
```

**`packaged` 与 `published` 必须在站点索引里区分开。**
读者点进去发现没有这篇，等于把「发重了」的风险换成了「发虚了」。

## 四、幂等

三层键（与 `weixin/wechat/state.py` 同构，**独立实现，不 import**）：

| 层 | 键 | 防的是什么 |
| --- | --- | --- |
| 内容 | 正文指纹 `sha256(body)` | 母稿改了 → 允许重发 |
| 平台 | `(content_id, platform)` | 同一篇重复出包 / 重复调接口 |
| 平台侧 | 头条返回的 `object_id` / `group_id` | 接口超时后重试不重复发 |

**超时不是失败。** 超时后**先按 `object_id` 查一次状态再决定**——
直接重试可能发两遍。这条与公众号是同一条纪律。

## 五、失败分类

| 失败 | 表现 | 处理 |
| --- | --- | --- |
| 接口报错 | errcode ≠ 0 | 记入状态快照（`status = failed` + reason），**不吞异常** |
| 权限不足 | 「权限不足」类 | 不重试——这是账号状态问题，重试无意义 |
| 审核不通过 | 审核状态字段 | **不自动重试**，转人工（内容有问题，重试无意义） |
| 网络超时（结果未知） | 没拿到响应 | **不当作失败**，下次跑先查状态再决定 |
