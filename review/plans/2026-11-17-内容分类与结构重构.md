### 3.1 `_index.md` 必须带 `cascade` 块（✓已复核，重要）

分类名的级联机制**不是**只读 `title:`。实测三层：

- `sync-hexo.py:443 read_section_categories()` —— 只读**顶层**目录 `_index.md` 的 `title:`
  （拿到一级赛道名）；
- `sync-hexo.py:458 read_cascade_categories()` —— 读的是 `cascade:` 块里的 `categories:` **列表**；
- `sync-hexo.py:486 resolve_post_categories()` —— 把一级名 + 各级祖先的 cascade 列表
  **按顺序拼接**成一条链；
- Hexo 侧 `node_modules/hexo/dist/models/post.js:118 setCategories()` 把 front matter 的
  `categories:` 列表当成**层级链**（第 i 个是第 i-1 个的子节点）。

**所以新目录的 `_index.md` 只写 `title:` + `description:` 是不够的** —— 二三级分类会
**静默消失**，文章全挂到一级赛道下，而没有任何测试会报错。参照
`docs/life/road/_index.md` 的现成写法，每个新 `_index.md` 要带：

```yaml
---
title: 存储引擎
description: 数据落在哪、怎么读进来、内存怎么分。
cascade:
  categories:
    - 源码主线
    - PostgreSQL
    - 存储引擎
---
```

**验收要断言三级路径 `/categories/源码主线/PostgreSQL/存储引擎/` 真的存在**，
而不是断言 `_index.md` 里有 `title:`。

### 5.2 迁移怎么做

1. **`data/tree-migration.json`** —— 人工策展的迁移表：
   - `dir_map`：旧目录前缀 → 新目录（`"db/postgresql/learning-path/"` → `"source-tracks/postgresql/getting-started/"`）
   - `file_map`：逐文件的例外（文件名不跟目录走的，比如 `docs/base/*.md` 这种一个目录里混着
     多个主题的，需要逐篇指定）
   - `out_map`：要移出 `docs/` 的目录与文件 → `internal/` 下的目标位置
   - `ref_rewrites`：相对链接的重写规则（跨系列搬家的那些）
   规则来源：`data/learning-path.json` 的 **157 条**路径匹配规则（按新目录重写）+ 新树的三级映射。

   > **实跑后的一处调整**：原设计里的 `content_id_map`（`publish/outbox/` 那 567 个
   > `content_id` 的新旧对照）**没有做成迁移表的一栏**。原因是快照文件名本身就是
   > `snapshot_name(content_id, platform)`，改 `content_id` 就必须同步改文件名 ——
   > 一次性改掉比维护一张对照表更省事，且有契约测试
   > （`publish/tests/test_episode.py`）守着「文件名 == `snapshot_name(content_id)`」。

2. **`tools/migrate-tree.py`** —— 执行迁移（幂等，可重复跑）：
   - 按 `dir_map` / `file_map` 逐个 `git mv`（**必须用 `git mv`**，保留文件历史）
   - 按 `out_map` 把内部文档移到 `internal/`
   - 顺手生成三张补丁：`REDIRECTS`（旧路径 → 新路径，键用拍平后的路径）、
     `DATE_OVERRIDES`（**键 = 新路径**）、`CATEGORY_REDIRECTS`（旧分类 → 新分类）
     —— 实跑时前三张表落成了**独立的数据文件**
     （`data/redirects.json`、`data/date-overrides.json`、`data/category-redirects.json`），
     由 `sync-hexo.py:212-213` 读进 `REDIRECTS` / `CATEGORY_REDIRECTS`。
     分文件而不是塞进 `sync-hexo.py` 里的字面量，是因为这次要搬 208 篇 ——
     字面量表会变成一堵墙，且没法用 `diff` 审。
   - 修 `FEATURED_POSTS`、`data/featured.json`、`infer_topics()` 的前缀规则、`META_CATS`、
     `home-hero.ejs` 的徽章名、`review/` 的目录名

3. **重定向的日期依赖（最容易漏、后果最重的一条）**：

   `write_redirects()`（`sync-hexo.py:1889`）用 `git_date(new_file)` 取日期来拼旧 URL 的
   日期段（stamp 在 `:1914`）。而 `git_date()`（`:606`）**不是**「对当前路径跑一次 git log」——
   它依次试**多个候选路径**并取**最早**的一个：

   ```python
   candidates = [f"docs/{rel}", rel]                    # rel 还会去仓库根找 docs/ 之前的历史
   if basename == "index.md": candidates += [f"docs/{parent}.md", f"{parent}.md"]
   ```

   因为很多文章最早写在**仓库根**（`docs/` 之前），后来整棵树才搬进 `docs/`。
   **`git mv` 之后，当前路径的最早提交就是「搬运」那一次** → 日期变成搬运日 →
   ① 文章日期全变，一齐跳到「最近发布」顶部；② 重定向页写到**错误的旧 URL**，旧链接照样 404。

   **对策（唯一正确解）**：搬之前**直接调用 `git_date(old_file)`**（它会走候选逻辑），
   把返回的日期按**新路径**固化进 `DATE_OVERRIDES`（`git_date` 查表用的 key 是
   `os.path.relpath(filepath, DOCS)`，即 docs 相对路径、含 `index.md`）。
   这样 `git_date(new_file)` 返回原日期 → 日期段不变 → 旧 URL 重定向页落回正确位置。

   > **⚠ 初版本文档在这条上给的是错的配方**（写的是「裸 `git log --all --reverse -- docs/<路径>`」）。
   > 实测（2026-11-17）：620 个 `docs/*.md` 里 **314 篇（50%）**的 `git_date()` 与裸 git log
   > **不一致**。例：`docs/base/data-struct.md` 的 `git_date()` 是 `2018-10-05`，
   > 裸 git log 是 `2025-04-16`。按初版配方做，**一半文章会被重新定到批量导入日**。

   **已实测**：568 篇文章的原始日期全部可取、零遗漏，可以直接生成完整的 `DATE_OVERRIDES` 表。
   但要注意分布：其中 **290 篇共用同一个日期 `2025-04-16`**（批量导入时间戳），
   年份分布 2025 年 305 篇 / 2026 年 263 篇。**日期机制一旦失灵，全站一半的文章会同时
   跳到同一天** —— 这比零散的日期错乱更难肉眼发现，也更难回滚。所以这条必须做成
   **自动断言**（迁移前后逐篇比对 `git_date()` 的返回值，不一致就退出码 1），不能靠抽查。

4. **`publish/outbox/` 的 567 个 `content_id` 会失效**（✓已复核，初版完全漏了）：
   每个快照长这样：

   ```json
   { "content_id": "source-tracks/postgresql/index-and-query/learning-path/03-query-pipeline",
     "package_dir": "toutiao/out/blog-架构" }
   ```

   `content_id` 里嵌的就是 docs 目录结构，`tools/build-publish-index.py:140` 靠它拼文章
   （只有 basename 唯一时才兜底）。**PostgreSQL 试点一步作废 203 条**。
   顺带：`publish/publishkit/episode.py:406 content_id_for_draft()` 也是从 docs 路径推
   content_id 的，所以「以后发新内容」会自动跟着新路径走，**只有历史快照**需要重写。

   > **⚠ 与「只动 docs/」这条线的一处出入（实跑后改了主意）**：
   > 原计划是「`publish/` 在范围外，本次不重写」，代价是历史发布快照与文章脱钩、
   > `build-publish-index.py` 只能靠 basename 兜底。**实跑时改了主意**：§六 的验收清单里
   > 这一条本来就写着「`publish/outbox/` 里这批文章的 203 个 `content_id` 已重写」——
   > 快照文件名 = `snapshot_name(content_id, platform)`，只改 `content_id` 不改文件名会直接
   > 违反 `publish/tests/test_episode.py` 的契约。所以**201 个快照连内容带文件名一起改了**，
   > 另 2 篇内部工作文档随 `out_map` 移出 `docs/` 后改成 `internal/db/logical_decode/…`。
   > 改动只碰 `content_id`、文件名与那 2 篇的 `reason` 字段，**没有动任何发布流程的代码**。

5. **内链断裂需要新工具才能看见**（✓已复核，初版选错了验收工具）：
   `tools/check-built-links.py` **只管 gaokao 一段** —— `:60 gaokao_pages()` 只收
   `/life/gaokao` 的页面，`:57 LINK_RE` 只匹配 gaokao 链接，**根本不查图片**。
   它会在「迁移打断 500 条链接」的情况下照样全绿，**当不了验收闸门**。

   而且相对链接恰恰是这次迁移最脆的东西：`sync-hexo.py:1407 rewrite_links()` →
   `:1345 _resolve_link_target()` 是在**编译时**按「引用方所在的 docs 目录」解析每个相对链接、
   换成绝对 permalink 的。所以：
   - 指向「被分到另一个新系列」的同目录兄弟的链接（`../postgresql-mvcc/index.html`）会断；
   - 留在原地、指向被搬走文章的链接会断；
   - `:1473-1480` 那个「往上一级目录再试一次」的兜底只能治好一部分。

   按一个合理的试点映射模拟，**45 条文章级相对链接会断**（db 35、pgsql 8，外加
   `docs/base/file.md` 的 2 条指向 `../pgsql/` 和 `../db/`）。真实数字取决于最终系列划分，
   但**这类断裂一定存在，而且现在没有任何工具能报出来**。

   **要新建一个全站内链检查器**：至少校验「每条相对链接在迁移后仍能解析到目标」+
   「构建产物里没有指向不存在页面的 href」。迁移脚本还要负责**改写被搬文件里的相对链接
   文字**（这是写操作，会动几百个文件的内容）—— 否则就是一批读者点不开的站内链接。

### 5.3 与「只动 docs/」这条线冲突的一处：`data/learning-path.json`

**实测结论（2026-11-17，在 worktree 上验证过）**：在 `docs/` 下新增 3 篇文章、而
**不**改 `data/learning-path.json` 的话，`tests/test_learning_path.py` **3 个用例直接红**：

```
FAILED test_learning_path.py::test_every_article_is_classified
FAILED test_learning_path.py::test_no_article_lands_in_two_places
FAILED test_learning_path.py::test_every_article_appears_exactly_once_in_the_rendered_pages
E   AssertionError: 赛道页里列了 577 篇文章，语料是 580 篇
```

原因：这个守卫测试拿「赛道页列出的文章数」和「语料里的文章数」对拍，**任何一篇文章
没被某条赛道的规则命中，语料就比赛道页多一篇**。这是它的设计意图 ——
「每篇文章都该有一条自己的规则，兜底阶段必须是空的」。

所以「只在 `docs/` 下加文章」与「`data/` 一点不碰」**不能同时成立**。三条出路：

| 方案 | 动什么 | 代价 |
| --- | --- | --- |
| **A. 允许 `learning-path.json` 的最小改动** | 每批新文章补一条 `path_prefix` 规则 | 改的是 `data/`（非 docs），但这是既有机制的自然延伸，一行 JSON |
| **B. 放宽守卫测试** | `tests/test_learning_path.py` 允许某些目录走 fallback | 动的是 `tests/`（非 docs），且**削弱了守卫的强度** —— 以后漏写规则不会再被发现 |
| **C. 新赛道不进学习路径** | 语料侧排除新目录 | 同样要动 `tests/` 或 `tools/build-learning-path.py`，而且新文章在站点上就没有位置了 |

**本方案按 A 执行（待作者确认）。** —— 这是唯一「不改守卫强度、且改动量最小」的方案，
而且它跟「非 docs 不涉及」的精神并不冲突：`learning-path.json` 是**策展表**，不是
工程代码，它的内容就是「每篇文章属于哪」—— 这恰恰就是本次要整理的东西。

据此，§零「范围」表里那条例外从「站点构建链路的配套改动」收窄成**一条明确边界**：

> **执行边界**：`data/learning-path.json` 按「每批新文章补一条 `path_prefix`
> 规则」的最小方式改动，**仅限**新增文章路径的登记。
> 不改规则语义、不改赛道/阶段结构、不改 `tools/build-learning-path.py`、不改 `tests/`。

后台那个独立进程已经按 A 做了最小改动（给 `blogging` 赛道加了一条
`path_prefix: "platform-meta/"`），在这条边界之内，保留。

## 七、与视频流水线的关系

本轮**不挂**。视频与多平台（抖音 / 公众号 / B站）的状态以后再接，接的时候：

- 每篇文章的「已出精简视频 / 已出完整视频 / 已同步平台」状态从
  `publish/outbox/` + `aiv/contracts/` 读
- 新树里每个**系列**（不是每篇）是视频生产的单位 —— 一个系列对应一期视频
- 现有 `series` 字段（播客系列，如「数据库内核机制」六期）与新树的「系列」概念**重名但不同义**，
  接视频时需要先决定是合并成一个概念，还是改名（如 `collection`）

## 八、风险

| 风险 | 缓解 |
| --- | --- |
| 重定向表写错一个键 → 一篇文章 404 | 迁移脚本自动生成，不手写；新建的全站内链检查器复查 |
| 外部链接（知乎、公众号、GitHub 引用旧 URL）全部 404 | 重定向页带 `meta refresh` + `canonical`，外链能跳；**但外链的读者体验是「跳一下」，需要同步通知已知的引用源** |
| `git mv` 几百次，中途失败留下半搬状态 | 迁移脚本幂等 + 可重跑；每块一个 commit，出错能单独回滚 |
| 搬完发现某个旧目录混着多个主题（如 `docs/base/`） | `file_map` 逐文件指定，一张表解掉 |
| 日期被改写 → 「最近发布」被几百篇霸占 | `DATE_OVERRIDES` 验收项 + 逐篇自动断言 |
| 相对链接批量断裂，而现有工具查不出来 | 必须新建全站链接检查器，且迁移脚本负责改写链接文字 |
| `publish/outbox` 的发布状态与文章脱钩 | content_id 重写纳入同一次迁移，并加断言 |
