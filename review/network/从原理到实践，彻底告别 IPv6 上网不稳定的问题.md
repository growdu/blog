6. 位置：L379
   - 问题：**算术对不上**。原文说「把 IPv6 也砍到 MSS = 1300 或 MTU=1368」。
     IPv6 下 MSS = MTU − 40（IPv6 固定头）− 20（TCP 头）= MTU − 60，
     所以 MSS 1300 对应的 MTU 是 **1360**，不是 1368。
     而文中实测的 Windows WLAN MTU 是 1410：IPv4 MSS = 1410 − 40 = 1370 ✓、
     IPv6 MSS = 1410 − 60 = 1350 ✓，两个数都对得上——唯独 1368 对不上
     任何东西。
   - 建议：改成 MTU=1360；更好的做法是**只给 MSS**（推荐 MSS = 1300），
     不给 MTU——MSS 是端到端协商出来的量，少一层换算就少一类错。
   - 原因：涉及数字，必须算得通；这类算术错误读者会照抄。
   - 落地：改成 1360，并写清它是怎么来的（1300 + 40 + 20）；
     同时按建议改成**只设 MSS、不动 MTU**。

## 事实待核

- [x] Cisco `ip tcp adjust-mss` 的默认值 —— Cisco IOS IP Application
  Services Command Reference：「Command Default: The MSS is determined by the
  originating host.」，取值范围 500–1460。**默认不开启**，
  原文 L290「专业的路由器一般都支持 MSS Clamping」没说它默认开，成立。
- [x] Cisco 对 1452 这个值的官方依据 —— 「in most cases, the max-segment-size
  argument of `ip tcp adjust-mss` should be set to 1452 bytes. This value plus
  the 20-byte IP header, 20-byte TCP header, and 8-byte PPPoE header, results
  in a 1500-byte packet that matches the Ethernet link MTU.」
  原文 L304「钳制到 1452，适合 PPPoE 用户」有官方依据。
- [x] 默认 MSS 与 PPPoE MTU 的表述 —— 「The default MSS size is 1460 bytes,
  when the default MTU of the containing IP datagram is 1500 bytes. The PPP
  over Ethernet (PPPoE) standard supports an MTU of only 1492 bytes.」
- [x] MSS Clamping 的适用边界 —— Cisco 文档：「`ip tcp adjust-mss` command only
  works for TCP connections through the router」。另外 Cisco 有一篇专门讲
  Catalyst 9K 的排障文档指出：MSS 调整的流量**始终走软件交换**，量大时
  会压垮 COPP 限速器，表现为 SSH 卡死、TCP 变慢——这是原文没有的坑，
  值得补进「哪些设备需要开启」那一节。
- [x] 各类封装对 MTU 的开销 —— PPPoE 8 字节（1492）、GRE 24 字节（1476）、
  VXLAN 50 字节（14 Ethernet + 20 IP + 8 UDP + 8 VXLAN）。
  原文 L48、L201 的数字**全部正确**。
- [x] 4G 抓包里的 MSS 数字 —— 实测下载原图核对：IPv6（访问知乎）SYN 的
  MSS=**1350**、SYN-ACK 的 MSS=**1300**；IPv4（访问百度）SYN 的 MSS=**1460**、
  SYN-ACK 的 MSS=**1370**。原文 L372「把 IPv6 的 MSS 砍到了 1300，把 IPv4 的
  MSS 也砍到了 1370」**与截图完全一致**。
- [x] 4G 那台的 1410 与两个 MSS 的关系 —— WLAN MTU 1410：IPv4 MSS =
  1410 − 40 = **1370** ✓；IPv6 MSS = 1410 − 60 = **1350** ✓。
  两个数都与实测吻合。
- [x] L100 的分片算例 —— 1500 字节 IP 包经 1492 与 1484 两级 MTU，
  碎成 1492+28 与 1484+28，总长 1540，比原包多 40 字节
  （两个额外 IP 头各 20）；分片偏移 1472 与 1464 都是 8 的倍数，合规。
  算得对。
- [x] L34 那张图的实际内容 —— 实测下载核对：三次握手抓包，
  SYN 的 MSS=1440、SYN-ACK 的 MSS=1432（被钳掉 8 字节）。
  与 L32 的文字描述一致。
- [x] 16 张图与 12 条参考的可达性 —— 实测：14 张唯一图片 URL 在不带浏览器
