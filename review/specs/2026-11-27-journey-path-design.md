# 设计：给读者的一条路 —— 从菜鸟到内核专家

> 2026-11-27。继 `2026-11-26-learning-path-tree-design.md`（把物理目录重排成
> 学习路径的镜像）之后的第二件事：**目录已经跟学习路径对齐了，但学习路径本身
> 还没有「顺序」**。

---

## 一、目标与非目标

### 目标

1. 给读者一条**能从头走到尾**的路：`/learning/` 现在是 11 条赛道按学科并排，
   读者得自己拼顺序；这条路要告诉他「先学什么、再学什么、学完能干什么」。
2. 这条路的顺序**由作者自己的成长轨迹给出**——不是拍脑袋排的难度，而是
   「这条路我真的走过，每一步都留下了文章」。成长过程因此变成**可验证的事实**，
   而不是一句自我介绍。
3. 不再造一棵平行的分类树。分期只能引用现有的 48 个阶段，**不能新增分类**。

### 非目标

1. 不改 `data/learning-path.json` 的规则表（11 赛道 / 48 阶段 / 0 条正则的现状不动）。
2. 不改任何一篇文章的分类链、URL、发布日期。
3. 不给读者编「这一期要学 X 周」的承诺 —— 站上没有依据支撑这种估计（见 §七）。
4. 不做「按读者起点分岔」的导航（那是 B 方案，2026-11-27 已否）。
5. 不把 6 期视频内容单元塞进分期 —— 它们不在 `docs/` 里，没有日期条目。

## 二、事实基线（2026-11-27 实测）

### 2.1 作者的写作年份分布

每篇文章的**首次提交日期**已经固化在 `data/date-overrides.json`（591 条，
`capture-dates.py --check` 逐篇比对漂移 0）。按年分箱：

| 2018 | 2019 | 2020 | 2021 | 2022 | 2023 | 2024 | 2025 | 2026 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 35 | 1 | **0** | **0** | **136** | 96 | 39 | 19 | **265** |

两个不能忽略的事实：**2020–2021 整整两年一篇没写**；**2026 年写了 265 篇，
占全站 45%**。

### 2.2 赛道 × 年份

| life 人生与成长 | | | | | 3 | 24 | 27 |
| blogging 博客与自媒体 | | | 1 | | | 19 | 20 |
| postgresql 内核 | | 29 | 16 | 10 | 1 | **153** | 209 |

| platform-meta 平台元数据 | | | | | | 7 | 7 |

这条曲线本身就是答案的一半：2018 年只有工程语言 → 2022 年一年跨到数据面、
Linux、分布式、内核（136 篇）→ 2023–2025 收窄、往内核深处沉
（engineering 36→13→6）→ 2026 年内核 153 篇。

### 2.3 现有学习路径结构（复用点）

- `data/learning-path.json`：11 赛道 × 48 阶段，每阶段有 `id` / `dir` / `title` /
  `goal` / `match`。
- `tools/build-learning-path.py`：读规则表 + `source/_posts/`，生成
  `source/learning/<赛道>/index.md` 与 `source/_data/learning.json`；
  `--check` 模式做「规则表对不上语料就红」。
- `themes/matery/layout/learning.ejs`：学习路径页的 layout（面包屑 + 正文）。

**这套东西全部复用。** 分期是它**上面的一层顺序**，不是另起一套。

## 三、这条路的形状

### 3.1 五期主线 + 一段选修

按「作者在每个阶段上实际花了多久」把 48 个阶段聚成 5 段，加一段选修。

| 期 | 主题 | 覆盖的阶段 | 篇数 | 作者写它的年份 |
| --- | --- | --- | ---: | --- |
| **1 · 打底** | 把工程基本功练成手感 | engineering L1–L4、life L1 | 115 | 2018–2026 |
| **2 · 看见机器** | 用户态下面是什么 | linux L1–L5、dataplane L1–L4 | 109 | 2022–2026 |
| **3 · 系统会怎么坏** | 分布式的直觉 | distributed L1–L4 | 64 | 2022–2026 |
| **4 · 走进内核** | 一次 SQL 的完整轨迹 | postgresql L1–L6、L8 | 130 | 2022–2026 |
| **5 · 深水区** | 逻辑复制与源码专项 | postgresql L7、linux-kernel L1–L3、ceph L1–L2 | 94 | **2026** |
| 选修 | 另一条线 | ai-tools L1–L4、blogging L1–L4、platform-meta L1–L6、life L2–L4 | 79 | 2023–2026 |

合计 **591 篇**（`docs/` 下 588 篇 `.md` + 3 篇 `.html`），
**48 个阶段全部有归属**，一篇不落、一阶段不重。

### 3.2 为什么这样切

- **期 1 收 engineering 全赛道 + life L1**：2018 年那 35 篇工程语言是作者的
  第一反应；`life L1`（学习方法、左耳朵耗子）是「还没开始学技术时该先读的东西」。
- **期 2 是 2022 年最重的一段**：linux 30 篇 + dataplane 40 篇，
  「从用户态走到机器」这件事作者是在同一年里啃完的。
- **期 3 紧接其后**：distributed 2022–2023 写了 53 篇，是紧接着内核去读的。
- **期 4 是主干**：postgresql 的 7 个阶段（L1–L6、L8），2022 年起持续补到 2026。
- **期 5 是深水区**：postgresql L7 逻辑复制 **79 篇全是 2026 年写的**，
  加上 linux-kernel 6 篇、ceph 9 篇 —— 这是作者**现在**在做的事，
  也是全站最重的一块。

### 3.3 口径：所有人从期 1 走起

2026-11-27 明确选 A 方案（教学史，一条直线）。因此：

- 页面**不提供按起点分岔的入口**，没有「你已经会了 → 跳过」。
- 每一期都是必修，期与期之间是**单向的顺序**。
- 已知代价见 §十一：期 1 的 115 篇里，94 篇是 2018 年的语言入门，
  对已经有经验的读者是负担。**这是明确接受的代价**，不是待办。

## 四、数据：`data/journey.json`

新文件。**只描述分期，不描述年份** —— 年份由生成器现算（§七），
这样日期表变了不用手改两张表。

```json
{
  "version": 1,
  "title": "成长路线",
  "subtitle": "从菜鸟到内核专家，作者走过的 8 年",
  "periods": [
    {
      "id": "p1",
      "title": "打底：把工程基本功练成手感",
      "goal": "这一期解决什么（一句话，动词开头）",
      "can_do": "读完这一期，你能做到什么（可验证的能力陈述）",
      "stages": ["engineering/L1", "engineering/L2", "engineering/L3",
                 "engineering/L4", "life/L1"],
      "first_read": [
        {"path": "docs/source-tracks/engineering/L1-basics/…", "why": "为什么先读它"}
      ]
    }
  ],
  "optional": {
    "id": "optional",
    "title": "另一条线",
    "goal": "…",
    "stages": ["ai-tools/L1", "…"]
  }
}
```

字段说明：

| 字段 | 含义 | 谁写 |
| --- | --- | --- |
| `stages` | `"<赛道 id>/<阶段 id>"` 引用现有阶段 | 人写 |
| `first_read` | 每期 1–2 篇起步文章 + 一句理由 | 人写（机器排不出「先读哪篇」） |
| `goal` / `can_do` | 这一期的目标与出口 | 人写 |
| 年份、篇数、矩阵 | **不在这张表里** | 生成器现算 |

**为什么 `stages` 用引用而不是复制阶段内容**：阶段标题、`goal`、文章列表
全部来自 `data/learning-path.json`。复制一份就多一处会漂移的地方。

## 五、生成器：`tools/build-journey.py`

新工具，跟 `build-learning-path.py` 同构：

```
python3 tools/build-journey.py            # 生成
python3 tools/build-journey.py --check    # 只校验，不写文件（CI 用）
```

产出：

| 路径 | 内容 |
| --- | --- |
| `source/journey/index.md` | 总览页（5 期卡片 + 矩阵 + 选修） |
| `source/journey/<期 id>/index.md` | 每期一页 |
| `source/_data/journey.json` | 结构化数据 |

### 5.1 数据流

```
data/learning-path.json  ─┐
                          ├─→ build-journey.py ─→ source/journey/**
data/journey.json        ─┘                └─→ source/_data/journey.json
data/date-overrides.json ─→ （只用来算年份矩阵）
```

### 5.2 `--check` 的语义

跟 `build-learning-path.py --check` 一致：**规则表对不上语料就红**。
具体是三件事（§九）。

### 5.3 复用什么、不重写什么

- 文章的标题、地址、分类 → 直接复用 `build-learning-path.py` 的
  `read_posts()` / `classify()`，**不重新实现一遍归类**（归类的唯一真相是
  `data/learning-path.json` 的规则表）。
- 页面的框 → 复用 `themes/matery/layout/learning.ejs`（§六.1 要改一处）。

## 六、页面结构

### 6.1 layout 要改一处

`learning.ejs` 的面包屑把父级写死成「学习路径」：

```ejs
<a href="<%- url_for('/learning/') %>">学习路径</a>
```

新增的成长路线页要显示「成长路线」。改法：**面包屑的父级从 front matter 读**，
缺省仍是 `/learning/`。这样 `learning.ejs` 同时服务两套页面，不新增 layout。

（`url_for` 的挂载点前缀问题照旧用 `tools/site_root.py` 解决，
主站 `/`、镜像站 `/blog`。）

### 6.2 总览页 `/journey/`

1. **一句话**：这是什么、给谁看。
2. **作者投入的时空分布**（期 × 年 的篇数矩阵，§七）—— 这一张表就是
   「从菜鸟到内核专家」的曲线本身。
3. **五期主线**，每期一张卡片：
   - 期号、主题
   - `goal`（这一期解决什么）
   - `can_do`（读完能做什么）
   - 作者在这一期的年份跨度 + 篇数
   - 包含哪些赛道阶段（链到 `/learning/<赛道>/`）
   - 「开始这一期」→ 期页
4. **选修线**：单独一小节。
5. **「这条路作者走了 8 年」** 的注脚 + 链到 `/learning/`（按学科查）。

### 6.3 每期页 `/journey/<期 id>/`

1. 期号 + 主题 + `goal` + `can_do`。
2. **推荐起步**：`first_read` 的 1–2 篇 + 理由。
3. **这一期包含的阶段**：每阶段一个小节（阶段标题 + 阶段 `goal` + 文章列表），
   阶段标题链到 `/learning/<赛道>/`。
4. **作者在这一期**：年份跨度、篇数、矩阵里对应的那几行。
5. **下一步**：「走完这一期，去 [第 N+1 期](…)」；最后一期给「去选修线」
   或「回总览」。

### 6.4 与 `/learning/` 的关系

**兄弟关系，不合并、不替代。**

| | `/learning/` | `/journey/` |
| --- | --- | --- |
| 组织方式 | 按学科（11 赛道） | 按顺序（5 期） |
| 回答的问题 | 「这个主题有哪些文章」 | 「我现在该学什么」 |
| 入口 | 首页的面板 | `/learning/` 总览页首屏 + 菜单 |

两页互相链接：总览页顶部链到成长路线，成长路线页每期链回对应的赛道页。

## 七、作者投入怎么呈现（口径）

这是本设计**唯一的新维度**：期 → 作者在它上面花了多少时间。

### 7.1 数据来源

`data/date-overrides.json`（591 条，每篇文章的首次提交日期，已固化）。
生成器按「期包含的阶段」把这些文章的年份统计出来。

口径写清楚：**只算 `docs/` 的 591 篇**。6 期视频内容单元住在 `aiv/`，
不在 `docs/`，没有日期条目，不参与统计。

### 7.2 矩阵（2026-11-27 实测）

| 期 | 18 | 19 | 20 | 21 | 22 | 23 | 24 | 25 | 26 | 篇数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 打底 | **35** | 1 | 0 | 0 | 12 | 36 | 13 | 9 | 9 | 115 |
| 2 看见机器 | | | | | **70** | 13 | 11 | 7 | 8 | 109 |
| 3 系统会怎么坏 | | | | | 25 | 28 | 5 | 1 | 5 | 64 |
| 4 走进内核 | | | | | 29 | 16 | 10 | 1 | 74 | 130 |
| 5 深水区 | | | | | | | | | **94** | 94 |
| 选修 | | | | | | 3 | | 1 | 75 | 79 |
| **合计** | 35 | 1 | 0 | 0 | 136 | 96 | 39 | 19 | 265 | **591** |

这张表必须能被读者一眼读懂，因为它就是「成长过程」本身：
**2018 只有期 1；2020–2021 全空；2022 一年铺开期 2/3/4；2026 全压在期 4/5 上。**

### 7.3 不给读者编工期

**不给「这一期要学 X 周」这类估计。** 站上没有依据支撑它：
作者一篇语言入门写了 3 小时还是 30 分钟，从提交记录里看不出来；
「篇数 ÷ 阅读速度」也依赖读者的底子。

替代做法：给**事实**（作者在这一期写了多少篇、跨越哪几年），让读者自己折算。
文章量级已经够读者估了 —— 「期 2 有 109 篇」本身就是信息。

### 7.4 「投入量」不等于「难度」

年份跨度是**作者的经历**，不是**读者的顺序**。期 1 跨度 8 年（2018–2026），
是因为作者 2018 年写语言、2023 年又回头补工程化 —— 跨度大不代表它最难。
页面文案不要把「作者写了 8 年」写成「这一期最难」。

## 八、入口与发现

`/learning/` 现在**只能从首页的面板进**（菜单里没有它）。新加一页只会更没人看见。

三处入口（本次一起做）：

1. **菜单加一项「学习路径」→ `/learning/`**（菜单：首页 / 归档 / 学习路径 / 关于）。
2. **`/learning/` 总览页首屏加一行**：想按一条线走通 → [成长路线]。
3. **首页学习路径面板加一行**：「面板是按学科分的；要按顺序走，看成长路线」。

首页**不加新的卡片** —— 那个面板已经占满一屏了，再加一块就把首页撑破。

## 九、守卫

新增 `tests/test_journey_path.py`（不依赖构建产物，进 `site-guard.yml`）：

1. **阶段全覆盖**：48 个阶段，每个**恰好**属于一期（主线 5 期之一，或选修）。
   少一个、多一个、重复一个，都红。
2. **引用必须存在**：`data/journey.json` 里每个 `"<赛道>/<阶段>"` 都得在
   `data/learning-path.json` 里找得到。
3. **期数与顺序固定**：主线恰好 5 期，id 依次 `p1`…`p5`，顺序即阅读顺序。
4. **起步文章必须存在**：`first_read` 的每个 `path` 得在 `docs/` 里真实存在。
5. **年份口径**：`data/date-overrides.json` 的条目数 = `docs/` 的文章数，
   且每期的篇数加起来 = 591（视频单元不计入）。
6. **链接**：`/journey/` 页面里的站内链接不许指向不存在的页面（复用
   `tools/check-internal-links.py` 的产物侧检查）。

另有一条**运行期**守卫：`build-journey.py --check` 在 CI 里跑，
规则表改了但 `data/journey.json` 没跟上（新增了阶段没归期）就红。

## 十一、不做的事 / 已知代价

1. **期 1 对有经验的读者是负担。** 115 篇里 94 篇是 2018 年的语言入门。
   选了 A 方案（教学史），这是明确接受的代价。想改就是 B 方案（分岔导航），
   那是另一个设计。
2. **2020–2021 的空白期在页面上是「0 篇」。** 它如实反映了作者那两年没写，
   不解释成「他那时候在忙别的」—— 站上没有依据。
3. **6 期视频内容单元不在分期里。** 它们不在 `docs/`，没有日期，
   也没有阶段归属（`path_exact` 单列规则）。
4. **`/journey/` 与 `/learning/` 是两套入口。** 两页必须互相链清楚，
   否则读者会以为是两批重复的文章 —— 这是本设计最容易做砸的地方，
   §六.4 的互链是硬要求，不是可选项。
5. **分期是手写的。** 新增赛道或阶段时，`data/journey.json` 不会自动更新，
   靠 §九 的第 1 条守卫把它逼出来（漏了就红）。
