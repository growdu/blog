# 审校：从两地三中心到OceanBase的多地多中心 - 墨天轮

- 原文：`docs/cluster/从两地三中心到OceanBase的多地多中心 - 墨天轮.md`
- 范围：全文
- 目标读者：金融行业的 DBA / 架构师，想搞清楚「两地三中心」到底是个什么
  口径的架构，以及 OceanBase 怎么落地
- 一句话定位：用监管要求 + 容灾取舍两条线，把 OceanBase 的多副本部署方式
  讲成「为了拿到 RPO = 0 而做的工程选择」
- 核心判断：**结论方向是对的，落地口径已经过时**——文章赖以展开的
  「灾难恢复六个等级」引自 GB/T 20988-2007，而该标准已于 2026-01-01 废止；
  部署方案名、副本分布口径、RTO 数字三处都与 OceanBase 官方当前文档
  对不上；此外这是一篇 **OceanBase 官方在 CSDN 发布的文章**（CC BY-SA），
  仓库里既没署名也没标来源，结尾还把开头整段贴了一遍
- 审校状态：建议中

## 优先修改

   - 原因：涉及事实，必须可回溯；这是全文的骨架，骨架错了下面的例子都站不住。

3. 位置：L120（RTO 数字与官方文档不一致）
   - 问题：原文「RTO: 不管是同城还是异地，只要是不丢数据的切换，都可以做到
     **一分钟内**完成。丢数据的切换也可以在数分钟之内完成。」
     官方文档写的是：「多副本高可用解决方案基于 Paxos 协议实现，在少数派副本
     不可用情况下，能够自动恢复服务，并且不丢数据，**始终保证 RTO 在 8 秒内，
     RPO 为 0**」；方案表里三种方案的 RTO 一律标「8s 内」。
     1 分钟 → 8 秒，差了一个数量级。
   - 建议：改成 8 秒内；若确实是另一个量纲（比如「业务侧恢复」而非
     「副本切换」），把口径写出来。

5. 位置：L7 / L9-L13（引用的是已废止的国标）
   - 问题：L7 引《商业银行数据中心监管指引》第七条，指名

     被 GB/T 20988-2025《网络安全技术 信息系统灾难恢复规范》（2025-06-30 发布、

     注意：指引本身（银监办发〔2010〕114号）并未废止，废止的是它引用的国标。
   - 建议：加一句版本说明——「本文按 GB/T 20988-2007 的六级口径展开；该标准

     废止标准做合规对标。

## 事实待核

- [x] L7 的第七条引文与原文逐字一致 —— 银监办发〔2010〕114号
  《商业银行数据中心监管指引》第七条：「总资产规模一千亿元人民币以上且跨省
  设立分支机构的法人商业银行，及省级农村信用联合社应设立异地模式灾备中心，
  重要信息系统灾难恢复能力应达到《信息安全技术信息系统灾难恢复规范》中定义的
  灾难恢复等级第5级（含）以上；其他法人商业银行应设立同城模式灾备中心并实现
  数据异地备份，重要信息系统灾难恢复能力应达到《信息安全技术信息系统灾难恢复
  规范》中定义的灾难恢复等级第4级（含）以上。」
- [x] L11-L13 的等级数值与国标一致 —— GB/T 20988-2007 等级表（华为云
  《RTO与RPO》、天翼云《灾难恢复能力等级》两页表格一致）：4 级 RTO 数小时至
  2 天 / RPO 数小时至 1 天；5 级 RTO 数分钟至 2 天 / RPO 0 至 30 分钟；
  6 级 RTO 数分钟 / RPO 0。正文写的「RPO数小时到一天，RTO数小时到两天」
  「RPO小于30分钟，RTO数分钟到两天」「RPO = 0, RTO数分钟」逐项对得上。
- [x] L61 的 Oracle 最大保护模式描述成立 —— Oracle 官方《Data Guard Concepts
  and Administration》：「To ensure that data loss cannot occur, the primary
  database **shuts down**, rather than continue processing transactions, if it
  cannot write its redo stream to at least one synchronized standby database.」
  与「当热备不可用的时候，主库也不可写入，可用性降低」一致。
- [x] L84 / L89 的 2+2+1 副本数与成员变更逻辑自洽 —— 深圳两个机房各 2 个副本
  + 上海 1 个 = 5；深圳 2 机房故障时剔除其 2 个副本，剩 3 个，与正文一致。
- [x] L103 的机器利用率算式成立 —— 主备 2 份资源给 1 份写能力 = 1/2；
  OceanBase 3 份资源给 2 份写能力 = 2/3；(1/2) ÷ (2/3) = 3/4，与正文一致。
- [x] L78 / L120 与官方当前文档不一致 —— 官方《容灾部署方案》（社区版
  V4.0.0，文档页标注更新时间 2026-06-01）方案表只有「同机房三副本 /
