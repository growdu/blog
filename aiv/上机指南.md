# 上机指南：在一台 Linux 机器上跑通出片流水线

这条流水线原来只在 macOS 上跑得起来——不是因为代码难移植，而是因为三件事
被默认了：**字体**、**素材**、**依赖**。三件事都补齐之后，一台干净的
Ubuntu/Debian 机器 clone 完就能直接出片。

```bash
git clone https://github.com/growdu/blog.git
cd blog

# 装依赖（需要 root）
sudo bash aiv/pipeline/scripts/bootstrap_linux.sh

# 自检：这台机器还缺什么、怎么补
cd aiv/pipeline && make doctor

# 出片
make EP=row-lock align validate brand render compose mix-verify
```

---

## 一、装什么

`bootstrap_linux.sh` 按包管理器（apt / dnf / pacman / zypper）装齐：

| 类别 | 包 | 为什么 |
| --- | --- | --- |
| 外部工具 | `ffmpeg`（含 `ffprobe`） | 编码、拼接、混音、抽帧 |
| 外部工具 | `fontconfig` | Linux 上 cairo 靠它按字体族名解析字体 |
| 外部工具 | `make` | 流水线的入口 |
| 中文字体 | `fonts-noto-cjk` | **渲染必需**，见 §三 |
| Python | `pycairo` `numpy` `Pillow` `scipy` `pytest` | 见 `aiv/pipeline/requirements.txt` |

Python 依赖**优先用系统包**（`python3-cairo` 等）：pip 编译 pycairo 需要
cairo 的开发头文件，自己编译容易踩坑。系统包装不上时脚本会自动退回 pip。

装完必须自检一遍：

```bash
cd aiv/pipeline
make doctor
```

`doctor` 会逐项报「环境 / 素材 / 可选工具」，缺什么给什么，**每条都带可执行的
修复命令**（装哪个包、跑哪条合成命令）。有硬性缺失时退出码非 0。

## 二、素材从哪来

**出片必需的输入已经入库**，clone 完就在：

| 素材 | 为什么必需 |
| --- | --- |
| `aiv/narration_<期号>.mp3` × 6 | 没有它就对齐不了、渲染不了 |
| `aiv/ddl-voiceover.mp3` | 音色参数（pitch / speed）是相对它标定的 |
| `aiv/growdu2.jpeg` | 形象原型——重新生成立绘的唯一来源 |
| `aiv/character/growdu_character_2k_nobg.png` | 小象立绘，合成进画面用这个 |
| `aiv/brand/clips/growdu_{intro,outro}_3s_1080p.mp4` | 品牌片头片尾 |
| `aiv/brand/audio/{intro,outro}_mix.wav` | 片头片尾的成品音轨 |
| `aiv/music/tracks/series-{bed,motif}-01.wav` | 正文铺底 BGM 与片头片尾闭环（授权 CC0-1.0） |

**不入库的是产物**：成片（`out/`）、片段（`build/`）、时间轴（`storyboard_*.json`）、
发布包、旁本（`*.spoken.txt`）。它们由上面的素材算出来，跟着素材走。

`aiv/pipeline/tests/test_assets_are_tracked.py` 盯着这件事：必需素材一旦被
`.gitignore` 拦掉、或者被 `git rm --cached` 了，测试立刻变红。

## 三、和 macOS 的差异（**只有一条，但它影响画面**）

**字体不同，所以像素不同。**

macOS 自带 `PingFang SC`；Linux 上没有等价物——PingFang 是 Apple 的授权字体，
不能随仓库分发。Linux 上退到开源的 `Noto Sans CJK SC` / 思源黑体。

| | macOS | Linux |
| --- | --- | --- |
| 字体 | `PingFang SC` | `Noto Sans CJK SC`（思源黑体） |
| 同一段文字的像素 | A | **与 A 不同** |
| 文案、字幕、版式 | 一致 | 一致 |
| 逐像素基准守卫 | 跑 | **跳过并说明原因** |

这条差异是**已知且被记录的**：`aiv/pipeline/tests/fixtures/scene_baseline.json`
的 `capture.font` 记着基准是在哪款字体下抓的，换字体时测试会跳过并说明
「基准绑在字体上，这里测不出东西」，而不是红、也不是假装绿。

想要指定别的字体就用环境变量：

```bash
AIV_FONT_FAMILY="Source Han Sans SC" make EP=row-lock render
```

验收口径按**视觉等价**（同一套视觉系统、文案一字不变），不按逐像素一致。

### 另两处 macOS 痕迹

- `aiv/brand/scripts/make_audio.sh` 用了 macOS 自带的 `say` 合成片头片尾旁白，
  **Linux 上跑不了**。它是历史路径：现行做法是 `make_audio_brand.py`（纯 ffmpeg，
  跨平台），出片链路不需要这个脚本。
- `aiv/brand/scripts/fix_plates.py` 原本硬编码 `/System/Library/Fonts/` 下的
  Avenir Next / Hiragino Sans GB，现在参数化了：macOS 用系统字体，Linux 退到
  DejaVu Sans / Noto Sans CJK SC。

## 四、哪些脚本在 Linux 上跑不了（以及为什么没关系）

| 脚本 | 状态 | 说明 |
| --- | --- | --- |
| `aiv/voice/scripts/synthesize_narration.py` | **需要联网** | 调 MiniMax TTS（`mcode-tools` CLI）。已入库的旁白不必重新合成 |
| `aiv/character/scripts/generate_character.py` | **需要联网** | 调图像生成。形象已入库，不必重新生成 |
| `aiv/music/scripts/fetch_music.py` | **需要联网** | 从 archive.org 下载曲库。曲库已入库，不必再下 |
| `aiv/brand/scripts/make_audio.sh` | **macOS 专有** | 用 `say` 合成旁白，历史路径 |

也就是说：**出片链路（align → validate → brand → render → compose → mix-verify）
在 Linux 上完全离线可跑**。只有「重新生成素材」才需要联网与 MiniMax 账号。

## 五、常见问题

**Q：渲染时报「找不到可用的中文字体」。**
装 `fonts-noto-cjk`，然后 `fc-cache -f`；或者把任一中文字体放进
`~/.local/share/fonts/` 再 `fc-cache -f`。也可以用 `AIV_FONT_FAMILY` 指定族名。

**Q：`make: python: No such file or directory`。**
`make PY=python3 ...`（或直接 `make doctor`，它会告诉你缺什么）。仓库里的
Makefile 会自动探测 `python3`，看到这条说明你的 Makefile 是旧版。

**Q：`doctor` 说某期旁白缺失。**
它会给出合成命令。跑那条命令即可（需要联网 + `mcode-tools`）。

**Q：跑出来的画面和 macOS 上不一样。**
正常——字体不同，见 §三。文案、字幕、版式规则都一致。
