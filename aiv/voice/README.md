# Growdu 音色

后续视频旁白统一使用这套音色。**规范见 [`../形象与音色规范.md`](../形象与音色规范.md) §2**。

## 定稿参数

```json
{
  "voice_id": "Chinese (Mandarin)_Radio_Host",
  "voice_name": "电台男主播",
  "pitch": -1,
  "speed": 1.33,
  "emotion": "neutral"
}
```

对标参照：`aiv/ddl-voiceover.mp3`。实测基频偏差 **+0.1 半音**、
F2 偏差 +31 Hz、动态跨度 107 Hz vs 参照 102 Hz。

## 试听样本

| 文件 | 配置 | 说明 |
| --- | --- | --- |
| `voice_sample_radio_s133_pm1.mp3` | pitch −1 / speed 1.33 | **定稿**，完整口播稿 |
| `voice_sample_radio_s135_pm2.mp3` | pitch −2 / speed 1.35 | 备选一，动态跨度最接近参照 |
| `voice_sample_southern_s150.mp3` | 南方小哥 / speed 1.5 | 备选二，F1 吻合但听感过于平直 |

## 合成

```bash
cd aiv/voice
python3 scripts/synthesize_narration.py --text "大家好，我是growdu。"
python3 scripts/synthesize_narration.py --script 字幕.md --out narration.mp3
```

依赖 `mcode-tools` CLI（先加载 `mcode-tools-master` skill）。

## ⚠️ 换稿必须重新定标

`pitch` / `speed` 是相对参照稿标定的。口播稿换了（字数、断句不同），语速和
音高分布都会变，直接套用会偏。

重新定标方法（规范文档 §2.1）：

1. 测参照稿的基频 F0 中位、F1/F2 共振峰、频谱重心、语速
2. 用候选音色合成同一段文本，跑同样的四项测量
3. 按 `|ΔF0半音|×3 + |ΔF1|/30 + |ΔF2|/120 + |Δ重心%|/5 + |Δ语速%|/4` 排序
4. 在真实口播稿上做 speed × pitch 网格微调，收敛到时长与语速都对得上

### 这把尺子：`scripts/measure_voice.py`

```bash
cd aiv/voice
# 量参照稿
python3 scripts/measure_voice.py --path ../ddl-voiceover.mp3 --chars 226
# 量候选稿，并与参照稿逐项比
python3 scripts/measure_voice.py --path 候选.mp3 --chars 255 \
    --ref ../ddl-voiceover.mp3 --ref-chars 226
```

**只认差值**：本脚本的测量定义与当初定标时未必一致，绝对值不能直接对规范
§2.1 表里的数（脚本头部的表列了各处口径差异）。参照稿与候选稿用同一把尺子量，
看差多少。

## 定标：PostgreSQL 18 并行逻辑解码（EP01）

口播稿 255 字（10 句），旁白落在 `aiv/narration_pg-parallel-decode.mp3`
（媒体产物，不入库）。

在 **pitch −1 / speed 1.33**（即定稿参数）下实测，与参照稿对照：

| 指标 | 参照稿 | 本期 | 差值 |
| --- | --- | --- | --- |
| 时长 | 29.27 s | 33.16 s | 字数不同所致 |
| 语速 | 7.72 字/秒 | **7.69 字/秒** | −0.4 % |
| F0 中位 | 118.1 Hz | **118.3 Hz** | +0.03 半音 |
| 频谱重心 | 1184 Hz | 1439 Hz | +21.6 % |

**结论：定稿参数不变**，不用改 pitch / speed。语速与基频这两项可靠指标已经贴住
参照稿。网格里 `speed 1.37` 的排序分略低，但它赢在频谱重心上——重心主要由
**文本内容**决定（同音色的旧定稿样本在这一项上就偏低 18 %），不能当选参依据。

两点必须记住：

- **F1/F2 对选参没有影响**。它由声道长度决定，同一个音色下不随 pitch / speed 变，
  只在换音色时才有区分度。
- **合成不是确定性的**。同参数连合成三次，时长相差 ±3.3 %、语速 ±0.24 字/秒、
  F0 ±0.69 半音。所以定标要挑「量出来最贴参照的那一条实例」，
  别把参数当成能复现出同一条音频的承诺。

## 定标：CSN 全序（EP02）

口播稿 267 字（10 句），旁白落在 `aiv/narration_csn-total-ordering.mp3`
（媒体产物，不入库）。

同样的做法：**定稿参数不变**，合三条实例，量出来挑最贴参照的那一条。

| 指标 | 参照稿 | EP01 | EP02（采用） |
| --- | --- | --- | --- |
| 时长 | 29.27 s | 33.16 s | **35.32 s** |
| 语速 | 7.72 字/秒 | 7.69（−0.4 %） | **7.56（−2.1 %）** |
| F0 中位 | 118.1 Hz | 118.3（+0.03 半音） | **114.7（−0.50 半音）** |
| 频谱重心 | 1184 Hz | 1518（+28 %） | **1435（+21 %）** |

三条候选的排序分在 8.06 ~ 8.19 之间，差距主要来自频谱重心——
而重心由**文本内容**决定，不能当选参依据。只看可靠的两项（语速、基频），
候选 2 最好：语速 −2.1 %、基频 −0.50 半音。

也试了 speed 网格（1.35 / 1.37）：语速分别落在 −5.5 % 与 −3.5 %，
还在合成随机性的抖动带里（见下），**没有比 1.33 更好**，所以参数不动。

> EP02 的语速比 EP01 略低是合理的：这期稿子里的拉丁词多
> （`openGauss`、`CSN`、`PostgreSQL 18`），而字数口径按字符数算，
> 字母多的词被算成了好几个字，实际语速比这个比值看起来要快。

**为什么必须挑实例**：合成不是确定性的。同一参数连合成三次，
时长相差 ±3.3 %、语速 ±0.24 字/秒、F0 ±0.69 半音。
定标要挑「量出来最贴参照的那一条实例」，别把参数当成能复现出同一条音频的承诺。
