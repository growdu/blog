## 一、目标与边界

### 1.1 目标

把「成片 → 平台 → 观众落地」这条链上的三个断点补上，让站点成为这个 IP 的
**唯一永久主页**：

| 断点 | 现状（2026-11-14 实测） | 本契约要达成的 |
| --- | --- | --- |
| **① 落地页不存在** | 6 期里 5 期的 `url` 指向 `/2026/11/12/life/aiv/`，该路径返回 **HTTP 200 + 120526 字节的首页**（服务端对任何未知路径软 404 回首页）；剩下 1 期指向一篇**母稿**而不是期号页 | 每期有**唯一**落地页，URL 由 slug 派生，**不可手写** |
| **② 母稿与成片不绑定** | 六篇母稿全部已上线，但 **0 篇**嵌入视频、**0 篇**提到期号 | 母稿页上出现期号区块：视频 + 字幕 + 各平台链接 + 本期机制图 |
| **③ 站点没有 IP 骨架** | 569 篇埋在 33 个平级分类里；菜单无 IP 入口；`atom.xml` 20 条 entry、**0 个 `<enclosure>`** | 系列页 + 期号页 + 带 enclosure 的 feed + 导航入口 |

### 1.2 非目标（本期明确不做）

| 不做 | 原因 |
| --- | --- |
| **成片 mp4 上站点托管** | 成片 5~6 MB/期，站点不承担视频带宽；沿用 [00](00-架构设计.md) §9.1「视频本体不在站点托管」 |
| **站内播放器** | 同上；期号页给 iframe（平台播放器）+ 外链，不自建播放能力 |
| **YouTube 接入** | `publish/capabilities/` 无 `youtube.toml`，主体与频道均未建；本期只在矩阵里留位 |
| **改主题 layout** | 沿用 [00](00-架构设计.md) §9.1 纪律：**不新增主题 layout**，一切经 `tools/patch-theme.py` 的 marker 幂等注入 |
| **选片头 / 选题材 / 选平台** | 属契约五、契约六与《选题库》 |
| **做「痛点排查」档的内容规划** | 属《运营手册》§5.1 的配比问题；本文只保证**这类内容有地方落** |

### 1.3 一条贯穿全文的原则

> **落地链接是契约的一部分，不是文案的一部分。**
> 「完整版与引用见 growdu.cn」这句话一旦写进 B站/视频号/抖音的简介，
> 它就是一个**对观众的承诺**。承诺必须由机器守住，不能靠人记得改。

（这条继承自 [00](00-架构设计.md) §三 的不变量三「不静默成功」。）

### 1.4 三条待拍板决定

本文按下列默认值写。**任一条改掉，只影响本文对应小节 + 一条测试**，
不动其余结构——这是把它们单列出来的原因。

| # | 决定 | 默认值（本文采用） | 备选 | 影响面 |
| --- | --- | --- | --- | --- |
| **D1** | 期号页的 URL 形态 | **母稿文章页即期号页**（方案 A）：沿用 Hexo permalink `/2026/11/15/database/postgresql-row-lock-deep-dive/`，页面上加期号区块 | 方案 B：独立页 `/podcast/<slug>/`，母稿只链接过去 | 决定 §四、§五、§七 的全部路径；方案 B 多一份内容与一处 SEO 重复 |
| **D2** | 站点是否托管旁白音频 | **托管旁白 mp3**（`aiv/narration_*.mp3`，六期合计约 3.1 MB，已入库），**不托管成片 mp4** | 不托管音频 → **不做 RSS**，feed 只做文章型 | 决定 §八 是否成立；RSS 的 `<enclosure>` 必须是自己域名下的稳定音频直链 |
| **D3** | 期号区块放在母稿正文**之前**还是**之后** | **之前**（正文首屏就是视频 + 本期钩子 + 机制图） | 之后（保持母稿纯阅读体验） | 决定 §四.2 的区块顺序 |

## 二、现状盘点（2026-11-14 实测）

### 2.1 断链的准确位置

`aiv/publish/<EP>.json` 的 `url` 字段在 [契约六](07-视频发布契约.md) §4.3 里的定义是
「站点详情页地址。**给了**就在发布文案末尾附上」——必填列是「—」，**没有任何校验**。

于是六期的实际状态是：

| 期 | manifest 里的 `url` | 线上实际返回 | 是否是期号页 |
| --- | --- | --- | --- |
| EP01 `pg-parallel-decode` | `https://growdu.cn/2026/11/12/life/aiv/` | 200 / 120526 字节 / 首页 | ❌ |
| EP02 `csn-total-ordering` | `https://growdu.cn/2026/11/12/life/aiv/` | 200 / 120526 字节 / 首页 | ❌ |
| EP03 `wal-interleave` | `https://growdu.cn/2026/11/12/life/aiv/` | 200 / 120526 字节 / 首页 | ❌ |
| EP04 `parallel-apply` | `https://growdu.cn/2026/11/12/life/aiv/` | 200 / 120526 字节 / 首页 | ❌ |
| EP05 `structured-ddl` | `https://growdu.cn/2026/11/12/life/aiv/` | 200 / 120526 字节 / 首页 | ❌ |
| EP06 `row-lock` | `https://growdu.cn/2026/10/15/database/postgresql-row-lock-deep-dive/` | 200 / 该母稿正文 | ❌（是母稿，无期号区块） |

> **软 404 的准确行为**：`https://growdu.cn/this-page-does-not-exist-xyz/` 返回
> **HTTP 200** + **120526 字节**首页 HTML。`curl -o /dev/null -w "%{http_code}"`
> 探活会得到 200，**看起来一切正常**。这是本条断点能长期存在而没被发现的原因。

**已发出的唯一一条**（EP06）在 B站简介末尾写着：

```
完整版与引用见 growdu.cn
```

这句话指向一篇 63,368 字、但**看不出是视频底稿**的技术长文——
没有期号、没有视频、没有「这是第 6 期」。

### 2.2 六篇母稿的线上状态

母稿全部已发布（`tools/sync-hexo.py` 编译进 `source/_posts/`），但：

| 检查项 | 结果 |

| 嵌入 `<video>` / `<audio>` | **0 / 6** |
| 提到期号（`EP0x`） | **0 / 6** |
| 提到成片在哪 | **0 / 6** |

**母稿在站上，但母稿和成片之间没有任何绑定关系。**

### 2.4 站点展示层的三处结构性缺失

承 [00](00-架构设计.md) §2.2，此处只补该文档之后的实测结论：

| 缺失 | 2026-11-14 实测 |

`docs/` 全树 621 篇的**源码路径密度**（每千字，去重后）：

| p50 | p75 | p90 | max |
| ---: | ---: | ---: | ---: |
| 0.00 | 0.00 | **0.39** | 3.03 |

即：**只有约 10% 的文章带源码路径**。这既是「技术深度」的真实分布，

## 三、概念模型与目录

### 3.1 三层：母稿 / 期号页 / 切片

```
docs/<分类>/<名>.md                 母稿（唯一真相，不变量一）
   │ sync-hexo.py（编译 + 契约透传）
   ▼
source/_posts/**                    内容单元 · content_id = 相对 source/_posts 的路径去后缀
   │
   │  ┌───────────────────────────────────────────────┐
   │  │  期号区块（front matter 透传 + partial 渲染）   │  ← 本契约新增
   │  │  视频 iframe / 钩子 / 机制图 / 字幕 / 平台链接   │
   │  └───────────────────────────────────────────────┘
   ▼
growdu.cn/2026/11/15/database/postgresql-row-lock-deep-dive/
   │        （方案 A：母稿页即期号页）
   │        （方案 B：/podcast/<slug>/  ← D1 的备选）
   ▼
publish/outbox/<EP>__<平台>.json     发布结果快照（落地 URL 从 content_id 派生，不手写）
```

**依赖方向只有一处接缝**：期号区块由 `publish/publishkit/` 提供**数据**，
由 `tools/patch-theme.py` 注入**渲染位**。主题文件不改（沿用 [00](00-架构设计.md) §9.1）。

### 3.2 目录

```
publish/publishkit/
  episode.py          【新增】期号内容单元的解析与落地 URL 派生
  evidence.py         【新增】证据密度检查（§六）
  linkcheck.py        【新增】落地链接可达性守卫（§五.3）

source/_posts/<分类>/<名>.md
  front matter:
    episode: pg-parallel-decode      【新增】有值 = 这篇是某一期
    episode_no: 1                    【新增】期号（展示用）
    series: 机制族                   【新增】系列名
    episode_hook: 一句话钩子           【新增】母稿的钩子（与口播稿一致）
    episode_sources:                  【新增】源码路径清单（§六）
    episode_repro:                    【新增】可复现命令清单（§六）
    episode_media:                    【新增】成片与旁白的相对路径 + 平台链接
    description: …                    【契约一已有】期号页必须有
    cover: …                         【契约一已有】期号页必须有

source/_data/podcast_index.json      【新增】构建期生成的系列索引（期号列表）
source/podcast/index.md              【新增】系列页（构建期生成）
source/feed.xml                      【新增】播客 feed（带 enclosure）
```

> **`/source/` 整个目录是 gitignore 的生成目录**（`.gitignore` 里 `/source/`，
> 只放行 `source/all/` 与 `source/recommended/`）。
> 它的内容由 `tools/sync-hexo.py` 从 `docs/` 编译出来，**不是仓库里的事实**。
>
> 因此：
>
> | 东西 | 它的家 | 是否入库 |
> | --- | --- | --- |
> | 期号 front matter | **`docs/<分类>/<名>.md`** | ✅ 入库 |
> | 期号区块的渲染位 | `themes/matery/layout/_partial/`（经 `patch-theme.py` 注入） | ✅ 入库 |
> | `source/_posts/**` 编译产物 | `sync-hexo.py` | ❌ 生成 |
> | `source/podcast/index.md`、`source/feed.xml` | 构建期生成 | ❌ 生成 |
> | `public/**` | `hexo generate` | ❌ 生成 |
>
> **写期号数据要写 `docs/`，不是 `source/`。** 这一点与
> [00](00-架构设计.md) 的不变量一（母稿唯一）一致。

### 3.3 依赖方向

| 模块 | 依赖 | 不得依赖 |
| --- | --- | --- |
| `publishkit/episode.py` | `contract.py`（front matter 契约） | AIV、平台 adapter |
| `publishkit/evidence.py` | 无（纯文本统计） | 被检内容本身 |
| `publishkit/linkcheck.py` | `episode.py` | 站点构建产物 |
| `tools/patch-theme.py` | 无 | `publishkit`（只注入渲染位，数据由构建期透传） |

## 四、契约七之一：期号页

### 4.1 标识

**期号内容单元 id = AIV 的期号 slug**（沿用 [契约六](07-视频发布契约.md) §4.1，
不另造编号）。slug 已经是契约、旁白、时间轴、片段目录、成片文件名的共同主键。

### 4.2 页面必填区块

方案 A 下，期号区块渲染在母稿正文**之前**（D3）。区块结构：

| 序 | 区块 | 内容 | 数据来源 |
| --- | --- | --- | --- |
| 1 | **期号头** | `EP01 · openGauss 的并行逻辑解码` + 一句话钩子 | `episode_no` / `episode` / `episode_hook` |
| 2 | **播放器** | 平台 iframe（横版）+ 竖版外链 + 「在 B站看 / 在视频号看 / 在抖音看」 | `episode_media` |
| 3 | **本期机制图** | 母稿中该期的主图（mermaid 或图片），**带图注** | `episode_media.diagram` |
| 4 | **速览** | 时长 / 画幅 / 语速 / 出处与许可证 / 更新日期 | `episode_media` |
| 5 | **字幕** | 折叠的完整字幕（`<details>`），供检索与引用 | `episode_media.subtitle` |
| 6 | **源码与复现** | 源码路径清单 + 可复制粘贴的命令块 | `episode_sources` / `episode_repro` |
| 7 | **系列导航** | 上一期 / 下一期 / 本系列全部期号 | `podcast_index.json` |

### 4.3 front matter 字段表

新增字段全部**可选**——没有 `episode` 键的普通文章不参与期号体系，
不因为缺字段而报错（沿用 [00](00-架构设计.md) §10.1「未知顶层字段告警不 fail」的宽松口径，
但**已知字段写错值要 fail**）。

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `episode` | str | — | slug 形式 `^[a-z][a-z0-9-]*$`；**必须与 `aiv/contracts/<EP>.json` 的 `episode` 逐字相同** |
| `episode_no` | int | ✅（有 `episode` 时） | ≥ 1；同一 `series` 内**不得重复** |
| `series` | str | — | 系列名；同一系列内 `episode_no` 必须连续（1,2,3…），**不得跳号** |
| `episode_hook` | str | ✅（有 `episode` 时） | 20~60 字；**必须出现在该期口播稿里**（防止钩子与片子对不上） |
| `episode_sources` | list[str] | — | 源码路径，每条必须真实存在于 `docs/` 或 `aiv/` 下 |
| `episode_repro` | list[str] | — | 可复制命令，每条必须非空且以 `$ ` 或可执行命令开头 |
| `episode_media.horizontal` | str | ✅（有 `episode` 时） | 相对路径；指向成片或平台外链 |
| `episode_media.vertical` | str | — | 竖版路径（抖音那一档） |
| `episode_media.platforms` | dict | — | `{"bilibili": "<BV号或URL>", "channels": "<链接>", "douyin": "<链接>"}` |
| `episode_media.subtitle` | str | — | 字幕文件相对路径 |
| `episode_media.diagram` | str | — | 机制图相对路径 |
| `episode_media.duration_s` | float | ✅（有 `episode` 时） | > 0；**必须与 `aiv/storyboard_<EP>__nobrand.json` 的实测值一致** |
| `episode_media.license` | str | — | 出处与许可证声明（如 `PostgreSQL BSD` / `openGauss Mulan PSL v2`） |

### 4.3.1 透传通道：字段必须能过两道白名单

新字段写在 **`docs/<分类>/<名>.md`** 的 front matter 里，但要渲染成期号页，
必须穿过两道**白名单**——两道都只认自己列出来的字段，**没列的一律丢弃**：

| 白名单 | 位置 | 现状 | 要加的字段 |
| --- | --- | --- | --- |
| 编译期 | `tools/sync-hexo.py:544` `PASSTHROUGH_SCALAR_FIELDS` / `:543` `PASSTHROUGH_LIST_FIELDS` | 有 `tldr` / `description` / `difficulty` / `cover` / `kind` 等 | `episode`、`episode_no`、`series`、`episode_hook`、`episode_repro`、`episode_media` |
| 契约层 | `publish/publishkit/contract.py:110` `PASSTHROUGH_FIELDS` | 同上（另一份清单） | 同上 |

> **两份清单要一起改。** 只改一处，字段就在中途被丢掉——
> 而且是**静默丢掉**：页面照常渲染，只是期号区块是空的。
> 这正是 [00](00-架构设计.md) §2.2 记的「展示元数据通道是断的」那种故障，
> 只不过这次是**新加**的字段。§十二 的集成测试必须断言
> 「`docs/` 里写了 → 构建产物里看得见」。

### 4.4 校验规则

由 `publishkit/episode.py` 负责，**缺一个必填字段就报错，绝不静默补默认值**：

1. `episode` 必须与契约一致；
2. `episode_no` 在同一 `series` 内唯一、且系列内连续；
3. `episode_hook` 必须出现在 `aiv/字幕-<主题>.md` 的口播段里；
4. `episode_sources` 的每条路径必须真实存在；
5. `episode_media.duration_s` 必须与 storyboard 实测值一致（**以 storyboard 为准**，
   见 §十六 的口径漂移）；
6. `episode_media.platforms` 里出现的平台，必须在 `publish/capabilities/` 里有同名能力声明。

## 五、契约七之二：落地 URL 的派生与守卫

### 5.1 为什么必须派生

现状 `url` 是**手写常量**。手写常量有三个必然失效的路径：
slug 改了忘了改、母稿换了路径忘了改、期号页还没生成就先把链接发出去了。
**第三条已经发生**——5/6 的链接指向一个从未存在的路径。

### 5.2 派生规则

```
落地 URL = SITE_ROOT + "/" + permalink(content_id)
```

| 项 | 规则 | 来源 |
| --- | --- | --- |
| `content_id` | 相对 `source/_posts/` 的路径去后缀 | [00](00-架构设计.md) §三 |
| `permalink` | `:year/:month/:day/:title/`（按文章 front matter 的 date） | `_config.yml` 的 `permalink` |
| `SITE_ROOT` | 主站 `""`，镜像 `/blog` | `tools/site_root.py`（已存在） |
| 方案 B 覆盖 | 若 D1 选方案 B：`/podcast/<episode-slug>/` | 本文 §一.4 |

**`url` 字段从 manifest 里删掉**，改为发布时从 `content_id` 派生。
保留字段但**改为只读派生值**（写进 outbox 快照是为了可回溯，不作为输入）。

### 5.3 守卫：链接必须真的能打开

**这是本契约最重要的一条。** 三道闸门，逐级加严：

| 闸门 | 什么时候跑 | 判据 |
| --- | --- | --- |
| **G1 结构闸**（每次提交） | `publishkit/episode.py` 校验 | 有 `episode` 的文章，其 `content_id` 派生的落地 URL 在 `source/_posts/` 下**必须存在对应文件** |
| **G2 站内锚点闸**（每次提交） | 现有 `tools/check-built-links.py` 扩展 | 构建产物里期号页之间的链接**不得失效**（页内锚点 + 跨页链接） |
| **G3 线上可达闸**（发布后 + 每日） | `publishkit/linkcheck.py` | 对**每个已发布**的期号（outbox 里 `published_url` 非空的），发真实 HTTP 请求，断言 **200** 且响应体含该期 slug |

> **G3 为什么必须打真实请求**：本条断点的特征就是「看起来是 200，实际是首页」。
> 任何只看本地文件、只看 URL 字符串格式的检查都会漏掉它——
> **软 404 的返回码就是 200**。
> G3 是集成测试（要联网），默认在 CI 里跑；离线环境下**明确 skip 并说明原因**，
> 不许假装绿。

### 5.4 发布文案里的链接

契约六 §4.3 说 `url` 给了就在文案末尾附上。改为：

- 落地 URL **由派生得到**，文案尾部照旧附上（格式不变，观众无感）；
- 但**发布动作本身**要过一次 G3：链接不通就不许把状态写成 `published`。
- 状态机：新增 `published_unreachable` —— 已发出但落地页不通。
  这是**真实存在的状态**，不该被压成 `published`。

## 六、契约七之三：证据密度（技术感的机器判据）

### 6.1 为什么需要它

「技术感」现在只存在于《人格规范》的文字里，而那本规范守的是**口播稿**。
观众看到的是**母稿页**。实测证据密度（2026-11-14，站内正文）：

| 页面 | 可读字数 | 源码文件路径（去重） | 函数名（去重） |
| --- | ---: | ---: | ---: |
| AIV meta 文章（线上） | 6,767 | **0** | **0** |
| 逻辑复制全链路（站内标杆） | 76,201 | **34** | 多个 |

> 技术感不是篇幅，是**读者能跟着走一遍**的可复现性。
> 《人格规范》§1 已经写对了「信任来自可追溯」，但这条规则目前只管口播稿。
> 本节把它落到**母稿页**上，并做成机器可检。

### 6.2 阈值表

阈值**全部来自真实分布**，不凭感觉定。依据栏写清「这个数字为什么是这个数」。

| 规则 | 指标 | 阈值 | 为什么是这个数 |
| --- | --- | --- | --- |
| **EV-01** | 源码路径数 | **≥ 6** | 六期母稿现有最小值是 6（EP03 `wal-interleave`），取**存量全部达标线**，不卡住已有资产 |
| **EV-02** | 函数/结构体引用数 | **≥ 1** | 同上，六期现有最小值是 1（EP03 / EP06）。只要求「有」，不设上限 |
| **EV-03** | 可复现命令数 | **≥ 1** | **现状几乎为 0**（六期 1~23 不等，中位数 6.5，但 `wal-interleave` 仅 5、`row-lock` 仅 1）。这是**新增要求**，不是存量达标线 |
| **EV-04** | 机制图数 | **≥ 1** | 六期母稿 mermaid 数为 3~29，**全部达标**；取 1 是最低可接受线 |
| **EV-05** | 口播字数（长版） | **3,451 ~ 5,176** | 语速 **7.19 字/秒**（六期实测：241~256 字 / 32.436~35.424 s，均值 7.19 字/秒 = 431 字/分）× 长版时长 480~720 s |
| **EV-06** | 母稿字数 | **≥ 22,609** | `docs/` 全树 621 篇的字数 **p90 = 22,609**。六期母稿 20,974~81,262，**除 EP03 外全部 ≥ p90**（EP03 略低，属已知例外，须在期号页标注） |
| **EV-07** | 压缩比（母稿 ÷ 口播） | **≤ 25:1** | 长版目标区间是 4.4:1 ~ 6.6:1（母稿 22,609 ~ 81,262 ÷ 口播 3,451~5,176）。取 25 作为上限，留出 3~5 倍余量给「母稿更长但口播不必更长」的期 |

**两条阈值来源必须分开标注**：

| 类别 | 规则 | 处置 |
| --- | --- | --- |
| **存量达标线**（现状已满足） | EV-01 / EV-02 / EV-04 | 六期母稿全部满足，**守卫上线时不会把已有资产判红** |
| **新增要求**（现状为 0 或接近 0） | EV-03 / EV-05 / EV-07 | **只对新长版生效**；现有六期（35 秒档）豁免，豁免名单进代码常量并写清理由 |

> **EV-05 / EV-06 / EV-07 只对「长版」生效，不对现有六期生效。**
> 否则守卫上线第一天就会把六期全判红——那是自证式守卫，不是守卫。
> 豁免机制本身也要被测（§十二）。

### 6.3 检查对象

**只检查期号页（`episode` 键存在的文章）**，不检查全站 569 篇。
理由：§2.5 的分布显示全站只有 11.4% 的文章带深度标记，
对全站设阈值就是把守卫变成大面积噪声。

### 6.4 与《人格规范》的分工

| 规则 | 管谁 | 判据 |
| --- | --- | --- |
| 《人格规范》9 条（`aiv/pipeline/pyv/persona.py`） | **口播稿** | 营销腔禁词、机构自称、绝对化断言、能力域边界、量化依据、边界表达、方法论表达、句子宽度与长度 |
| 本文 EV-01 ~ EV-04 | **母稿页** | 源码路径 / 函数引用 / 可复现命令 / 机制图 |

两者**不重叠、不互相替代**。口径一致的地方：都要求「可追溯、可复现」，
但一个管片子、一个管落点。

### 6.5 技术感的第三个维度：来源与许可证

母稿页比视频更容易越界（贴更多代码、更具体的行号）。因此期号页**必须**有
`episode_media.license` 字段，写清这一期讲的是谁的什么、依据哪份公开材料。

沿用《运营手册》§8.1 的判断标准：

> 如果这个信息在官网 / 公开仓库 / 公开演讲里已经出现过，我讲它没问题；
> 如果只有内部同事知道，我讲它就有问题——即使技术上完全正确。

## 八、契约七之五：播客 feed

### 8.1 对 [00](00-架构设计.md) §9.1 的一处更正

> **原文**：「**视频本体不在站点托管。** 成片在 B站 / YouTube，站点只嵌 iframe + 给外链。」

这句在**成片 mp4** 上仍然成立，本文不改。**但它没有覆盖旁白音频**，
而 RSS 的 `<enclosure>` 必须是自己域名下的**稳定音频直链**——
B站/视频号都不提供可直接放进 `<enclosure>` 的音频地址。

因此更正为：

> **成片 mp4 不在站点托管；旁白 mp3 在站点托管。**
> 站点承担的是「文字 + 音频」的永久副本，视频流量仍然导给平台。

理由：旁白 mp3 **已经入库**（`aiv/narration_*.mp3`，7 个文件，六期约 **3.1 MB**），
是「出片必需的输入」而不是产物（与 `aiv/index.md` §四 的口径一致）——
托管它不增加仓库体积，只增加站点带宽。

### 8.2 feed 规格

| 项 | 值 | 依据 |
| --- | --- | --- |
| 路径 | `/feed.xml` | 与 `atom.xml` 并存（`atom.xml` 是博客 feed，`content: false`，不动） |
| 格式 | RSS 2.0 | `<enclosure>` 是 RSS 的原生能力，Atom 的 `link rel="enclosure"` 支持度差 |
| `<enclosure>` | `url` = 站点托管的 mp3 绝对地址；`type` = `audio/mpeg`；`length` = 字节数 | 三个属性缺一，部分阅读器会拒收 |
| `<guid>` | `growdu.cn/podcast/<slug>` | **必须稳定且不随日期变**（否则重发会变成新条目） |
| `<pubDate>` | 该期成片实测完成日 | 用 `storyboard` 的实测值，不用 manifest 里手写的日期 |
| 条目数 | 最近 20 期 | 与 `atom.xml` 的 `limit: 20` 一致 |
| `itunes:author` | growdu | — |

### 8.3 更新节奏是一条契约，不是一句口号

《运营手册》§6.3 定的是「每周 1 长 + 2 短 + 1 图文」。**那条节奏一旦写进系列页，
就是对观众的承诺。**

因此：

- 期号页与 feed 里**必须写明下一期的预计时间**（如「下期预计 2026-11-21」）；
- **承诺了就要兑现**：连续两期延期，系列页上改成「不定期更新」并说明原因，
  比悄悄延期好；
- 《运营手册》§9.3 已经有一条止损线（连续 8 周完播率 < 20% → 停 2 周改形式），
  **本文再加一条**：**连续 3 期母稿未上线 → 停止出片，先补母稿**。
  理由：母稿是唯一的永久资产，片子是切片；**先出片子后补母稿的顺序，
  正是本契约要修的那个错误的逆版本**。

## 九、平台形态矩阵（一核五形）

### 9.1 母版是核，其余是切片

| 形态 | 时长 | 内容 | 落点 | 现状 |
| --- | --- | --- | --- | --- |
| **母版** | 不限 | 机制 + 源码路径 + 调用链 + 边界 + 数字 + 可复现方法 | 站内期号页（唯一真源） | **无期号页**（母稿散落） |
| **深潜版** | 8~12 min | 母稿的讲述版 + 分 P + 章节 + 中英字幕 | B站 / YouTube | **只有 35 秒** |
| **图文版** | 8~12K 字 | 母稿改写，保留可复制代码块 + 路径 + 行号 | 公众号 | **无对期内容** |
| **精华版** | 90 s | 一个反直觉结论 + 一个数字 | 视频号 | 现有 35 秒**低于档位** |
| **钩子版** | 45 s | 前 3 秒抛反常识，竖版 9:16 | 抖音 | 竖版文件已出，**未发** |
| **双投版** | 图文 3K / 视频 6 min | 问题—方案—收益 | 头条号 | 未启动，**且有 1000 粉前置** |

### 9.2 时长的硬缺口

| 档位 | 需要口播字数 | 现有六期 | 缺口 |
| --- | ---: | ---: | ---: |
| 深潜版 8 min | 3,451 字 | 241~256 字 | **13.5×** |
| 深潜版 12 min | 5,176 字 | 241~256 字 | **20.2×** |
| 精华版 90 s | 1,294 字 | 241~256 字 | 5.1× |
| 钩子版 45 s | 647 字 | 241~256 字 | 2.5× |

> **35 秒那一档不是废品**——它是**钩子版**的素材（30~60 s 正是《运营手册》§1.3
> 给短视频定的档位）。问题是它现在被当成**唯一一档**用，
> 于是「机制」这一层完全没被发出去。
>
> 更要紧的是：**35 秒 + 强结论，在观感上无法与营销号区分。**
> 《人格规范》禁掉了营销腔的**词**，但禁不掉「短促结论」这个**形式**自带的营销感。
> 这是一条词表管不到的营销腔，只能靠**时长与形态分层**解决。

### 9.3 与《运营手册》§5.1 配比的关系

《运营手册》定的四类配比是：源码深潜 30% / 痛点排查 30% / 新特性首发 20% / 工具方法 20%。
**六期实况：源码深潜 1 期、新特性首发 5 期、痛点排查 0 期、工具方法 0 期。**

「痛点排查」是手册自己认定的「唯一一类用户带着问题来搜索的」「自然流量里转化率最高的一类」，
且**它不吃深度优势**（靠的是排查方法与检索能力）。

本契约只保证**这类内容有地方落**（期号页不挑类型），内容配比属手册范畴。

## 十、幂等与状态

### 10.1 状态落盘

沿用 [00](00-架构设计.md) §七 的三层键与 `publish/outbox/` 快照。期号侧的**新增状态**：

| 状态 | 含义 | 触发 |
| --- | --- | --- |
| `published` | 已发布且**落地页可达** | G3 通过 |
| `published_unreachable` | 已发布但落地页不通 | G3 失败；**人肉步必须先修链接** |
| `episode_drafted` | 期号页已生成、平台包已出、待人工发出 | 契约六 §7.3 的 `drafted` |

### 10.2 不静默成功

`published_unreachable` 的存在，是为了**让「发到哪儿了」这个问题有一个诚实的答案**。
当前 `publish/outbox/` 里 20 份快照的 `published_url` 有 18 份是 `null`，
只有 2 份（EP06 的 B站 / 视频号）有链接——**而那 2 份的落地页是母稿，不是期号页**。

## 十二、测试策略

### 12.1 三类测试

| 类 | 测什么 | 放哪 |
| --- | --- | --- |
| **单元** | URL 派生规则、证据密度统计、字段校验、豁免名单 | `publish/tests/test_episode.py` / `test_evidence.py` |
| **集成** | 真文章 → front matter → 期号区块渲染产物断言；真 outbox → 落地 URL 派生 → 页面存在 | `publish/tests/test_episode_page.py` |
| **契约（跨仓）** | 本规格与仓库现状一致；落地链接在真实站点可达 | 根 `tests/test_podcast_spec.py`（随 `site-guard.yml` 进 CI） |

### 12.2 规格自身的漂移守卫

`tests/test_podcast_spec.py` 负责让**本文档与仓库现状保持一致**：

| 检查 | 判据 |
| --- | --- |
| 本文档引用的每个仓库路径真实存在 | 逐条 `Path.exists()` |
| 本文档引用的每个 slug 在 `aiv/contracts/` 与 `aiv/publish/` 里都存在 | 集合相等，**不多不少** |
| EV-01 ~ EV-04 的存量达标线**确实被六期母稿满足** | 逐期统计，**取最小值**断言 ≥ 阈值 |
| EV-05 的语速常数与六期实测一致 | 重新算 241~256 字 / 32.436~35.424 s，断言均值 == 7.19（误差 < 0.01） |
| EV-06 的 p90 与 `docs/` 实际分布一致 | 重跑分布，断言 p90 == 22,609 |
| 契约编号不与既有规格冲突 | 本文档 = 契约七；`00` = 一~四、`06` = 五、`07` = 六 |
| 六期母稿的线上页面**不含**期号区块（改动前的现状） | 改动落地后**反转**这条断言 |

> **最后一条要特别小心**：它是「改动前红、改动后绿」的断言，
> 实施时必须**在同一个 commit 里改掉**，否则会留下一条永远红的测试。

### 12.3 阈值的独立取值

EV 表里的数字**不从被测代码 import**——它们是**独立手写的事实源**，
一致性由 §12.2 的守卫单独钉住。理由与既有教训相同：
守卫从生产代码 import 阈值 = 自证，永远是绿的。

## 十五、风险与兜底

| 风险 | 兜底 |
| --- | --- |
| **软 404 让守卫假绿** | commit 1 先修；G3 断言**状态码 + 响应体含 slug**，两条都要 |
| **平台简介里的链接已经发出去** | 已发出的 EP06 链接指向母稿——母稿加了期号区块后**那条链接自动变成正确的**，不需要重发。这一点是方案 A 的额外好处 |

## 十六、待拍板与待验证项

### 16.1 待拍板（3 条）

见 §一.4。**默认值的理由**：

| # | 默认 | 为什么这样默认 |
| --- | --- | --- |
| D1 | 方案 A（母稿页即期号页） | 满足不变量一「母稿唯一」；一个 URL 同时承载长文与视频，SEO 集中；落地 URL 可由既有 `content_id` 直接派生，**不需要新增生成步骤，断了的风险最小**；且已发出的 EP06 链接**无需重发**即自动变正确 |
| D2 | 托管旁白 mp3，不托管成片 mp4 | RSS 的 `<enclosure>` 必须是自有域名的稳定音频直链，平台不提供；旁白 mp3 已入库，六期约 3.1 MB，带宽可忽略；成片 mp4 仍不托管，沿用 §9.1 |
| D3 | 期号区块在正文之前 | 观众落地页的第一屏应该是「这是哪一期 + 视频 + 钩子」，而不是两万像素的技术长文；母稿正文紧随其后，深度不减 |
